---
title: SSR and Strict Mode
description: How to create a client safely under server rendering and React Strict Mode.
---

Create the client inside the provider `factory`, or in an effect. Never create it at module scope in code that also runs on the server. This rule keeps a client safe under server rendering and React Strict Mode. No package accesses the DOM at module load time.

## Use the provider factory

`LiveCursorProvider` runs its `factory` once per mount, in a mount effect:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, LiveCursorProvider } from "@anchor-presence/react";

function App() {
  return (
    <LiveCursorProvider
      factory={() => {
        const transport = createWebSocketTransport({ path: "/?room=main" });
        return createPresenceClient({ transport });
      }}
    >
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

Before the factory runs, the provider renders its children with a `null` client, and every hook returns its server-safe value. Server renders never run the factory. Create the transport inside the factory, because `client.dispose()` calls `transport.disconnect()`.

## Why Strict Mode matters here

In development, React Strict Mode renders every component twice, and mounts, unmounts, and mounts it again. This finds effects that break when they run two times. A `createPresenceClient` call directly inside a component body runs on each render, so two clients exist. A client at module scope runs once, but it also runs on the server, and every request then shares that one client.

The provider creates the client in an effect with a cleanup. The first mount creates the client, and Strict Mode's cleanup disposes it. The second mount's effect creates a new client, so the page always holds one live client.

## Two supported SSR patterns

- Pass a `factory` to the provider. The provider runs it only in the browser, so a server render creates no client.
- Create your own client in a `useEffect`. Pass `client={null}` until the effect creates the client.

Every hook that reads changing data has a server-safe snapshot: `useRemoteCursors` and `useRemotePresence` return `[]`, and `useCursorStatus` returns `"disconnected"`. `useLocalContext` returns `[undefined, setContext]`, and `useLocalUser` returns `[undefined, setUser]`. `useCursorClient` and `useCursorBinding` read the context, not a snapshot. With `client={null}` and no `binding` prop, both return `null`. `renderToString` works with `client={null}` for a tree that uses every hook:

```tsx
<LiveCursorProvider client={null}>
  <Dashboard />
</LiveCursorProvider>
```
