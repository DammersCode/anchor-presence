---
title: Anchor registration
description: How an element becomes an anchor, the data-anchor attribute, and duplicate IDs.
---

An anchor is a DOM element that the binding measures and places cursors on. The binding registers and unregisters anchors on its own. An application never calls a register function.

## The anchor attribute

An element becomes an anchor the moment it has a non-empty value for the configured attribute. The default attribute is `data-anchor`:

```html
<button data-anchor="nav.dashboard">Dashboard</button>
```

Set `anchorAttribute` in `DomBindingOptions` to use a different attribute name. The name must start with a letter and contain only letters and digits, with single hyphens between groups. For any other name, `createDomBinding` throws a `TypeError`.

## Auto-registration

The binding watches the document with a `MutationObserver`. The observer watches the `environment.root` that you pass, or the global `document` by default. The observer tracks:

- New elements added anywhere under the root, including nested elements with the anchor attribute.
- Removed elements, which unregister their anchor.
- Changes to the anchor attribute's value on an existing element.

You call no registration or cleanup function. A framework that mounts and unmounts elements, such as React, keeps the anchor map in sync through this observer alone.

## Empty values

A blank or whitespace-only attribute value does not register an anchor. In development mode, the binding warns one time for each element that has such a value.

## Duplicate IDs

If two elements register the same anchor ID, the newest registration wins. In development mode, the registry warns one time for each duplicate ID.

A new element can mount before the old element with the same ID unmounts. Examples are React Strict Mode and a virtualized list that swaps rows. The rule "the newest registration wins" gives the same result every time in that case.

## Shadow DOM

The anchor ancestor walk crosses open shadow boundaries. An anchor inside a shadow root still resolves as an ancestor of a pointer target in that shadow tree.
