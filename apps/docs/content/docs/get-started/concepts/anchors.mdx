title: Anchors

An anchor is a DOM element with a stable ID. A cursor position names an anchor and a normalized position inside it.

## Semantic anchors

A semantic anchor is a DOM element that the application marks with a stable string ID. Anchors mark locations that matter: a button, a table row, or a sidebar link.

The sender expresses cursor position relative to an anchor, not as an absolute screen coordinate. The receiver measures its own copy of that anchor and places the cursor there.

Mark an anchor with the configured anchor attribute. The default attribute is `data-anchor`:

```tsx
<button data-anchor="nav.dashboard">Dashboard</button>
```

A binding can use another attribute through `anchorAttribute`. See [`DomBindingOptions`](/docs/dom/api/binding).

## Anchor IDs

An anchor ID is an opaque string, 1 to 256 characters. Choose your own naming scheme, for example `nav.dashboard`, `stats.revenue`, or `orders.row:17.actions`.

Anchor IDs are map keys only. They never become CSS selectors, query strings, or code. A remote message can only address an element in the registered anchor map. See [Security](/docs/get-started/guides/security).

If two elements register the same ID, the newest one wins. See [Duplicate IDs](/docs/dom/anchor-registration#duplicate-ids) for the reason and the development-mode warning.

## Normalized u/v coordinates

Each anchor point carries `u` and `v`, both in the range 0 to 1.

- `u` is the horizontal position across the anchor's width: 0 at the left edge, 1 at the right edge.
- `v` is the vertical position across the anchor's height: 0 at the top edge, 1 at the bottom edge.

The sender computes `u` and `v` from its own anchor rectangle:

```text
u = (pointerX - rect.left) / rect.width
v = (pointerY - rect.top) / rect.height
```

The receiver reverses the formula against its own anchor rectangle to place the cursor. See [Resolution](/docs/dom/resolution) for the pixel formula.

Both sides use a proportion of the anchor's own size. A 75% mark stays a 75% mark, even if the anchor is a different width or height on each client. See [Responsive layouts](/docs/get-started/concepts/responsive-layouts) for a worked example.

The receiver clamps `u` and `v` to `[0, 1]` during validation. See [Security](/docs/get-started/guides/security).
