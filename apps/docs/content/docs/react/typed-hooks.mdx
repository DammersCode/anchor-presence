`createPresenceHooks<TContext, TUser, TEvents>()` returns the provider and every hook with your types fixed. A hook from the result takes no type parameter, so a call with a wrong type does not compile. Use it in every app that has a known shape for its context, user, or event values. `TEvents` is optional.

## Usage

Call `createPresenceHooks` one time, at module level, and export the result:

```ts
// presence.ts
import { createPresenceHooks } from "@anchor-presence/react";

export type User = { name: string; color: string };
export type Context = { pageId: string };
export type Events = { reaction: { emoji: string }; ping: undefined };

export const {
  LiveCursorProvider,
  useCursorClient,
  useLocalContext,
  useCursorEvents,
  useLocalUser,
  useRemoteCursors,
  useRemoteUsers,
  useSendEvent,
} = createPresenceHooks<Context, User, Events>();
```

Then import the provider and the hooks from your module, not from `@anchor-presence/react`:

```tsx
import { useRemoteUsers } from "./presence";

function PresenceList() {
  const users = useRemoteUsers();
  return (
    <ul>
      {users.map((entry) => (
        <li key={entry.clientId}>{entry.user?.name ?? "Guest"}</li>
      ))}
    </ul>
  );
}
```

`entry.user` has the type `User | undefined`. A field that `User` does not have, for example `entry.user?.age`, is a type error. A type argument, for example `useRemoteUsers<OtherUser>()`, is also a type error.

## Typed events

`TEvents` is an event map: an object type that maps each event type to the type of its `data`. The result has two hooks for these events:

- `useSendEvent()` returns a function that sends one event. A misspelled type or a `data` value of the wrong type does not compile. The function returns the result of `client.sendEvent`. Without a client, it sends nothing and returns `false`. It keeps its identity while the client stays the same.
- `useCursorEvents(listener)` calls `listener` with a typed event. A check of `event.type` narrows `event.data` to the type of that event.

This component sends a reaction and shows the last reaction from a peer (another client in the same room):

```tsx
import { useState } from "react";
import { useCursorEvents, useSendEvent } from "./presence";

function Reactions() {
  const sendEvent = useSendEvent();
  const [lastEmoji, setLastEmoji] = useState<string | null>(null);

  useCursorEvents((event) => {
    if (event.type === "reaction") setLastEmoji(event.data.emoji);
  });

  return (
    <div>
      <button type="button" onClick={() => sendEvent("reaction", { emoji: "tada" })}>
        React
      </button>
      {lastEmoji !== null && <p role="status">{lastEmoji}</p>}
    </div>
  );
}
```

## Check remote events

<Callout type="warn">
  If a peer sends data of another type, `useCursorEvents` still delivers it. The types check only the code
  that you write. Pass the client a `parseEvent` that checks the same event map.
</Callout>

`createEventParser` from `@anchor-presence/core` builds this `parseEvent` from one parser per event type. For an event without data, use `null` as the parser. Pass the result to `createPresenceClient` in the provider `factory`:

```tsx
import { createEventParser, createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { type Events, LiveCursorProvider } from "./presence";

const parseEvent = createEventParser<Events>({
  reaction: (data) => {
    const emoji = (data as { emoji?: unknown } | undefined)?.emoji;
    return typeof emoji === "string" ? { emoji } : undefined;
  },
  ping: null,
});

function App() {
  return (
    <LiveCursorProvider
      factory={() => createPresenceClient({ transport: createWebSocketTransport(), parseEvent })}
    >
      <Reactions />
    </LiveCursorProvider>
  );
}
```

Declare the event map with `type`, not with `interface`. `createEventParser` rejects an `interface` at compile time, while `createPresenceHooks` accepts both. For the parser rules, see [Typed events](/docs/core/presence-client#typed-events).

## What the result contains

| Name                                    | Types that the result fixes                                          |
| --------------------------------------- | -------------------------------------------------------------------- |
| `LiveCursorProvider`                    | context and user                                                     |
| `useCursorClient`, `useCursorBinding`   | context and user                                                     |
| `useRemoteCursors`, `useRemotePresence` | context and user                                                     |
| `useRemoteCursorsSelector`              | context and user. It still takes the `TSelected` type of its result. |
| `usePeerChanges`                        | context and user                                                     |
| `useRemoteUsers`, `useLocalUser`        | user                                                                 |
| `useLocalContext`                       | context                                                              |
| `useCursorEvents`, `useSendEvent`       | events                                                               |
| `useCursorStatus`                       | none                                                                 |

Without `TEvents`, an event can have any `type`, and its `data` has the type `unknown`. `CursorLayer` and `DefaultCursor` are not in the result. Import them from `@anchor-presence/react`, and pass your types as type arguments, for example `<CursorLayer<Context, User> />`.
