A cursor on an element lands on the same element on every screen. Between two elements, the result depends on the layout. A short move for one user can become a large jump for another user. Follow the rules on this page when you design a page that shows presence, especially for narrow and mobile screens. The audit skill measures five of these rules in your running app.

## A minimal example

Give the container of a group of anchors its own anchor:

```tsx
<nav data-anchor="nav">
  <a data-anchor="nav.home">Home</a>
  <a data-anchor="nav.orders">Orders</a>
</nav>
```

A pointer in the gap between the links then lands on `nav`, not on a viewport position.

## How a short move becomes a jump

A remote cursor moves from anchor to anchor, as the pointer of the sender does. In the [Basics example](/docs/examples/basics), the wide pane shows three buttons in a row, and the narrow pane stacks them at full width. The pointer moves 10 pixels in the wide pane, from the right edge of **Save draft** to the left edge of **Preview**. In the narrow pane, the remote cursor moves about 250 pixels.

Four layout differences cause jumps:

- Two neighbors in one layout are far apart in the other layout.
- The pointer crosses a gap with no anchored parent, so the cursor falls back to the viewport position.
- An anchor changes shape, so the same `u`/`v` lands on another spot inside it.
- An anchor exists in one layout only, so the cursor falls back to a parent.

## Anchor every container

Give each container of anchors its own anchor: the sidebar, the toolbar, the list, the table. A pointer between two child anchors then lands on the container, as in the [minimal example](#a-minimal-example). This markup has no anchored parent for the gap, which causes jumps:

```tsx
<nav>
  <a data-anchor="nav.home">Home</a>
  <a data-anchor="nav.orders">Orders</a>
</nav>
```

## Keep neighbors next to each other

Change the number of columns, not the order or the axis. A row that wraps keeps most neighbors on one line. A row that turns into a column moves every neighbor:

<Tabs items={["Correct", "Causes jumps"]}>
<Tab value="Correct">

```tsx
<div className="flex flex-wrap justify-end gap-2">{buttons}</div>
```

</Tab>
<Tab value="Causes jumps">

```tsx
<div className={wide ? "flex justify-end gap-2" : "flex flex-col gap-2"}>{buttons}</div>
```

</Tab>
</Tabs>

When a table becomes cards, keep adjacent cells adjacent inside the card, in the same order. See the [Table and cards example](/docs/examples/table-and-cards) and the [Responsive grid example](/docs/examples/responsive-grid).

## Keep item sizes and shapes alike

The receiver applies the `u`/`v` of the sender to its own box. If a button is 80 pixels wide on one screen and 250 pixels on the other, a point near its edge lands far from its label. When a layout stacks items, keep their own width. Give icon-only items a square box:

<Tabs items={["Correct", "Causes jumps"]}>
<Tab value="Correct">

```tsx
<div className="flex flex-col items-end gap-2">{buttons}</div>
```

</Tab>
<Tab value="Causes jumps">

```tsx
<div className="flex flex-col gap-2">{buttons}</div>
```

</Tab>
</Tabs>

A board of fixed-size columns that scrolls, and does not shrink, keeps every cursor steady. See the [Kanban example](/docs/examples/kanban).

## Keep the same anchor IDs in every state

A collapsed and an expanded sidebar are two layouts of one page. Give each item the same anchor ID in both states:

```tsx
function NavItem({ item, collapsed }: { item: { key: string }; collapsed: boolean }) {
  const id = `nav.${item.key}`;
  return collapsed ? <IconLink data-anchor={id} /> : <LabeledLink data-anchor={id} />;
}
```

## Keep the parent of a hidden anchor anchored

A layout can drop an anchor, for example a narrow table without its action column. The cursor then falls back to the nearest parent anchor that remains. Anchor each level: the button, its row, and the table. Then the fallback lands one step up, not on a viewport position. See the [Anchors and fallbacks example](/docs/examples/anchors-and-fallbacks).

## Anchor meaning, not wrappers

The fallback chain carries at most 4 anchors by default (the `maxSentAnchors` binding option). An anchor on a padding or grid wrapper uses one of these entries for a box with no meaning. Put anchors on elements that a user can name: a card, a row, a button, a panel.

## Check a layout with the audit skill

The `anchor-presence-audit` agent skill opens each route at several window widths and UI states. It gives each pair of layouts a risk score from 0 (low) to 100 (high). Each score has five parts, one for each of the first five rules above:

| Part   | What it measures                                         | Rule                                        |
| ------ | -------------------------------------------------------- | ------------------------------------------- |
| Jump   | Receiver distance for a short move between two neighbors | Keep neighbors next to each other           |
| Gap    | Container area with no anchored parent                   | Anchor every container                      |
| Depth  | How far an anchor falls back in the other layout         | Keep the parent of a hidden anchor anchored |
| Aspect | Shape change of one anchor between layouts               | Keep item sizes and shapes alike            |
| Parity | Share of anchor IDs that exist in one layout only        | Keep the same anchor IDs in every state     |

To install and run the skill, see the [layout audit skill](/docs/skills/layout-audit).
