# Docs findings: core and dom

F1 | bug | packages/dom/src/pointer.ts:142 | A focus cursor calls `setLocalCursor(position)` without pointer info, so peers keep the last mouse/pen/touch type for a keyboard cursor. | Pass `{}` as the pointer for focus cursors and for an unknown `pointerType`.
F2 | api | packages/core/src/client.ts:230 | `setLocalCursor(cursor, pointer?)` keeps the previous pointer when `pointer` is omitted; only `{}` clears the type. The binding passes `undefined` for an unknown `pointerType` (packages/dom/src/pointer.ts:113), so peers keep the old type. | Document `{}` as the clear value in the JSDoc, or treat an omitted `pointer` as "no pointer".
F3 | bug | packages/dom/src/auto-register.ts:108 | Auto-registration uses `root.querySelectorAll` and one observer on the root, so an element with `data-anchor` inside a shadow root never registers. The resolver and scheduler (shadow-root observers, hit test) support shadow anchors that cannot exist. | Walk open shadow roots in auto-registration and observe them, or state the light-DOM-only rule in JSDoc.
F4 | bug | packages/dom/src/broadcast-transport.ts:53 | `connect()` after `disconnect()` sets the status to `connected` on a closed `BroadcastChannel`; the next `send` throws `InvalidStateError` inside `postMessage`. | Make `connect()` after `disconnect()` a no-op with a dev warning, like the WebSocket transport. Fixed in the working tree during this pass.
F5 | bug | packages/dom/src/broadcast-transport.ts:40 | `event.data.from` throws a `TypeError` when another script posts `null` or a primitive on the same channel name. | Check that `event.data` is an object before reading `from`. Fixed in the working tree during this pass.
F6 | api | packages/dom/src/transport.ts:23 | `WebSocketTransport` declares only `connect` and `disconnect` as required, although `subscribeClose`, `subscribeStatus`, `getStatus` and `bufferedBytes` always exist. Callers must write `transport.subscribeClose?.(...)`. | Declare all always-present members as required in `WebSocketTransport` (and `subscribeStatus`/`getStatus` in `BroadcastChannelTransport`).
F7 | api | packages/dom/src/transport.ts:173 | Without a global `WebSocket` and without `WebSocketCtor`, `connect()` returns silently and the status stays `connecting` forever. | Throw a `TypeError` at creation, or report `disconnected` with a close and a dev warning.
F8 | api | packages/core/src/store.ts:126 | For a known `clientId` with a new session, the store reports `update` only when `user` differs; a changed `context` gives no `update`. A same-session message compares both. | Compare `context` as well for a new session. Fixed in the working tree during this pass.
F9 | error-message | packages/core/src/internal/ingest.ts:172 | Every inbound drop reason ends with "A codec mismatch between peers causes this", also for an oversized message and for a subscriber that threw. | Name the likely cause per reason, and only blame the codec for a decode failure.
F10 | api | packages/core/src/internal/ingest.ts:90 | When the event rate limiter tracks 512 senders, a new sender clears every bucket, so all known senders get a full burst again. | Evict the oldest bucket instead of clearing all of them.
F11 | api | packages/core/src/binary-codec.ts:101 | The event type has a u16 length field on the wire, but `encode` rejects a type over 255 bytes. | Allow up to 65535 bytes, or write a u8 length.
F12 | error-message | packages/core/src/binary-codec.ts:125 | An invalid viewport throws a `TypeError`; every other encode limit throws a plain `Error`. | Throw the same error type for every encode limit.
F13 | api | packages/dom/src/scheduler.ts:193 | `binding.invalidate(reason)` accepts a `reason` that nothing reads or logs. | Log the reason in a dev trace, or remove the parameter.
F14 | error-message | packages/dom/src/binding.ts:128 | The `anchorAttribute` error says "must be a valid DOM attribute name", but the rule is stricter (letters and digits in hyphen groups, so `data_anchor` and `data-a:b` fail). | State the actual rule in the message, for example "letters and digits in groups split by single hyphens".
F15 | api | packages/core/src/internal/publish-loop.ts:181 | The late-join delay reads `Math.random`, so a test with fake timers cannot fix the delay; `now` and `scheduler` are injectable but randomness is not. | Add a `random` option, like `createWebSocketTransport`.
F16 | api | packages/core/src/index.ts:63 | `warnOnce` and `reportListenerError` are public exports, but they exist for the sibling packages. Internal helpers are now public API, and a key that an app passes to `warnOnce` shares the set with the package keys. | Move it to an internal entry point, or document it as public.
F17 | api | packages/core/src/internal/dev-warnings.ts:27 | Development warnings mix two scopes: `warnOnce` keys are once per process (duplicate `clientId`, stale vs heartbeat), other warnings are once per client (store full, inbound drops). | Use one scope for all "one time" warnings.
F18 | api | packages/core/src/client.ts:115 | Without `subscribeStatus`, the client ignores `getStatus` and reports a constant `connected`, even when the transport reports another status. | Read `getStatus()` when it exists, also without `subscribeStatus`.
F19 | api | packages/core/src/in-memory-transport.ts:81 | `send` delivers while the sending side is `disconnected`, unlike the shipped browser transports. A test of offline behavior passes with the in-memory pair and fails in production. | Drop a send while the sending side is not `connected`.
