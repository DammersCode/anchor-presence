You want a relay with no framework and no extra dependency, on the WebSocket support of Bun. Each room is one topic of `Bun.serve`. Bun forwards each message to every other socket that subscribes to the topic, so the relay needs no room map of its own.

## Install

Install the packages with Bun:

```sh
bun add @anchor-presence/core @anchor-presence/dom
```

The relay itself needs no dependency beyond Bun.

## Client

The client needs no custom transport. It connects with the native `createWebSocketTransport`:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";

const transport = createWebSocketTransport({ port: 8788, path: "/?room=main" });
const client = createPresenceClient({ transport });
```

## Behavior notes

- **Room name validation.** The relay reads the room from the `room` query parameter. `parseRoom` caps room names at 256 characters and restricts them to `[A-Za-z0-9_-]`. A missing name is `main`. An invalid name closes the socket with code `4007`.
- **Upgrade path.** The relay accepts the upgrade only at `/`. It answers any other path with HTTP `404`.
- **Max payload size.** `MAX_MESSAGE_BYTES` (default 32 KiB) drops an oversized message instead of closing the connection.
- **Per-connection rate limit.** A token bucket (a counter that refills at a fixed rate) limits inbound messages per socket (`RATE_CAPACITY`, `RATE_REFILL_PER_SECOND`).
- **Origin allowlist.** `RELAY_ALLOWED_ORIGINS` is a comma-separated list of allowed origins. Leave it empty for local development. The relay then accepts every origin.
- **Connection check.** Pass an `authCheck` function to check each connection. Without it, set `RELAY_AUTH_TOKEN`. The relay then compares the [room token](/docs/dom/websocket-transport#room-token) of each connection with that value.
- **Identity binding.** If `authCheck` returns `{ clientId, user }`, the relay writes that identity into every JSON frame of the connection. See [Identity binding](/docs/examples/backends#identity-binding).
- **Room cleanup.** The relay drops a room's entry once its last socket closes.
- **Connection caps.** `RELAY_MAX_ROOM_SOCKETS` (default 128) limits one room. `RELAY_MAX_TOTAL_SOCKETS` (default 10,000) limits the process. Above either cap, the relay closes the new socket with code `4001` (room full) or `4002` (server full).
- **Dead connections.** `RELAY_IDLE_TIMEOUT_SECONDS` (default 60) sets Bun's `idleTimeout`, and `sendPings` is on. If a socket sends nothing for that time, Bun sends a ping. If no pong comes back, Bun closes the socket.
- **Slow receivers.** `RELAY_SLOW_PEER_HARD_BYTES` (default 8 MiB) sets Bun's `backpressureLimit`, and `closeOnBackpressureLimit` is on. Bun closes a receiver whose send buffer passes that size. Bun does not expose the buffer of each receiver. For this reason, the relay cannot skip sends to a slow receiver, as the `ws` relay does.

<Callout type="warn">
  If you expose this relay outside local development, set `RELAY_ALLOWED_ORIGINS` and `RELAY_AUTH_TOKEN`. Also
  put a proxy that serves TLS (`wss://`) in front of the relay. Without them, any page and any visitor can
  join a room.
</Callout>
