This page covers two ways to give a coding agent working knowledge of Anchor Presence: the shipped skill, and the machine-readable `llms.txt` index.

## Install the shipped skill

The repository ships an installable skill at `skills/anchor-presence`. It teaches an agent the anchor model, the integration steps, and the hard rules (render untrusted data as text, create clients in browser-only code, treat anchor IDs as opaque keys) without needing to read the source.

Install it with [skills.sh](https://skills.sh):

```sh
npx skills add DammersCode/anchor-presence
```

Point your agent at the installed skill file and ask it to wire up live cursors. The skill covers:

- the five-method transport interface and how little a relay needs to be
- how to mark anchors with `data-anchor` and why parent anchors matter for fallback
- the visibility policy shape, including the `pointVisible` occlusion signal
- the three hard rules: render `user`/`context` as text, create the client in browser-only code, and treat anchor IDs as opaque

## Audit layouts with the audit skill

The repository ships a second skill at `skills/anchor-presence-audit`. It checks a running app for cursor jumps between layouts, against the rules in [Designing layouts for presence](/docs/get-started/guides/layout-design).

Install only this skill:

```sh
npx skills add DammersCode/anchor-presence --skill anchor-presence-audit
```

The skill measures the app in a real browser through Playwright. If the app has no `playwright` package, the skill gives you the install command for your package manager.

To run it, start the app and ask your agent to audit the layouts for cursor jumps. The agent then does these steps with you:

1. It scans the code for anchors, routes, breakpoints, and toggles such as a collapsible sidebar, tabs, or dialogs.
2. It proposes a list of views (routes, viewport widths, and UI states). You confirm or change the list.
3. It measures every view and scores each pair of views from 0 to 100.
4. It asks for the report format: a table in chat, a Markdown file, Mermaid charts, or a combination.
5. It proposes fixes, each with a file and a change. You pick the fixes to apply.
6. It applies the fixes, measures again, and shows the scores before and after.

To use the score as a CI gate, run the measure script with `--fail-above <score>`. The script then exits with code 1 when a pair of views scores above that value.

## Point an agent at llms.txt

Every page on this site is also available as plain Markdown, for an agent that reads URLs directly instead of using the skill.

- [`/llms.txt`](/llms.txt): an index of every doc page, with a link to its Markdown version.
- [`/llms-full.txt`](/llms-full.txt): every page concatenated into one document, for an agent with a large context window and no crawler.
- `/docs/<page>.md`: any single page's Markdown, for example [`/docs/get-started/quick-start.md`](/docs/get-started/quick-start.md).

Every doc page also has a **Copy Markdown** button at the top, plus **Open in ChatGPT** and **Open in Claude** actions. A person reading a page in a browser can hand it to a chat model in one click.

## Which one to use

Use the skill when the agent already runs inside this repository, or a project that depends on it: it is denser and includes integration steps the reference docs spread across several pages. Use `llms.txt` when the agent works from a URL with no repository access, or when it needs the full API reference alongside the integration steps.
