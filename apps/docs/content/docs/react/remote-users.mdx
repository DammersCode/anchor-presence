---
title: Remote users
description: Read the remote user values with useRemoteUsers, and react to joins and leaves with usePeerChanges.
---

`useRemoteUsers` returns one entry per peer. A peer is another client in the same room. The entry has the `user` value of the peer, its session, and whether it is idle. Use it for a presence list or an avatar stack. These lists need one row per person, not one row per cursor frame.

## Usage

The hook has this signature:

```ts
function useRemoteUsers<TUser = unknown>(): RemoteUser<TUser>[];
```

This component lists the peers and dims the idle ones:

```tsx
import { useRemoteUsers } from "@anchor-presence/react";

type MyUser = { name: string; color: string };

function PresenceList() {
  const users = useRemoteUsers<MyUser>();
  return (
    <ul>
      {users.map((entry) => (
        <li key={entry.clientId} style={{ opacity: entry.idle ? 0.5 : 1 }}>
          {entry.user?.name ?? "Guest"}
        </li>
      ))}
    </ul>
  );
}
```

Each `RemoteUser` entry has:

| Field      | Type                 | Meaning                                                                                             |
| ---------- | -------------------- | --------------------------------------------------------------------------------------------------- |
| `clientId` | `string`             | the peer that sent the user value                                                                   |
| `user`     | `TUser \| undefined` | the user value, or `undefined` when the peer sent none                                              |
| `session`  | `string`             | the session ID of the peer                                                                          |
| `idle`     | `boolean`            | `true` when the presence of the peer did not change for `idleAfterMs`, even while heartbeats arrive |

## User shape

The client checks each remote `user` against the shape of the local `user` value. A `null` inside a remote `user` fits every key, so render each field with a `null` fallback. If a remote value does not fit the shape, the client drops it, and the entry keeps the previous `user` value. In development mode, the client then warns one time and names `parseUser`. For the rules and for `parseUser`, see [Remote user and context](/docs/core/validation#remote-user-and-context).

## Peer changes

`usePeerChanges(listener)` calls `listener` when a peer joins, leaves, or changes its `user` or `context`. Use it for a one-time effect, such as a notice. For a list, use `useRemoteUsers`.

The hook has this signature:

```ts
function usePeerChanges<TContext = unknown, TUser = unknown>(
  listener: (change: PeerChange<TContext, TUser>) => void,
): void;
```

This component shows the last peer that joined:

```tsx
import { useState } from "react";
import { usePeerChanges } from "@anchor-presence/react";

function JoinNotice() {
  const [notice, setNotice] = useState<string | null>(null);
  usePeerChanges((change) => {
    if (change.type === "join") setNotice(`${change.clientId} joined`);
  });
  return notice !== null ? <p role="status">{notice}</p> : null;
}
```

The listener receives a `PeerChange` with a `type` of `join`, `update`, or `leave`, the `clientId` of the peer, and its `user` and `context` when set. On `leave`, they hold the last known values. Cursor moves never call it. For the rules of each `type`, see [Peer changes](/docs/core/remote-presence#peer-changes).

The hook keeps one subscription per client, so an inline listener does not subscribe again on each render. The hook always calls the listener from the last render. Without a client, the hook calls nothing. The hook never rerenders its component.

## Render cost

The hook rerenders only when the set of peers changes, or when one entry's `user`, `session`, or `idle` field changes. A remote cursor that moves across the screen does not rerender this hook, because position is not part of `RemoteUser`.

The returned list, and each unchanged entry inside it, keep the same object identity across renders. A `React.memo` row component keyed by `clientId` skips rendering for every user whose fields did not change.
