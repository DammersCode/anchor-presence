`createDomBinding(client, options?)` creates the DOM side of one presence client. It returns a `DomBinding`: an object with a snapshot of resolved cursors, a `subscribe` method, and a `dispose` method. A resolved cursor is the position of one remote cursor in the pixels of your viewport.

## Create a binding

Call `createDomBinding` with a `PresenceClient`:

```ts
import { createPresenceClient } from "@anchor-presence/core";
import { createDomBinding } from "@anchor-presence/dom";

const client = createPresenceClient({ transport: myTransport });
const binding = createDomBinding(client);

binding.subscribe(() => {
  for (const cursor of binding.getSnapshot()) {
    if (cursor.visible) renderCursor(cursor.clientId, cursor.x, cursor.y);
  }
});
```

The client is live when its status is `connecting` or `connected`. A peer is another client in the same room. The binding runs its geometry scheduler only while the client is live and at least one peer has a cursor. In all other cases the scheduler stops, so an empty room costs no frame work.

## Options

`maxAnchors` caps the fallback chain that the pointer source sends. The default is `4`. The binding clamps an integer outside `1` to `8` into this range. `anchorAttribute` sets the attribute that marks an anchor element. The default is `data-anchor`. See [Anchor registration](/docs/dom/anchor-registration).

`createDomBinding` throws a `TypeError` in these cases:

- `anchorAttribute` is not letters and digits in groups split by single hyphens, with a letter first. For example, `data-anchor` and `anchor` pass, and `data_anchor` and `1-anchor` fail.
- `maxAnchors` is not an integer, for example `2.5` or `NaN`.

`capturePointer` turns the local pointer source on or off. The default is `true`. Set it to `false` for a client that shows remote cursors and sends no local cursor. One example is a mobile viewer. `context` and `user` still go to peers.

`captureFocus` publishes a cursor at the center of the focused element, for keyboard users. The default is `false`. When `capturePointer` is `false`, the binding ignores `captureFocus`. See [Pointer capture](/docs/dom/pointer-capture#keyboard-focus).

`resolution` sets how remote cursors turn into screen positions. See [Resolution](/docs/dom/resolution) and [Motion](/docs/dom/motion).

`environment` replaces the DOM and timing hosts that the binding uses: `root`, `window`, `raf`, `caf`, `ResizeObserverCtor`, and `MutationObserverCtor`. Each field defaults to the matching browser global. A test can replace one host with a fake and keep the others.

See [Binding API](/docs/dom/api/binding) for the full option and return types.

## Draw cursors without React

`@anchor-presence/react` draws the cursors for you. Without React, subscribe to the binding and update one element for each cursor. Set `CURSOR_MARKER_ATTRIBUTE` on the root element of each cursor. The binding then ignores the DOM changes inside your cursors and does not measure the layout again for them.

This function draws each visible cursor as a `div` inside `layer`, and returns the unsubscribe function:

```ts
import { CURSOR_MARKER_ATTRIBUTE, type DomBinding } from "@anchor-presence/dom";

function drawCursors(binding: DomBinding, layer: HTMLElement): () => void {
  const elements = new Map<string, HTMLElement>();
  return binding.subscribe(() => {
    const shown = new Set<string>();
    for (const cursor of binding.getSnapshot()) {
      if (!cursor.visible) continue;
      shown.add(cursor.clientId);
      let element = elements.get(cursor.clientId);
      if (element === undefined) {
        element = document.createElement("div");
        element.setAttribute(CURSOR_MARKER_ATTRIBUTE, "");
        element.className = "remote-cursor";
        layer.append(element);
        elements.set(cursor.clientId, element);
      }
      element.style.transform = `translate(${cursor.x}px, ${cursor.y}px)`;
    }
    for (const [clientId, element] of elements) {
      if (shown.has(clientId)) continue;
      element.remove();
      elements.delete(clientId);
    }
  });
}
```

`x` and `y` are viewport pixels. Give `.remote-cursor` the CSS `position: fixed`, `left: 0`, `top: 0`, and `pointer-events: none`. `@anchor-presence/react` uses the same styles on each cursor root. The final empty snapshot of `dispose` removes every element.

## invalidate

`binding.invalidate(reason?)` marks the layout dirty. On the next frame, the binding measures every active anchor again and resolves the cursors again.

The binding reacts to these layout signals:

- A resize or a scroll.
- A `ResizeObserver` entry.
- A DOM change under the anchor attribute.
- A CSS transition or animation on an active anchor.

Call `invalidate` after a layout change that none of these signals can see. One example is a scroll from code on an element with `overflow: hidden` and no `scroll` event. Another example is a font that loads after the first paint and changes the text size:

```ts
document.fonts.ready.then(() => {
  binding.invalidate("fonts-loaded");
});
```

`reason` is for your own logging. The binding does not read it.

If state that your `visibilityPolicy` reads changes, also call `invalidate`. See [Run the policy again after a state change](/docs/dom/visibility-policy#run-the-policy-again-after-a-state-change).

## Connection status

While the client status is `reconnecting` or `disconnected`, the binding hides every remote cursor. The snapshot is empty during that time. The remote presences stay in the client store. When the status returns to `connected`, the binding resolves the cursors again and shows them. The `connecting` status does not hide cursors.

## Page hide

On the `pagehide` event of the window, the binding calls `client.leave()`. Peers then remove this client at once, so a closed tab does not leave a cursor behind. If the page stays open, the next publish or heartbeat announces the client again.

## Errors in a policy or interpolator

If a `visibilityPolicy` or an interpolator throws, the binding keeps the last snapshot and does not stop. In development mode, it logs the error with `console.error`. The binding tries again on the next remote, anchor, or layout change.

## Dispose

`binding.dispose()` does these steps in order:

1. It clears the local cursor on the client, unless you pass `keepLocalCursor: true`.
2. It stops the scheduler and removes every listener.
3. It sends one final empty snapshot, so subscribers can remove every cursor.
4. It clears the subscriber list.

When the surface that owns the binding unmounts, call `dispose` one time.

Because `dispose` clears the local cursor, a client that stays connected after the binding stops leaves no cursor on its peers.

If you replace the binding and keep the client, pass `keepLocalCursor: true`. Peers then keep the local cursor while the new binding starts:

```ts
binding.dispose({ keepLocalCursor: true });
const nextBinding = createDomBinding(client, { resolution: { hitTest: true } });
```
