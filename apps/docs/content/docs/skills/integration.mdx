The integration skill teaches a coding agent to add Anchor Presence to your app. It also teaches the agent to fix live cursors that misbehave. To use it, install the skill. Then ask your agent to add live cursors or to fix a cursor problem. The skill gives the agent all the remaining steps.

## What it does

The agent reads your code and picks a transport and a relay that fit your stack. The transport is the connection between the browser and the relay. The relay is the server that forwards presence messages to the other clients.

The agent installs the three packages. Then it adds a provider, a cursor layer, and anchors. An anchor is an element that users point at, marked with `data-anchor`. At the end, the agent runs two clients side by side. It checks that a cursor lands on the same element at two viewport widths.

If the integration is broken, the agent goes directly to the matching fix in its troubleshooting list.

## When to use it

| Situation                                                           |                            Use it                            |
| ------------------------------------------------------------------- | :----------------------------------------------------------: |
| You add live cursors, multiplayer presence, or a who-is-online list |                             Yes                              |
| You choose anchor IDs for a component                               |                             Yes                              |
| A remote cursor drifts, vanishes, or lands on the wrong element     |                             Yes                              |
| You design a new relay protocol from scratch                        |   No. See [Custom transport](/docs/core/custom-transport).   |
| You audit a layout for cursor-jump risk before you ship it          | No. Use the [layout audit skill](/docs/skills/layout-audit). |

## Prerequisites

| Requirement         | Detail                                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------- |
| React               | Version 18 or later.                                                                                           |
| Rendering           | The provider goes in a client component. The skill does not change server components.                          |
| A real-time channel | An existing channel (Socket.IO, SignalR, a WebSocket server), or none. In both cases, the skill picks a relay. |
| Package manager     | The skill uses the package manager that the project already uses.                                              |

## What it asks you

| Question                                                           | Options                                                                  | Default                                                    |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------- |
| Which views get live cursors?                                      | Any set of routes or components                                          | None. The agent asks, because the code cannot answer this. |
| If the project has no real-time channel, where does the relay run? | Bun, Node (Express, Fastify, `http`), Hono, Elysia, or a managed service | None. The agent asks, because the code cannot answer this. |

Everything else comes from your code. If you ask for a who-is-online list, the skill adds one. Otherwise, it adds none.

## How it works

1. **Survey.** The agent reads the project to find its package manager, React version, framework, and existing real-time channel. It also finds where the display name of the user comes from.
2. **Pick a transport.** It matches your setup to a transport and relay, for example a Socket.IO server or a plain WebSocket relay on Bun.
3. **Install.** It runs the install command for your package manager. If the relay needs dependencies, it installs them too.
4. **Add the client.** It adds `LiveCursorProvider` with a `factory` prop, and `CursorLayer`, to a client component.
5. **Mark anchors.** It adds `data-anchor` to navigation items, cards, table rows, dialog controls, and every other element that a user points at. It also gives each anchor a parent anchor.
6. **Scope with context, if necessary.** If the app has several pages, tabs, or dialogs, the agent publishes the current state as context. Context is a value that describes the app state of a user, for example the open page. Then the agent hides the cursors of users in a different state.
7. **Check.** It runs the typecheck and the build of the project. Then it runs two clients at different viewport widths. It checks that a cursor lands on the same element in both.

## Common questions

**Does it touch my server code?** Yes. If your project has no real-time channel, the agent adds a small relay in the location that you choose. If the project has a channel, the agent adds one presence event or route to it.

**Will it read or send my data?** The skill reads your code and fetches these docs as Markdown. The library sends no screen coordinates. Each message holds an anchor ID and a normalized offset, and your own channel carries it.

**What if my project has no React yet?** The skill assumes React 18 or later. For a DOM app without React, use `@anchor-presence/dom` directly. See [DOM](/docs/dom).

**Can it fix a cursor that jumps instead of gliding?** Yes, but first read about [reduced motion](/docs/dom/motion). If a user has that system setting, a jumping cursor is the intended behavior.

## It works if

- The provider wraps every target view, and the project typechecks.
- Every navigation item, card, table row, row action, dialog, and primary control in the target views has an anchor. Every anchor has a marked parent.
- A cursor on an anchored element in a wide client appears on the same element in a narrow client, at a different pixel position.
- After the transport connects, `useCursorStatus()` reports `connected`, not `connecting`.
