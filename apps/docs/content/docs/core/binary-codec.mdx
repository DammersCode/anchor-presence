`binaryCodec` is a compact codec with a fixed binary layout. It sends about half the bytes of `jsonCodec` for a typical message. If bandwidth matters more than readable traffic, use it. See [Choose a codec](/docs/core/codecs#choose-a-codec).

## Usage

Pass `binaryCodec` as the `codec` option:

```ts
import { binaryCodec, createPresenceClient } from "@anchor-presence/core";

const client = createPresenceClient({ transport: myTransport, codec: binaryCodec });
```

## Wire layout

The layout is little-endian. The fields come in this order:

| Field       | Present for | Encoding                                                                                                  |
| ----------- | ----------- | --------------------------------------------------------------------------------------------------------- |
| Header      | every frame | Magic `0x41`, format `2`, protocol version `1`, one byte each.                                            |
| `clientId`  | every frame | A `u16` byte length, then the UTF-8 bytes.                                                                |
| `session`   | every frame | A `u16` byte length, then the UTF-8 bytes.                                                                |
| `sequence`  | every frame | A `u32`.                                                                                                  |
| Cursor tag  | every frame | `0` for a `null` cursor, `1` for a cursor, `2` for a leave message, `3` for an event.                     |
| Event type  | tag `3`     | A `u16` byte length, then the UTF-8 event type.                                                           |
| Anchors     | tag `1`     | A `u8` anchor count. Then for each anchor: a `u16` id length, the UTF-8 id, an `f32` `u`, an `f32` `v`.   |
| Viewport    | tag `1`     | A tag, `0` absent or `1` present. A present viewport adds an `f32` `u` and an `f32` `v`.                  |
| Pointer tag | every frame | `0` absent, `1` present without a type, `2` `mouse`, `3` `pen`, `4` `touch`.                              |
| `context`   | every frame | A tag: `0` absent, `1` explicit `null`, or `2` JSON. Tag `2` adds a `u32` byte length and the UTF-8 JSON. |
| `user`      | every frame | The same encoding as `context`.                                                                           |

An event frame writes the pointer tag and the `context` tag as `0`. It writes the event `data` in the `user` slot.

The `context` and `user` values stay JSON inside the binary frame. Only the cursor fields use the fixed layout. As a result, the size gain grows with the number of anchors.

## Coordinate precision

`binaryCodec` stores the anchor and viewport `u` and `v` values as 32-bit floats. A decoded coordinate keeps about 7 significant digits, so it can differ from the sent value. For a coordinate from `0` to `1`, the difference is less than `1e-7`. This difference is much less than one pixel.

## Encode limits

`binaryCodec.encode` throws when a message breaks a frame limit. It throws an `Error` in these cases:

- `version` is not `1`.
- `clientId`, `session`, or an anchor `id` is longer than 65535 UTF-8 bytes.
- The event `type` is longer than 255 UTF-8 bytes.
- `cursor.anchors` is not an array.
- The cursor has more than 255 anchors.
- `sequence` is not a safe integer from 0 to `DEFAULT_MAX_SEQUENCE`.
- An anchor coordinate is not a finite number.
- `pointer.type` is not `mouse`, `pen`, or `touch`.
- `JSON.stringify` cannot serialize `context` or `user`.

A viewport coordinate that is not a finite number throws a `TypeError`.

The protocol limits on the [Validation](/docs/core/validation#validationlimits) page are tighter than these frame limits. For example, the protocol allows 8 anchors and the frame allows 255. A message inside the protocol limits never reaches a frame limit. If an encode error comes from `user` or `context`, the client sends the message again without them. In all other cases, the client loses the message and continues.

`binaryCodec.decode` never throws. It returns `null` for malformed, truncated, or non-binary input.
