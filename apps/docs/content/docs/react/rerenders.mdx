title: Rerenders
description: Which hook rerenders when, so you can pick the smallest one for each component.
---

Each hook in `@anchor-presence/react` rerenders its component only when the value that it returns changes. Pick the hook that returns the smallest value that your component needs. Then an unrelated update does not rerender it.

## Rerender rules

A peer is another client in the same room. Each hook rerenders by these rules:

| Hook                                                       | Rerenders when                                                                                           |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| [useRemoteCursors](/docs/react/remote-cursors)             | on every resolved-cursor snapshot, which is every frame while cursors move                               |
| [useRemoteCursorsSelector](/docs/react/remote-cursors)     | only when its `select` output changes under `isEqual`                                                    |
| [useRemoteUsers](/docs/react/remote-users)                 | only when the set of peers, or the `user`, `session`, or `idle` field of one peer, changes               |
| [useRemotePresence](/docs/react/remote-presence)           | only when the `cursor`, `context`, `user`, `pointer`, `session`, `idle`, or membership of a peer changes |
| [useCursorStatus](/docs/react/connection-status)           | only when the connection status changes                                                                  |
| [useLocalContext](/docs/react/local-context)               | only when the local context value changes                                                                |
| [useLocalUser](/docs/react/local-context#local-user)       | only when the local user value changes                                                                   |
| [usePeerChanges](/docs/react/remote-users#peer-changes)    | never: it calls its listener and returns nothing                                                         |
| [useCursorEvents](/docs/react/cursor-events)               | never: it calls its listener and returns nothing                                                         |
| [useCursorClient](/docs/react/api/hooks#usecursorclient)   | when the provider's client or binding instance changes                                                   |
| [useCursorBinding](/docs/react/api/hooks#usecursorbinding) | when the provider's client or binding instance changes                                                   |

An idle room, with no inbound messages, costs nothing: none of these hooks rerender.

## Choose the smallest hook

A component that renders one cursor's position needs `useRemoteCursors`, or better, a `useRemoteCursorsSelector` that selects one client. A component that renders a name list needs `useRemoteUsers`, not `useRemoteCursors`, because a presence list does not care where the cursor sits on screen.

`CursorLayer` already applies this rule. It uses `useRemoteCursorsSelector` internally to skip cursors that `filterCursor` removes. `React.memo` then skips a cursor's row when its resolved values did not change.
