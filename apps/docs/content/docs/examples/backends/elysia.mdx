You want a relay built on [Elysia](https://elysiajs.com)'s route-based API instead of raw `Bun.serve`. This example uses Elysia's `.ws()` route on Bun, backed by Elysia/Bun's own topic pub-sub, the same model `examples/bun-native` uses. The relay types its query with a schema, and the client connects through an Eden treaty. Eden gives the connection end-to-end type safety: a wrong query parameter is a compile error on the client.

## Production notes

- **Query validation.** The relay validates the `room` and `token` query parameters against its schema before the upgrade. A parameter with the wrong type fails the upgrade with a 422 validation error.
- **Room name validation.** `parseRoom` caps room names at 256 characters and restricts them to `[A-Za-z0-9_-]`. A missing name is `main`. An invalid name closes the socket with code `4007`.
- **Max payload size.** `MAX_MESSAGE_BYTES` (default 32 KiB) drops an oversized message instead of closing the connection.
- **Per-connection rate limit.** A token bucket limits inbound messages per socket (`RATE_CAPACITY`, `RATE_REFILL_PER_SECOND`).
- **Origin allowlist.** `RELAY_ALLOWED_ORIGINS` is a comma-separated list of allowed origins. Leave it empty for local development. Every origin is accepted then.
- **Auth hook placeholder.** Pass an `authCheck` function, or set `RELAY_AUTH_TOKEN` for a plain shared-token check.
- **Room cleanup.** The relay drops a room's entry once its last socket closes.
- **Connection caps.** `RELAY_MAX_ROOM_SOCKETS` (default 128) limits one room. `RELAY_MAX_TOTAL_SOCKETS` (default 10,000) limits the process. Above either cap, the relay closes the new socket with code `4001` (room full) or `4002` (server full).
- **Dead connections.** `RELAY_IDLE_TIMEOUT_SECONDS` (default 60) sets Bun's `idleTimeout`, and `sendPings` is on. If a socket sends nothing for that time, Bun sends a ping. If no pong comes back, Bun closes the socket.

- **Slow receivers.** `RELAY_SLOW_PEER_HARD_BYTES` (default 8 MiB) sets Bun's `backpressureLimit`, and `closeOnBackpressureLimit` is on. Bun closes a receiver whose send buffer passes that size. Bun's pub-sub does not expose each receiver's buffer, so this relay cannot skip a slow receiver before it closes it, as the `ws` relay does.

Set `RELAY_ALLOWED_ORIGINS` and `RELAY_AUTH_TOKEN` before you expose this relay past local development. Put a TLS-terminating proxy in front of it.
