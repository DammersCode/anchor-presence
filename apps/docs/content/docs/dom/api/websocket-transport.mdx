This page lists `createWebSocketTransport` and its types. Use it to look up an option. The [WebSocket transport](/docs/dom/websocket-transport) guide explains the behavior.

```ts
import { createWebSocketTransport } from "@anchor-presence/dom";
import type { WebSocketTransport, WebSocketTransportOptions } from "@anchor-presence/dom";
```

## createWebSocketTransport

`createWebSocketTransport(options?)` returns a `WebSocketTransport`. If `options.url` is missing, it throws a `TypeError` in two cases: `window` does not exist, or `options.path` does not start with `/` or `?`. See [The default URL](/docs/dom/websocket-transport#the-default-url).

`WebSocketTransport` is a `LiveCursorTransport` from `@anchor-presence/core` whose `connect` and `disconnect` methods are required. The type keeps `subscribeStatus`, `getStatus`, `subscribeClose`, and `bufferedBytes` optional, although the returned object always has them.

A `subscribeClose` listener receives a [`TransportClose`](/docs/core/api/transports-and-codecs#transportclose) from `@anchor-presence/core`.

## WebSocketCtor

`WebSocketCtor` is the type of the `WebSocketCtor` option: `new (url: string) => WebSocketLike`. The option replaces the WebSocket constructor of the transport. Its default is `globalThis.WebSocket`. A test can pass a fake `WebSocketLike` and use no network.

The browser `WebSocket` constructor fits `WebSocketCtor` without a cast:

```ts
const transport = createWebSocketTransport({
  url: "wss://relay.example.com/?room=main",
  WebSocketCtor: WebSocket,
});
```
