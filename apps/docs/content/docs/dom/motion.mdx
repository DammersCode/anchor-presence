Motion is the ease of a remote cursor from its last position to its new one. Without it, a cursor jumps on each message. The binding uses one interpolator for each peer, from a factory that you choose when you create the binding. A peer is another client in the same room.

## Choose a custom interpolator

Pass `resolution.interpolatorFactory` to use another easing style, for example a spring:

```ts
import { createDomBinding } from "@anchor-presence/dom";

const binding = createDomBinding(client, {
  resolution: { interpolatorFactory: mySpringInterpolatorFactory },
});
```

Write the factory against the `Interpolator` interface. See [Interpolation](/docs/core/interpolation#the-interpolator-interface) for the interface and the `settled` flag.

## Default interpolator

If you omit `resolution.interpolatorFactory`, `createDomBinding` picks a factory from `@anchor-presence/core`:

| Condition at creation                                              | Factory              | Motion                    |
| ------------------------------------------------------------------ | -------------------- | ------------------------- |
| `matchMedia("(prefers-reduced-motion: reduce)").matches` is `true` | `noneInterpolator`   | The cursor jumps.         |
| In all other cases                                                 | `linearInterpolator` | A linear ease over 80 ms. |

The check reads `environment.window`, or the global `window`. It runs one time, at creation. A preference change after that does not change the interpolator of an existing binding.

## Where easing runs

`@anchor-presence/core` defines the interpolators but never calls them, because it has no frame clock. The binding samples the interpolator on each scheduled frame and writes the result into `ResolvedCursor.x` and `ResolvedCursor.y`. Code that uses only `@anchor-presence/core` reads raw positions, with no easing.

## When motion restarts instead of easing

The resolver moves a cursor without an ease in three cases:

- The `clientId` of the cursor appears for the first time. The cursor starts at its first position.
- The cursor had the `hidden` tier and resolves again. While the tier is `hidden`, the resolver calls the optional `reset` method of the interpolator, so the cursor jumps to its next position.
- A local scroll or resize moves the anchor while no message arrives. The resolver calls `shift`, which moves the cursor and its target by the same distance.

In all other cases, a new remote position eases the cursor from where it is.
