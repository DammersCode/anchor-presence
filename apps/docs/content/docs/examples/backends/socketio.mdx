`examples/socketio` adds a Socket.IO transport to the demo. Only the backend changes: the client builds its presence client over `createSocketIoTransport` instead of a plain WebSocket, and every `@anchor-presence/react` hook behaves the same way.

## Client transport

<CodeFromSource repo="examples/socketio/transport.ts" lang="ts" />

Use it like any other transport:

```ts
import { createPresenceClient } from "@anchor-presence/core";
import { io } from "socket.io-client";
import { createSocketIoTransport } from "./transport";

const socket = io("https://your-server.example", { query: { room: "main" } });
const client = createPresenceClient({ transport: createSocketIoTransport(socket) });
```

## Behavior notes

- `subscribeStatus` replays the current status to every new subscriber, so a component that mounts after the socket already connected still learns it can send.
- The relay is deliberately dumb: it never parses `"presence"` payloads, so `validatePresence()` on the receiving client is still the only thing standing between the wire and the store. See [Security](/docs/get-started/guides/security).
- An integration test in `examples/socketio/socketio.test.ts` starts a real Socket.IO server on an ephemeral port and connects two clients. It checks that a cursor update sent from one reaches the other through `getRemoteSnapshot()`.
- Run the relay with `cd examples/socketio && bun run dev:relay`, and the demo with `cd apps/demo && bun run dev`, then open it with `?backend=socketio`. Add `?room=<name>` to route into a separate room lane.
