`@dammers/anchor-presence-core` is the protocol layer. It sends the local presence, and it checks and stores the presence of each peer. Use the package directly in a test, on a server, or in an adapter for a UI framework other than React.

`@dammers/anchor-presence-core` has no runtime dependencies and needs no DOM. It runs in Node.js, Bun, workers, and browsers. It reads `document` at one place only, after a check that `document` exists. There, the client listens for `visibilitychange`. When the page becomes visible, the client sends a pending publish at once.

This sample connects two clients in one process:

```ts
import { createInMemoryPair, createPresenceClient } from "@dammers/anchor-presence-core";

const { a, b } = createInMemoryPair();
const clientA = createPresenceClient({ transport: a, user: { name: "Alice" } });
const clientB = createPresenceClient({ transport: b, user: { name: "Bob" } });
```

## Where core sits

`@dammers/anchor-presence-core` imports no DOM library, no framework, and no transport or codec library. `@dammers/anchor-presence-dom` adds the browser side, and `@dammers/anchor-presence-react` adds the React components:

<Mermaid
  chart={`flowchart TD
  accTitle: Package layers and imports
  react["@dammers/anchor-presence-react"] --> dom["@dammers/anchor-presence-dom"]
  dom --> core["@dammers/anchor-presence-core"]
  react --> core`}
/>

This split has two results:

- A test or a server process can create a `PresenceClient` and run the protocol with no browser and no framework.
- A framework adapter holds no protocol state of its own. It only subscribes to the client.
