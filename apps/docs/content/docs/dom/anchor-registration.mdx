An anchor is a DOM element that the binding measures and places cursors on. The binding registers and unregisters anchors on its own: you mark an element with an attribute, and the binding finds it. Read this page to choose anchor IDs and to know which elements the binding can find.

## The anchor attribute

An element becomes an anchor when it has a non-empty value for the anchor attribute. The value is the anchor ID. The default attribute is `data-anchor`:

```html
<button data-anchor="nav.dashboard">Dashboard</button>
```

The binding trims spaces at the start and the end of the value. Set `anchorAttribute` in `DomBindingOptions` to use another attribute name. The name must start with a letter and contain only letters and digits, with single hyphens between groups. For any other name, `createDomBinding` throws a `TypeError`.

## Auto-registration

The binding watches the root with a `MutationObserver`. The root is the `environment.root` that you pass, or the global `document`. The binding reacts to these changes:

- A new element anywhere under the root, including nested elements with the anchor attribute.
- A removed element, which unregisters its anchor.
- A change of the anchor attribute on an existing element.

You call no registration or cleanup function. A framework that mounts and unmounts elements, such as React, keeps the anchors in sync through this observer alone.

## Empty values

A blank or whitespace-only value does not register an anchor. In development mode, the binding warns one time for each element that has such a value.

## Duplicate IDs

If two elements register the same anchor ID, the newest registration wins. In development mode, the binding warns one time for each duplicate ID. When the newest element unmounts, the older element with the same ID becomes the anchor again.

A new element can mount before the old element with the same ID unmounts. Examples are React Strict Mode and a virtualized list that swaps rows. The rule "the newest registration wins" gives the same result every time in that case.

## Shadow DOM

The binding registers only elements in the light DOM of the root. It does not look inside shadow roots, so an element with the anchor attribute inside a shadow root never becomes an anchor.

The walk from a pointer target to its anchors crosses open shadow boundaries. As a result, a pointer target inside an open shadow root still finds the anchors on its shadow host and above it.

<Callout type="warn">
  If a web component holds the elements that you want to anchor, put the anchor attribute on the host element.
  An anchor attribute inside its shadow root has no effect.
</Callout>
