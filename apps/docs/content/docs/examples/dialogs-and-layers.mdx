A dialog covers the layout behind it, but a remote cursor can belong to either layer. Two cases need a rule. In the first case, the cursor of a peer (another client in the same room) is on a card behind your open dialog. In the second case, your cursor is inside a dialog that is closed for the peer. This demo runs that rule with a visibility policy. The cursor itself always paints above the dialog, because `CursorLayer` defaults to `z-index: 9999`.

Both panes pass the same policy through `resolution.visibilityPolicy`. The policy compares the sender's `context` and the resolved `anchorId` with the dialog state of its own pane. The binding reads `bindingOptions` once at creation. For this reason, the policy reads the dialog state through a ref.

## Behavior notes

- The wide pane runs a team board with an invite dialog. The narrow pane renders the board without the dialog.
- Mira opens the dialog with the context `{ dialog: "invite" }` and points at an anchor inside it. She closes it with the context `{ dialog: null }`. Theo stays on a card behind the dialog.
- While the wide dialog is open, the wide pane hides Theo's cursor: his anchor sits outside the dialog. The narrow pane hides Mira's cursor: her context names a dialog that is closed in this pane.
- Your cursor follows the same rule: while the dialog is open, it only shows where a dialog exists. The open pane hides your cursor on the board behind the dialog. The other pane hides your cursor, because your context names a dialog that is closed in that pane.
- A cursor inside the dialog paints above the dialog, because the z-index of the cursor is higher than the z-index of the dialog. This dialog is not a native modal `<dialog>`. For a native modal dialog, see [Dialogs and the top layer](/docs/react/cursor-layer#dialogs-and-the-top-layer).
- The Invite button opens the dialog, and its close button closes it. Mira's context also opens and closes the dialog. The dialog shows while Mira's context or your button keeps it open.
