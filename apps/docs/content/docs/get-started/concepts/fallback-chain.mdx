---
title: Fallback chain
description: How a cursor degrades from an exact anchor to viewport, and the resolution tiers.
---

A fallback chain lets a receiver place a cursor when the exact element is missing on its screen.

## Fallback chains

A fallback chain is the ordered list of anchors that a cursor position carries, most specific first, up to 8 entries.

The sender builds the chain by walking up from the pointer target through registered ancestor anchors. The binding caps the chain length at `maxAnchors`. See [Binding](/docs/dom/binding) for the default and its range.

The receiver walks the chain in order. It uses the first anchor that is connected to the DOM and has a non-zero size. If the exact element is missing on the receiver, the cursor moves to the next anchor in the chain. One example is a table row that does not exist in a shorter table.

## Viewport fallback

Every cursor position can also carry a `viewport` field: a normalized `u`/`v` position across the full browser window, computed from `pointerX / innerWidth` and `pointerY / innerHeight`.

When no anchor in the fallback chain resolves, the receiver falls back to this viewport position. Viewport fallback keeps a cursor visible even when every semantic anchor is missing on the receiver.

## Resolution tiers

Every resolved cursor carries a tier that names which fallback stage won: an exact anchor, the viewport position, or nothing. See [Resolution](/docs/dom/resolution) for the tier table and the pixel formulas.

The resolution order is fixed: the exact anchor, then each ancestor anchor in the chain from the nearest to the outermost, then the viewport position. After resolution, a visibility policy decides whether the cursor shows. The policy can hide an `anchor` or `viewport` tier cursor for application reasons. See [UI context](/docs/get-started/concepts/ui-context).

## Interpolation

The receiver eases a remote cursor from its last position to its new one, instead of jumping. The library ships two styles: `none` (snap) and `linear` (fixed-duration ease). Write a custom style, such as a spring, against the public `Interpolator` interface. See [Interpolation](/docs/core/interpolation).
