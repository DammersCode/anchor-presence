A codec turns a `CursorPresence` message into bytes for the wire, and turns bytes back into a value. `@anchor-presence/core` ships `jsonCodec`, the default, and `binaryCodec`, a compact binary codec with a fixed layout.

## CursorCodec

`@anchor-presence/core` exports `CursorCodec` with this shape:

```ts
interface CursorCodec {
  encode(message: CursorPresence): Uint8Array;
  decode(data: Uint8Array): unknown;
}
```

`decode` returns `unknown`, not `CursorPresence`, because the client checks the value after the decode. A codec must never throw from `decode`. For malformed input, `decode` returns a value that fails validation, for example `null`.

Pass a codec to `createPresenceClient`:

```ts
const client = createPresenceClient({ transport: myTransport, codec: myCodec });
```

## jsonCodec

`jsonCodec` works like this code:

```ts
const jsonCodec: CursorCodec = {
  encode(message) {
    return new TextEncoder().encode(JSON.stringify(message));
  },
  decode(data) {
    try {
      return JSON.parse(new TextDecoder().decode(data));
    } catch {
      return null;
    }
  },
};
```

`decode` catches JSON parse errors and returns `null`. `validatePresence(null)` then returns `null`, and the client drops the message. When you omit `codec` from `createPresenceClient`, the client uses `jsonCodec`.

## Choose a codec

`binaryCodec` sends about half the bytes of `jsonCodec`. A message with 4 anchors is 144 bytes with `binaryCodec` and 292 bytes with `jsonCodec`. That message has two-letter anchor IDs, coordinates with one decimal place, and a `user` with a name and a color. Coordinates with more decimal places make the JSON message longer. The binary message keeps its size, because each coordinate is an `f32`. `jsonCodec` writes readable JSON, so the network tab of the browser shows each message. See [Binary codec](/docs/core/binary-codec) for the wire layout and the encode limits.

## Same codec per room

All clients in the same room must use the same codec. The relay forwards bytes and does not convert between `jsonCodec` and `binaryCodec` frames. A client that decodes the bytes of another codec gets `null`, and `validatePresence` drops the message.
