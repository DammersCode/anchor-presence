You want a relay on the route API of [Elysia](https://elysiajs.com) instead of raw `Bun.serve`. This example uses the `.ws()` route of Elysia on Bun. Each room is one Bun topic, as in the [Bun relay](/docs/examples/backends/bun-native). The relay types its query with a schema. The client connects through Eden, the typed client of Elysia, so a wrong query parameter is a compile error on the client.

## Install

Install the packages with Bun:

```sh
bun add @anchor-presence/core @anchor-presence/dom elysia @elysia/eden
```

`treaty` creates the Eden client. Eden checks the query against the `ElysiaRelayApp` type of the relay. It builds the URL from the base URL of `treaty` and the typed query. For this reason, Eden ignores the URL that the transport builds. `edenSocket` gives the transport a fresh Eden socket for each connection. The cast to `WebSocketCtor` is necessary, because the Eden function does not match the type of the WebSocket constructor.

<Callout type="warn">
  If your room token expires, do not use this typed client. It sends one fixed room token on every connection,
  because Eden ignores the URL that carries the `token` function result. Use `createWebSocketTransport` with a
  `token` function instead.
</Callout>

## Run it

Start the entry file with Bun:

```sh
bun relay.ts
```

The relay listens on `http://localhost:8791`. To use a different port, give the port as the first argument.

## Behavior notes

Each setting is an environment variable. The factory options `maxMessageBytes`, `rateCapacity`, `rateRefillPerSecond`, `maxRoomSockets`, `maxSockets`, `idleTimeoutSeconds`, `allowedOrigins` and `authCheck` override them.

### What the relay does

| Topic            | Behavior                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Query            | Checks `room` and `token` against the schema before the upgrade. A wrong type fails the upgrade with HTTP `422`.                 |
| Room             | Reads `room` from the query. A missing value is `main`. An invalid name closes the socket with code `4007`.                      |
| Upgrade path     | Accepts the upgrade only at `/`. Any other path gets HTTP `404`.                                                                 |
| Fan-out          | `ws.publish` sends to every subscriber of the room topic except the sender.                                                      |
| Payload          | Forwards each frame unchanged. Decodes a frame only for identity binding.                                                        |
| Dead connections | Sets Bun's `idleTimeout` to `RELAY_IDLE_TIMEOUT_SECONDS` (60) with `sendPings`. Bun closes a socket that does not answer a ping. |
| Room cleanup     | Releases the room slot when a socket closes. Bun drops a topic with no subscribers.                                              |

### Limits

The rate limit is a token bucket: a socket can send a burst of 80 messages, then 40 messages per second.

| Limit               | Setting (default)                                                  | Above the limit                           |
| ------------------- | ------------------------------------------------------------------ | ----------------------------------------- |
| Message size        | `MAX_MESSAGE_BYTES` (32 KiB)                                       | Drops the message. The socket stays open. |
| Hard frame size     | Bun's `maxPayloadLength`: 4 × `MAX_MESSAGE_BYTES`, at least 1 MiB  | Bun closes the connection.                |
| Message rate        | `RATE_CAPACITY` (80) and `RATE_REFILL_PER_SECOND` (40)             | Drops the message. The socket stays open. |
| Sockets in one room | `RELAY_MAX_ROOM_SOCKETS` (64)                                      | Closes the new socket with code `4001`.   |
| Sockets in total    | `RELAY_MAX_TOTAL_SOCKETS` (10,000)                                 | Closes the new socket with code `4002`.   |
| Slow receiver       | `RELAY_SLOW_PEER_HARD_BYTES` (8 MiB), as Bun's `backpressureLimit` | Bun closes the receiver.                  |

Bun does not expose the send buffer of each subscriber. For this reason, the relay cannot skip sends to a slow receiver, as the [Node.js (ws)](/docs/examples/backends/node-ws) relay does.

### Auth

| Check            | Setting                                                                              | On refusal                                                         |
| ---------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| Origin           | `RELAY_ALLOWED_ORIGINS`, comma-separated. Empty allows every origin.                 | Upgrades, then closes with code `4004`.                            |
| Room token       | `RELAY_AUTH_TOKEN`. Compares the `token` query parameter. Empty turns the check off. | Closes with code `4006`.                                           |
| `authCheck` hook | Factory option. Replaces the room token check.                                       | Closes with code `4006` on `false` or an error.                    |
| Identity binding | `authCheck` returns `{ clientId, user }`.                                            | Drops a frame that is not a JSON object.                           |
| Check order      | Origin, then the hook, then room name.                                               | The hook runs for an invalid room name, with `room` set to `main`. |

See [Identity binding](/docs/examples/backends#identity-binding) for the demo identity mode.

<Callout type="warn">
  If you expose this relay outside local development, set `RELAY_ALLOWED_ORIGINS` and `RELAY_AUTH_TOKEN`. Also
  put a proxy that serves TLS (`wss://`) in front of the relay. Without them, any page and any visitor can
  join a room.
</Callout>
