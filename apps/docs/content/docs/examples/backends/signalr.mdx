`examples/signalr` runs the demo over an ASP.NET Core SignalR hub instead of a WebSocket relay. The hub is a dumb relay, same as the Socket.IO example: it forwards one method call to every other connection and never parses the payload.

## A simpler sketch

If your app talks to the hub directly with `@microsoft/signalr`'s `HubConnection`, wrap it more directly:

```ts
import type { LiveCursorTransport, ConnectionStatus } from "@anchor-presence/core";
import type { HubConnection } from "@microsoft/signalr";

export function createSignalRTransport(connection: HubConnection): LiveCursorTransport {
  const statusListeners = new Set<(status: ConnectionStatus) => void>();
  let status: ConnectionStatus = "connecting";
  const setStatus = (next: ConnectionStatus) => {
    status = next;
    for (const listener of statusListeners) listener(next);
  };

  connection.onreconnecting(() => setStatus("reconnecting"));
  connection.onreconnected(() => setStatus("connected"));
  connection.onclose(() => setStatus("disconnected"));

  return {
    connect: async () => {
      setStatus("connecting");
      await connection.start();
      setStatus("connected");
    },
    disconnect: () => connection.stop(),
    send: (data) => connection.send("OnPresence", data),
    subscribe: (listener) => {
      const handler = (data: Uint8Array) => listener(data);
      connection.on("PresenceReceived", handler);
      return () => connection.off("PresenceReceived", handler);
    },
    subscribeStatus: (listener) => {
      statusListeners.add(listener);
      listener(status); // replay so a late subscriber sees the current state
      return () => statusListeners.delete(listener);
    },
    getStatus: () => status,
  };
}
```

This sketch does not run in this repository's tests. The shipped `examples/signalr/transport.ts` does. Check the sketch against your hub version before you ship it.

## Behavior notes

- The hub adds each connection to a SignalR group for its room. `PresenceHub.OnPresence` forwards to `Clients.OthersInGroup(room)`, so a sender never receives its own message and other rooms never receive it.
- `examples/signalr/signalr-hub.test.ts` starts the real ASP.NET Core hub and runs two clients through it. The test skips when `dotnet` is not on `PATH`.
- `connection.send` and `connection.on` are fire-and-forget over the hub's method name; there is no acknowledgment, matching the transport interface's `send` contract.
