---
title: Visibility policy
description: VisibilityPolicy, the default policy, and how to write a custom one.
---

A `VisibilityPolicy` decides whether a resolved cursor renders. The resolver calls it once per remote client, per frame, after it computes the tier and the point's occlusion state.

## The default policy

If you do not set `resolution.visibilityPolicy`, `createDomBinding` uses `defaultVisibilityPolicy`:

```ts
const defaultVisibilityPolicy: VisibilityPolicy = ({ resolution }) =>
  resolution.tier === "hidden" ? "hide" : "show";
```

The default policy hides a cursor only when nothing resolved. It shows an `anchor` or `viewport` tier cursor even when the point sits in a clipped, scrolled-away region. See [Occlusion and scroll](/docs/dom/occlusion-and-scroll) for a policy that also hides a clipped point.

## Writing a custom policy

A policy receives the full presence, including `context` and `user`, and the resolution result. The first type parameter of `VisibilityPolicy` is the context type. This policy hides the cursors of staff users:

```ts
import type { VisibilityPolicy } from "@anchor-presence/dom";

const hideStaffCursors: VisibilityPolicy<{ role: string }> = ({ presence }) =>
  presence.context?.role === "staff" ? "hide" : "show";
```

The sender sets `context`, and nothing authenticates it. A policy hides a cursor on the receiver. It does not enforce a permission. See [Security](/docs/get-started/guides/security).

Pass the policy through `resolution.visibilityPolicy`. The client must have the same context type as the policy:

```ts
import { createPresenceClient } from "@anchor-presence/core";
import { createDomBinding } from "@anchor-presence/dom";

const client = createPresenceClient<{ role: string }>({ transport });
const binding = createDomBinding(client, {
  resolution: { visibilityPolicy: hideStaffCursors },
});
```

## What the policy can decide

The policy runs after tier resolution. It can act on the resolution tier, the winning anchor ID, or whether the point sits in a visible region (`pointVisible`). It can also read the sender's `context` and `user` values. A common use is hiding cursors for a role, a permission, or a UI mode the receiver's own state defines. See [UI context](/docs/get-started/concepts/ui-context).
