`@anchor-presence/dom` is the only package that calls browser APIs: `getBoundingClientRect`, `ResizeObserver`, `MutationObserver`, `requestAnimationFrame`, and pointer events. It depends only on `core`. See [Architecture](/docs/get-started/concepts/architecture).

## createDomBinding

```ts
import { createDomBinding } from "@anchor-presence/dom";

const client = createPresenceClient({ transport: myTransport });
const binding = createDomBinding(client);

binding.subscribe(() => {
  for (const cursor of binding.getSnapshot()) {
    if (cursor.visible) renderCursor(cursor.clientId, cursor.x, cursor.y);
  }
});
```

`createDomBinding(client, options?)` wires anchor auto-registration, pointer sampling, geometry scheduling, and remote resolution to a `PresenceClient`. It returns a `DomBinding`:

### invalidate

`binding.invalidate(reason?)` marks the layout dirty. The binding re-resolves the cursors on the next frame. Call it after a programmatic layout change the built-in signals cannot see. See [Performance](/docs/get-started/performance) for the full invalidation-signal list and when to call it yourself.

## Anchor attributes

An element is an anchor when it has a non-empty value for the configured attribute, `data-anchor` by default:

```tsx
<div data-anchor="nav.dashboard"></div>
```

Empty or whitespace-only values are ignored. Changing the attribute value re-registers the element under the new ID. Removing the attribute or the element unregisters the anchor. Duplicate anchor IDs use the newest registration and warn once in development.

## createWebSocketTransport

```ts
import { createWebSocketTransport } from "@anchor-presence/dom";
```

Native WebSocket transport for the bundled relay or a compatible relay. Exposes `bufferedBytes()` and reconnect with exponential backoff. See [Transports](/docs/core/transports) for a full walkthrough.
