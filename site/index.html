How it works

A cursor is an address, not a coordinate.

No screen position ever crosses the wire. You send a label plus an offset; each person’s browser turns it into pixels for their own layout.

01

You send what, not where

A pointer move becomes a label plus a position inside it: “the Revenue card, 42% across.” Never a screen coordinate.

02

Your channel carries it

It works over any real-time channel: WebSocket, Socket.IO, SignalR, BroadcastChannel. Plug in the one your app already runs.

03

Their browser does the rest

On their side, the label is measured against their own layout and turned into pixels. A different sidebar or screen size can’t misplace it.

no raw pixels cross the wirets
// sender: mark the elements you want to share
// <div data-anchor="stats.revenue">…</div>
// <tr data-anchor="orders.row:10482">…</tr>

const client = createPresenceClient({ transport, user: { name: "Phil" } })
createDomBinding(client)

// a pointer move becomes a semantic address, never a screen coordinate
// { anchors: [{ id: "stats.revenue", u: 0.42, v: 0.88 }], viewport: { u, v } }

// receiver: same address, different layout → its own pixels
const binding = createDomBinding(theirClient)
binding.subscribe(() => {
  for (const c of binding.getSnapshot()) renderCursor(c.user, c.x, c.y)
})

Guarantees

Built so it doesn’t break.

The demo runs on ten rules, held on every message. The ones you’ll feel on the first move:

01
No pixels on the wirePosition is a label + an offset, never a coordinate.
02
Your layout is the source of truthEach browser resolves against its own DOM.
03
Survives reflow and resizeThe cursor follows the element, not the frame.
04
Fails in a defined orderElement → parent → region → viewport → hidden.
05
Adapters stay thinThe framework layer never owns the engine’s state.
06
The channel is swappableThe engine imports no transport.
07
Reflow costs nothingA local layout change moves a still cursor with zero packets.
08
Messages can’t run codeAnchor IDs resolve only against elements marked with the binding’s anchor attribute.
09
You own the renderingNo cursor component is required.
10
Built to growThe boundary is designed to extend without touching the core.

Run it

Two windows, one cursor.

Start the relay and the demo, open two windows, and move the pointer. The other window tracks the same element across different sizes and sidebar states.

quickstart (requires bun)sh
$ git clone https://github.com/DammersCode/anchor-presence.git
$ cd anchor-presence
$ bun install
$ bun run build
# terminal 1 · relay
$ cd apps/server && bun run dev
# terminal 2 · demo (open two windows)
$ cd apps/demo && bun run dev

Give each window a distinct name so the cursors are easy to tell apart:
