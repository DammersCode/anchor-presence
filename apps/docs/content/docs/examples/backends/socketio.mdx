Your app already uses Socket.IO for other real-time features, and you want presence on the same connection. `examples/socketio` has a Socket.IO relay and a client transport for it. The relay forwards each `"presence"` event to the peers of the sender and never reads the payload. Every `@anchor-presence/react` hook works the same way as on a WebSocket relay.

## Install

Install the Socket.IO server and client with your package manager:

## Run it

Start the entry file with Bun, or with a TypeScript runner on Node.js:

```sh
bun relay.ts
# On Node.js:
npx tsx relay.ts
```

The relay listens on `http://localhost:5001`. To use a different port, give the port as the first argument.

## Close reasons

Socket.IO has no close codes. For this reason, the relay sends the code in one of two ways. The `io.use` middleware checks the handshake: first the origin, then the room name, then the `authCheck` hook. If a check fails, the client gets a `connect_error` with the code in `error.data.code`. After the handshake, the relay sends a `refused` event with a code and a reason, and then it disconnects the socket. The transport reports the code of both ways through `subscribeClose`:

| Code   | Meaning                             | How the relay sends it             |
| ------ | ----------------------------------- | ---------------------------------- |
| `1008` | Identity binding needs JSON frames. | `refused` event, then a disconnect |
| `4001` | The room is full.                   | `refused` event, then a disconnect |
| `4002` | The server is full.                 | `refused` event, then a disconnect |
| `4004` | The origin is not allowed.          | `connect_error` with `data.code`   |
| `4006` | The room token is missing or wrong. | `connect_error` with `data.code`   |
| `4007` | The room name is not valid.         | `connect_error` with `data.code`   |

A middleware error and a disconnect from the server both stop the Socket.IO client from retrying, so `willReconnect` is `false` for these codes. To show the reason to the user, subscribe to the close:

```ts
client.subscribeClose((close) => {
  if (!close.willReconnect && close.code === 4001) console.warn("The room is full.");
});
```

## Behavior notes

Each setting is an environment variable. The factory options `maxMessageBytes`, `rateCapacity`, `rateRefillPerSecond`, `maxRoomSockets`, `maxSockets`, `allowedOrigins` and `authCheck` override them. `allowedOrigins` is an array of strings in this relay.

### What the relay does

| Topic            | Behavior                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Room             | Reads `room` from the handshake query. A missing value is `main`. An invalid name gets a `connect_error` with code `4007`. |
| Upgrade path     | The default Socket.IO path, `/socket.io/`.                                                                                 |
| Fan-out          | `socket.to("room:" + room).emit` sends to every other socket in the room. The prefix keeps a socket ID from naming a room. |
| Payload          | Forwards each `"presence"` payload unchanged. Decodes a payload only for identity binding.                                 |
| Dead connections | The Socket.IO heartbeat closes them. The `pingInterval` and `pingTimeout` server options control it.                       |
| Room cleanup     | Releases the room slot when a socket disconnects. Socket.IO deletes an empty room.                                         |

### Limits

[Deploy a relay](/docs/get-started/guides/deploy-relay#set-the-environment-variables) lists the limits, their defaults, and the close codes. The relay sets the hard frame size with `maxHttpBufferSize`.

### Auth

| Check            | Setting                                                                              | On refusal                                                  |
| ---------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| Origin           | `RELAY_ALLOWED_ORIGINS`, comma-separated. Empty allows every origin.                 | `io.use` fails the handshake with code `4004`.              |
| Room token       | `RELAY_AUTH_TOKEN`. Compares the `token` handshake query. Empty turns the check off. | `connect_error` with code `4006`.                           |
| `authCheck` hook | Factory option. Replaces the room token check.                                       | `connect_error` with code `4006` on `false` or an error.    |
| Identity binding | `authCheck` returns `{ clientId, user }`.                                            | Sends a `refused` event with code `1008`, then disconnects. |
| Check order      | Origin, then room name, then the hook.                                               | The hook never runs for a refused origin or room.           |

See [Identity binding](/docs/examples/backends#identity-binding) for the rules. The relay never parses a payload without identity binding. The validation in the receiving client is then the only check between the wire and the store. See [Security](/docs/get-started/guides/security).

### Tests

`examples/socketio/socketio.test.ts` starts a real Socket.IO server on a free port and connects two clients. It checks that a cursor update from one client reaches the other through `getRemoteSnapshot()`. It also checks the rate limit.

<Callout type="warn">
  If you expose this relay outside local development, set `RELAY_ALLOWED_ORIGINS` and `RELAY_AUTH_TOKEN`. Also
  serve it over TLS (`https://`). Without them, any page and any visitor can join a room.
</Callout>
