These types describe the wire protocol that the client sends, checks, and stores. `@anchor-presence/core` exports every name on this page. Use the page when you write a relay, a codec, or code that reads raw messages. Import them from the package:

```ts
import type { PresenceMessage, RemotePresence } from "@anchor-presence/core";
```

## PresenceMessage

`PresenceMessage` is the wire format of one presence message.

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="PresenceMessage" />

A missing `user` or `context` field keeps the previous value of the same session. A `null` value clears it.

### Leave and event messages

A message with `leave: true` tells receivers that the client left. A message with an `event` field carries one [event](/docs/core/events). Both messages have a `null` cursor. An event message carries no `context`, `user`, or `pointer`.

Both codecs carry the two fields:

- `jsonCodec` writes `leave` and `event` as JSON fields.
- `binaryCodec` writes a leave message with cursor tag `2`. It writes an event message with cursor tag `3`, followed by the event `type`. The event `data` uses the slot of `user`.

<Callout type="warn">
  If a relay checks messages, it must pass `leave` and `event` through. If a relay drops these fields, a
  client that left stays until the stale timeout. Each event then arrives as a message that clears the cursor
  of the sender.
</Callout>

## PresenceEvent

A `PresenceEvent` is a one-shot event that `client.sendEvent` sends.

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="PresenceEvent" />

`RemoteEvent` is a `PresenceEvent` plus the `clientId` of the sender. `client.subscribeEvents` gives a `RemoteEvent` to its listener.

## PeerChange

A `PeerChange` reports a peer that joined, left, or changed its `user` or `context`. `client.subscribePeers` gives a `PeerChange` to its listener. See [Peer changes](/docs/core/remote-presence#peer-changes).

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="PeerChange" />

## CursorPosition

A `CursorPosition` is the cursor position inside one presence message. It holds a fallback chain of anchors and an optional viewport position.

## RemotePresence

A `RemotePresence` is a stored presence message without the `sequence` field and with an `idle` field. `client.getRemotePresence()` returns an array of this type. See [Idle state](/docs/core/remote-presence#idle-state).

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="RemotePresence" />

## PointerInfo and PointerType

`PointerInfo` holds the optional pointer info of a presence message. `PointerType` is `"mouse" | "pen" | "touch"`.

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="PointerInfo" />

## ConnectionStatus

`ConnectionStatus` is `"connecting" | "connected" | "reconnecting" | "disconnected"`. See [Connection status](/docs/core/transports#connection-status) for how a transport reports it.

## validatePresence

`validatePresence(input: unknown, limits?: ValidationLimits): PresenceMessage | null` checks one decoded message. It returns the checked message, or `null` for a message to drop. It never throws, and it does not check `maxMessageBytes`. See [Use validatePresence directly](/docs/core/validation#use-validatepresence-directly).

## ValidationLimits

`ValidationLimits` is the shape of the `validationLimits` option and of the `limits` argument. Each field is optional. See [ValidationLimits](/docs/core/validation#validationlimits) for the result of each limit.

## Protocol constants

Import the protocol constants from `@anchor-presence/core`:

```ts
import {
  DEFAULT_MAX_CLIENT_ID_LENGTH,
  DEFAULT_MAX_SESSION_LENGTH,
  DEFAULT_MAX_SEQUENCE,
  DEFAULT_MAX_ANCHORS,
  DEFAULT_MAX_ANCHOR_ID_LENGTH,
  DEFAULT_MAX_FIELD_BYTES,
  DEFAULT_MAX_FIELD_DEPTH,
  DEFAULT_MAX_MESSAGE_BYTES,
  MAX_EVENT_TYPE_LENGTH,
} from "@anchor-presence/core";
```

The `DEFAULT_` constants are the defaults of `ValidationLimits`. See [ValidationLimits](/docs/core/validation#validationlimits) for each value and what it checks.

`MAX_EVENT_TYPE_LENGTH` is the maximum length of an event `type`. `ValidationLimits` cannot change it. See [Limits of an event](/docs/core/events#limits-of-an-event).

## Wire frames

A `jsonCodec` frame is the UTF-8 JSON of one `PresenceMessage`. A relay forwards these bytes unchanged. This frame moves a cursor over two anchors and a viewport position:

```json
{
  "version": 1,
  "clientId": "client-1",
  "session": "session-1",
  "sequence": 1,
  "cursor": {
    "anchors": [
      { "id": "board.card-12", "u": 0.25, "v": 0.5 },
      { "id": "board", "u": 0.5, "v": 0.25 }
    ],
    "viewport": { "u": 0.4, "v": 0.3 }
  },
  "pointer": { "type": "mouse" }
}
```

This frame sends one event:

```json
{
  "version": 1,
  "clientId": "client-1",
  "session": "session-1",
  "sequence": 2,
  "cursor": null,
  "event": { "type": "reaction", "data": { "emoji": "party" } }
}
```

This frame tells peers that the client left:

```json
{ "version": 1, "clientId": "client-1", "session": "session-1", "sequence": 3, "cursor": null, "leave": true }
```

The cursor frame has no `user` field, because the user did not change. See [Remote presence](/docs/core/remote-presence) for how the store keeps the last value.
