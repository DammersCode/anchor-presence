---
title: Remote users
description: Read the remote user values with useRemoteUsers, one entry per client.
---

`useRemoteUsers` returns one entry per remote client, with the client's `user` value, its session, and whether it is idle. Use it for a presence list or an avatar stack, where you need one row per person, not one row per cursor frame.

## Usage

```ts
function useRemoteUsers<TUser = unknown>(): RemoteUser<TUser>[];
```

```tsx
import { useRemoteUsers } from "@anchor-presence/react";

type MyUser = { name: string; color: string };

function PresenceList() {
  const users = useRemoteUsers<MyUser>();
  return (
    <ul>
      {users.map((entry) => (
        <li key={entry.clientId} style={{ opacity: entry.idle ? 0.5 : 1 }}>
          {entry.user?.name ?? "Guest"}
        </li>
      ))}
    </ul>
  );
}
```

Each `RemoteUser` entry has:

| Field      | Type                 | Meaning                                           |
| ---------- | -------------------- | ------------------------------------------------- |
| `clientId` | `string`             | the remote client that sent the user value        |
| `user`     | `TUser \| undefined` | the user value, or `undefined` when none was sent |
| `session`  | `string`             | the session ID of the client                      |
| `idle`     | `boolean`            | `true` when the client sent no update for a while |

## Render cost

The hook rerenders only when the set of remote clients changes, or when one entry's `user`, `session`, or `idle` field changes. A remote cursor moving across the screen does not rerender this hook, because position is not part of `RemoteUser`.

The returned list, and each unchanged entry inside it, keep the same object identity across renders. A `React.memo` row component keyed by `clientId` skips rendering for every user whose fields did not change.
