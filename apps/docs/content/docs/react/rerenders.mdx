A hook in `@anchor-presence/react` rerenders its component when the value that it returns changes, or when the provider value changes. `useSendEvent`, `usePresenceClient`, and `useDomBinding` rerender on any change of the provider value. Use this page to pick the hook with the smallest value that a component needs. Then an unrelated update does not rerender the component.

## Usage

If your app has a [typed `presence.ts` module](/docs/react/typed-hooks), import the hooks from it. The package export reads only the provider of `@anchor-presence/react`.

This badge shows the resolution tier of one peer. It rerenders only when that tier changes, not on every cursor frame:

```tsx
import { useCallback } from "react";
import { useRemoteCursorsSelector, type ResolvedCursor } from "@anchor-presence/react";

function TierBadge({ clientId }: { clientId: string }) {
  const select = useCallback(
    (cursors: readonly ResolvedCursor[]) =>
      cursors.find((cursor) => cursor.clientId === clientId)?.tier ?? "hidden",
    [clientId],
  );
  const tier = useRemoteCursorsSelector(select);
  return <span>{tier}</span>;
}
```

## Rerender rules

| Hook                                                                          | Rerenders when                                                                                      |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| [useRemoteCursors](/docs/react/remote-cursors)                                | a new snapshot of resolved cursors arrives: every frame while cursors move                          |
| [useRemoteCursorsSelector](/docs/react/remote-cursors#select-a-smaller-value) | its `select` output changes under `isEqual`                                                         |
| [useRemoteUsers](/docs/react/remote-users)                                    | a peer joins or leaves, or the `user`, `session`, or `idle` field of a peer changes                 |
| [useRemotePresence](/docs/react/remote-presence)                              | a peer joins or leaves, or its `cursor`, `context`, `user`, `pointer`, `session`, or `idle` changes |
| [useSendEvent](/docs/react/remote-events)                                     | the provider value changes (client, binding, or the `clientPending` flag)                           |
| [usePresenceStatus](/docs/react/connection-status)                            | the connection status changes                                                                       |
| [useLocalContext](/docs/react/local-context#local-context)                    | the local context value changes                                                                     |
| [useLocalUser](/docs/react/local-context#local-user)                          | the local user value changes                                                                        |
| [usePeerChanges](/docs/react/remote-users#peer-changes)                       | never by itself: it calls its listener and returns nothing                                          |
| [useRemoteEvents](/docs/react/remote-events)                                  | never by itself: it calls its listener and returns nothing                                          |
| [usePresenceClient](/docs/react/api/hooks#usepresenceclient)                  | the provider value changes (client, binding, or the `clientPending` flag)                           |
| [useDomBinding](/docs/react/api/hooks#usedombinding)                          | the provider value changes (client, binding, or the `clientPending` flag)                           |

A peer that turns idle or expires also changes the values that hooks return, so hooks can rerender in a room with no inbound messages. When a factory finishes creating its client, the provider value changes and every hook rerenders. The value changes again when the provider creates its own binding.

## CursorLayer rerenders

`CursorLayer` follows the same rule. It reads the cursors through `useRemoteCursorsSelector`, so a cursor that `filterCursor` removes causes no render. Each cursor row is memoized, so a row renders again only when its resolved values change. This works only with stable callbacks. See [Keep the callbacks stable](/docs/react/cursor-layer#keep-the-callbacks-stable).
