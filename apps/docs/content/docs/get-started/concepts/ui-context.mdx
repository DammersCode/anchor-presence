UI context is app state that a sender attaches to its cursor, for example the open dialog or the route. A visibility policy on the receiver reads that context and shows or hides the cursor. Use context when the anchor alone cannot tell whether a cursor makes sense on the receiver. Anchor Presence never changes the UI state of the receiver.

## Set the context

Call `setContext` on the client:

```ts
client.setContext({ route: "/settings", dialog: "invite" });
```

In React, use the [`useLocalContext`](/docs/react/local-context) hook. On the receiver, the context reaches the visibility policy and the `context` field of each `ResolvedCursor`.

## What the client sends

The `context` field of `PresenceMessage` is opaque: `@anchor-presence/core` gives it no meaning.

- The client sends a changed context once. Later messages leave the field out, which means "unchanged".
- Reconnect and heartbeat messages carry the current context, so a late peer gets it.
- `setContext(undefined)` sends `null`, which clears the context on every peer.
- The receiver drops a context above 8 KiB of JSON. If the receiver has a local context, it also checks the shape of each remote context. See [Remote user and context](/docs/core/validation#remote-user-and-context).

<Callout type="warn">If you put private data in context, every peer in the room gets it.</Callout>

## Visibility policies

A visibility policy is a pure function that decides whether a resolved cursor shows:

```ts
type VisibilityPolicy<TContext = unknown, TUser = unknown> = (input: {
  presence: PresenceMessage<TContext, TUser>;
  resolution: { tier: ResolutionTier; anchorId: string | null; pointVisible: boolean };
}) => "show" | "hide";
```

`ResolutionTier` is `"anchor" | "viewport" | "hidden"`. The default policy hides only the `hidden` tier. `pointVisible` is `false` when a scroll container clips the point. See [Occlusion and scroll](/docs/dom/occlusion-and-scroll).

Pass a custom policy in `resolution.visibilityPolicy` of the binding options. In React, pass it in `bindingOptions` of `PresenceProvider`. [Visibility policy](/docs/dom/visibility-policy) has the full reference.

## Dialog mismatch handling

The cursor of a sender can sit inside the anchor `settings.dialog.invite`. If that dialog is closed on the receiver, the fallback chain moves to a parent anchor, for example `settings`. A cursor at that place can mislead the receiver. Pick one of three approaches:

- **Hide the cursor.** If `presence.context?.dialog` names a dialog that is closed on the receiver, return `"hide"`.
- **Fall back to the dialog trigger.** Give the button that opens the dialog a stable anchor ID. Then the fallback chain lands on that button.
- **Show a muted cursor.** Keep the cursor, and render a muted version from the `tier` and `context` of the resolved cursor.

This policy hides the cursor of a sender whose `dialog` context is not the dialog that is open on the receiver:

```ts
const dialogAwarePolicy: VisibilityPolicy<{ dialog?: string }> = ({ presence, resolution }) => {
  const senderDialog = presence.context?.dialog;
  if (typeof senderDialog === "string" && senderDialog !== myOpenDialogId()) return "hide";
  return resolution.tier === "hidden" ? "hide" : "show";
};
```

The client needs the same context type as the policy, for example `createPresenceClient<{ dialog?: string }>`. The binding cannot see the open dialog of the receiver. When it changes, call `binding.invalidate()` to run the policy again. See [Run the policy again after a state change](/docs/dom/visibility-policy#run-the-policy-again-after-a-state-change).

## Share typing and away

Two common states fit in `context`: the anchor where the user types, and whether the tab is hidden. The sender sets both with `useLocalContext`. The receiver reads them with `useRemotePresence`.

`setContext` replaces the whole context. The hook below merges each change into the current local context, so a change of one field never drops the other. It sends a new context only when a field changes. Call `useStatus` once, in a parent, and pass `publish` to each box. Then one `visibilitychange` listener serves every box:

```tsx
import { useLocalContext, useRemotePresence } from "@anchor-presence/react";
import { useCallback, useEffect, useRef } from "react";

type Person = { name: string };
type Status = { typingIn: string | null; away: boolean };

const TYPING_STOP_MS = 2000;

function useStatus(): (patch: Partial<Status>) => void {
  const [context, setContext] = useLocalContext<Status>();
  const latest = useRef(context);

  useEffect(() => {
    latest.current = context;
  }, [context]);

  const publish = useCallback(
    (patch: Partial<Status>) => {
      const current = { typingIn: null, away: false, ...latest.current };
      const next = { ...current, ...patch };
      if (next.typingIn === current.typingIn && next.away === current.away) return;
      latest.current = next;
      setContext(next);
    },
    [setContext],
  );

  useEffect(() => {
    const sync = () => publish({ away: document.visibilityState === "hidden" });
    sync();
    document.addEventListener("visibilitychange", sync);
    return () => document.removeEventListener("visibilitychange", sync);
  }, [publish]);

  return publish;
}

function CommentBox({ anchorId, publish }: { anchorId: string; publish: (patch: Partial<Status>) => void }) {
  const stopTimer = useRef<ReturnType<typeof setTimeout>>(undefined);

  const stopTyping = () => {
    clearTimeout(stopTimer.current);
    publish({ typingIn: null });
  };

  useEffect(() => () => clearTimeout(stopTimer.current), []);

  return (
    <textarea
      data-anchor={anchorId}
      aria-label="Comment"
      onChange={() => {
        publish({ typingIn: anchorId });
        clearTimeout(stopTimer.current);
        stopTimer.current = setTimeout(stopTyping, TYPING_STOP_MS);
      }}
      onBlur={stopTyping}
    />
  );
}

function Comments() {
  const publish = useStatus();
  return <CommentBox anchorId="comments.box" publish={publish} />;
}

function TypingHint({ anchorId }: { anchorId: string }) {
  const names = useRemotePresence<Status, Person>()
    .filter(({ context }) => context?.typingIn === anchorId && !context.away)
    .map(({ user }) => user?.name ?? "Someone");

  return names.length === 0 ? null : <p>{names.join(", ")} typing…</p>;
}
```

Render `<TypingHint anchorId="comments.box" />` next to `<Comments />`. Both read the same anchor ID. If your app puts more fields in the context, for example a `selection` from the [kanban recipe](/docs/examples/kanban#show-who-is-on-a-card), use one context type with all fields. Both recipes spread the current context before they change a field, so neither drops the other's field.

`away` is a visibility flag that the sender sets on `visibilitychange`. It is true at once when the tab is hidden, and false at once when the tab shows again. A peer with `away: true` does not show as typing, even if its last typing state was never cleared. The receiver treats `typingIn` and `away` as untrusted: it compares them, and renders only `user.name` as text.

### Idle or away

The store sets `idle` on a peer whose presence did not change for `idleAfterMs`, 15 seconds by default. It needs no code in the sender, and it cannot tell a tab in the background from a user who reads. A context change ends the idle state, so a sender that sets `away` also resets the idle timer.

- Use `idle` to dim a cursor that stopped. `CursorLayer` and `useRemoteUsers` already give it.
- Use `away` when you need to know at once, and for a reason you can name, like a hidden tab.

## Never change the receiver UI

A remote cursor only gives information. It must not change a route, open or close a dialog, expand a sidebar, or scroll the page of the receiver. If a cursor points into UI that is closed on the receiver, fall back or hide the cursor.

Do not change local UI state as a reaction to `useRemoteCursors()` or `useRemotePresence()`. Use `context` to decide how to show a cursor, nothing more. [Follow mode](/docs/get-started/guides/follow-mode) is the one exception: the user asks to follow a peer, so a scroll is the expected result.
