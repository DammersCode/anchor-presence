# Library Review — Compact Findings (canonical)

Scope: core library + public user/React API only (packages/core, packages/dom, packages/react). Examples/apps/tests ignored.
Provenance: no pre-existing review file was found in the repo, worktrees, or artifacts, so this review was **generated** (not compressed) on 2026-09-01 by three specialized review agents (core / dom / react+API) plus an independent full read by the advisor. Duplicates merged: R-3→D-1, D-7→C-4.

Format: `ID | Bereich | Problem | Evidenz | Impact | vorgeschlagener Fix | Severity`

## Core (@anchor-presence/core)

- C-1 | client.ts | `setContext`/`setUser` never trigger a publish; changes reach peers only on next cursor move or heartbeat (≤10 s) | client.ts:207-213 no `schedulePublish()`; timer guard `latestCursor !== lastSentCursor` (155) would skip anyway | Spec §12 use case (receiver policy reacting to sender context) acts on stale context | Mark dirty + schedule publish on setContext/setUser | medium
- C-2 | client.ts | `"reconnecting"` counts as sendable, so `send()` "succeeds" (transport silently drops), `lastSentCursor` updates, and the reconnect republish in `setStatus` never fires on reconnecting→connected | client.ts:114 `wasSendable = status !== "connecting" && status !== "disconnected"`; 137 blocks only disconnected/connecting | Stale cursor/context on peers up to 10 s after every drop-recover cycle | Treat reconnecting as unsendable, or republish on every transition into connected | medium
- C-3 | transport.ts + client.ts | Status contract lacks "emit current status on subscribe"; client starts at `"connecting"` (client.ts:101) and a transport already connected before subscribe leaves it stuck there forever — receives but never sends | transport.ts:11; no replay requirement in spec §5 or docs/transports.md examples | Silent permanent publish failure with e.g. `await transport.connect()` before `createPresenceClient()` | Require replay-on-subscribe in the contract (+ fix docs/examples), or add `getStatus()` to the transport interface | high
- C-4 | protocol.ts + client.ts + pointer.ts | Wire field `pointer?: {type}` is validated inbound but impossible to send: no option, no producer, `buildMessage` never sets it (merged: D-7) | protocol.ts:22 vs client.ts:123-134; pointer.ts discards `event.pointerType` | Dead v1 protocol field; type promises more than runtime delivers | Thread `pointerType` through, or drop the field from v1 | low
- C-5 | client.ts | `dispose()` sends no leave message (`cursor: null`); peers keep a ghost cursor until stale sweep (default 70 s) | client.ts:238-251; only dom pointerleave/blur publish null | Every SPA unmount/navigation leaves a frozen cursor for all peers | Best-effort `send(null)` at top of dispose while sendable | medium
- C-6 | client.ts | Inbound transport callback runs `codec.decode` + `store.ingest` + consumer listeners unguarded; a throwing custom codec or subscriber propagates into the transport dispatch loop | client.ts:181-189; store.ts:90-93 sync listener fan-out | One bad codec/subscriber can kill delivery for all listeners of the transport | try/catch around handler body, drop message on error | low
- C-7 | client.ts | Timing options unvalidated: `staleTimeoutMs: 0` → `setTimeout(0)` sweep busy loop; `heartbeatMs <= 0` → message flood | client.ts:170-178 | Plausible misconfig burns CPU / floods transport instead of erroring | Validate/clamp options at creation | low
- C-8 | client.ts | `registerTeardown` after `dispose()` silently drops the fn (array already drained) | client.ts:234-236, 248 | Late-registered cleanup never runs; silent listener leak | Run fn immediately (or throw) when disposed | low
- C-9 | client.ts | Publish dedup is reference equality on the cursor object; a consumer mutating and re-passing the same `CursorPosition` gets silent no-op publishes | client.ts:155 | Direct core consumers (not using dom) can see updates stop with no error | Use a dirty flag set in `updateLocalCursor`, or document fresh-object requirement | low

## DOM (@anchor-presence/dom)

- D-1 | binding.ts, pointer.ts + core client.ts | `registerTeardown` has no unregister; every `createDomBinding`/`attachPointerSource` permanently appends its dispose closure to the client (merged: R-3) | binding.ts:110, pointer.ts:95; client.ts:234-236 only pushes | StrictMode/remount/HMR against a long-lived client retains disposed bindings (scheduler, registry, resolver) until client dispose; unbounded growth | `registerTeardown` returns an unregister fn; binding/pointer unregister on their own dispose | medium
- D-2 | scheduler.ts | Invalidation signals (scroll capture on document, MutationObserver on doc.body, transition events) are blind to shadow roots, though registry/pointer/occlusion explicitly support shadow-DOM anchors | scheduler.ts:231, 240; scroll/transition are composed:false; MO doesn't descend into shadow roots | Anchors in web components: frozen/misplaced cursors on shadow-internal scroll/mutation (Invariant 7 broken there) | Observe shadow roots of registered anchors, or document the limitation | medium
- D-3 | scheduler.ts + pointer.ts | `getCachedRect` serves previous-frame rects even after an invalidation marked the scheduler dirty, contradicting pointer.ts's own comment | scheduler.ts:107-110 sets dirty only; 318-320 ignores it; pointer.ts:40-41 | Scroll+pointermove in same frame publishes briefly wrong u/v; transient receiver wobble | Return undefined from getCachedRect while dirty | low
- D-4 | pointer.ts | Document-level `pointerenter` listener allegedly never yields a sample (enter events don't bubble; target at doc is non-Element) — needs browser verification | pointer.ts:83 + eventTargetElement (20-25) | Dead registration; re-entry sampled only on first pointermove | Drop listener or verify actual browser dispatch behavior | low
- D-5 | occlusion.ts | `computeVisibleRect` intersects every overflow-clipping DOM ancestor regardless of CSS containing-block rules; positioned anchors that escape `overflow:hidden` get `pointVisible:false` while visible | occlusion.ts:74-83, no position check | With docs-recommended clippedPointPolicy, cursors over non-portaled popovers/dropdowns wrongly hidden | Stop clip walk at containing-block boundaries, or document limitation | low
- D-6 | scheduler.ts + occlusion.ts | Computed styles not cached per frame; clip-ancestor walk repeats per cursor → N cursors on one anchor do N full walks with fresh `getComputedStyle` per ancestor | scheduler.ts:97-99 passthrough; frameCache.ts:55; resolver.ts:85 per presence | Breaks read-once-per-frame batching intent; overhead near the 100-cursor budget | Memoize getStyle (and visibleRect per anchor) in frame cache | low

## React / Public API (@anchor-presence/react + cross-package)

- R-1 | contextStore.ts + docs/react.md | `useCursorContext` never sees the client's initial `context` option and desyncs on direct `client.setContext()`; docs promise "returns the current context value" | contextStore.ts:15 unseeded; core client.ts:90 | Stale/empty context rendered whenever context set outside the hook's own setter | Add `getContext()` reader to PresenceClient and seed/read from it | medium
- R-2 | core protocol.ts + dom pointer.ts | Both packages export `DEFAULT_MAX_ANCHORS` with different values and meanings (8 = inbound validation cap vs 4 = outbound chain length) | protocol.ts:28 vs pointer.ts:7, both re-exported from index | Auto-import silently picks the wrong semantic; sender can be tuned above receiver cap without signal | Rename the dom one (e.g. DEFAULT_MAX_SENT_ANCHORS) | medium
- R-4 | react index.ts | React package re-exports none of the foreign types in its public signatures (`ResolvedCursor`, `PresenceClient`, `DomBinding`, `CursorPresence`, `ConnectionStatus`, …) | e.g. cursor.tsx:20 forces import from @anchor-presence/dom | react-only consumers can't name callback/return types without direct deps on core/dom | Re-export the public-signature types from react | low
- R-5 | docs/react.md | Documented `useRemoteCursors` shape omits `pointVisible`, which a later doc example uses | docs/react.md:109 vs resolver.ts:17 and docs/react.md:132 | Reference misses the field its own recipe requires | Add pointVisible to the documented shape | low
- R-6 | binding.ts + hooks.ts | After `client.dispose()`/`binding.dispose()` with provider still mounted, listeners are cleared without a final notify; hooks render the last snapshot/status forever | binding.ts:108, client.ts:247; hooks.ts:70 | Cursors stay painted and status freezes after disposal, no re-notification path | Publish empty snapshot + "disconnected" before clearing listeners | low
- R-7 | cursor.tsx + binding/resolver | `sameCursors` compares by element identity, but every scheduler pass builds new `ResolvedCursor` objects, so the selector equality never holds while any cursor is visible → CursorLayer re-renders on every pass even when nothing changed (e.g. unrelated mutation-triggered re-measure) | cursor.tsx:9-11; resolver.ts:158/192 new objects per resolveAll | Selector memoization is defeated; extra React renders on every invalidation with static cursors | Structural equality in sameCursors, or cache unchanged ResolvedCursor instances in the resolver | medium

## Reviewer health summaries
- core: good shape; weaknesses cluster in connection-status lifecycle (C-2, C-3) and delayed non-cursor state propagation (C-1, C-5).
- dom: clean layering, SSR-safe, correct rAF coalescing; real issues are client-teardown registration (D-1) and shadow-DOM invalidation (D-2).
- react: well built (uSES usage, StrictMode, SSR); packaging (exports/types/sideEffects/peers) clean.
