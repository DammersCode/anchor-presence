You want a relay that runs on plain Node, not Bun, with a well-known WebSocket library. This example uses [`ws`](https://github.com/websockets/ws) over `node:http`, with each room kept as a plain `Set<WebSocket>`.

## Install

Install the packages with Bun:

```sh
bun add @anchor-presence/core @anchor-presence/dom ws
bun add -D @types/ws
```

## Client

The client needs no custom transport. It connects with the native `createWebSocketTransport`:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";

const transport = createWebSocketTransport({ port: 8789, path: "/?room=main" });
const client = createPresenceClient({ transport });
```

```sh

```

The relay listens on `http://localhost:8789`. To use a different port, give the port as the first argument.

## Behavior notes

- **Room name validation.** The relay reads the room from the `room` query parameter. `parseRoom` caps room names at 256 characters and restricts them to `[A-Za-z0-9_-]`. A missing name is `main`. An invalid name closes the socket with code `4007`.
- **Upgrade path.** The relay accepts the upgrade only at `/`. It answers any other path with HTTP `404`.
- **Max payload size.** The message handler drops a message above `MAX_MESSAGE_BYTES` (default 32 KiB) and keeps the connection open. The `maxPayload` option of `ws` is a hard limit at four times that size, or at least 1 MiB. Above it, `ws` closes the connection.
- **Per-connection rate limit.** A token bucket limits inbound messages per socket (`RATE_CAPACITY`, `RATE_REFILL_PER_SECOND`).
- **Origin allowlist.** `RELAY_ALLOWED_ORIGINS` is a comma-separated list of allowed origins. Leave it empty for local development. The relay then accepts every origin. The relay accepts the upgrade of a foreign origin and then closes the socket with code `4004`.
- **Connection check.** Pass an `authCheck` function to check each connection. Without it, set `RELAY_AUTH_TOKEN`. The relay then compares the [room token](/docs/dom/websocket-transport#room-token) of each connection with that value.
- **Identity binding.** If `authCheck` returns `{ clientId, user }`, the relay writes that identity into every JSON frame of the connection. See [Identity binding](/docs/examples/backends#identity-binding).
- **Room cleanup.** The relay drops a room's entry once its last socket closes.
- **Connection caps.** `RELAY_MAX_ROOM_SOCKETS` (default 128) limits one room. `RELAY_MAX_TOTAL_SOCKETS` (default 10,000) limits the process. Above either cap, the relay closes the new socket with code `4001` (room full) or `4002` (server full).
- **Dead connections.** The relay sends a ping to each socket at an interval of half `RELAY_IDLE_TIMEOUT_SECONDS` (default 60, so every 30 seconds). It terminates a socket that did not answer the previous ping.
- **Slow receivers.** `ws` exposes `bufferedAmount` per socket. The relay skips sends above `RELAY_SLOW_PEER_SOFT_BYTES` (default 1 MiB). It closes the connection with code `4003` above `RELAY_SLOW_PEER_HARD_BYTES` (default 8 MiB).

<Callout type="warn">
  If you expose this relay outside local development, set `RELAY_ALLOWED_ORIGINS` and `RELAY_AUTH_TOKEN`, and
  put a proxy that serves TLS (`wss://`) in front of it. Without them, any page and any visitor can join a
  room.
</Callout>
