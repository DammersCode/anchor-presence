`PresenceProvider` shares a presence client and its DOM binding with every hook and component below it. The DOM binding is the object from `@anchor-presence/dom` that turns remote presence into screen positions. Every app that uses `@anchor-presence/react` wraps its cursor-aware tree in one provider.

## Usage

The samples on this page connect to the Bun relay of the [Quick start](/docs/get-started/quick-start#connect-a-relay), on port 8788. This provider creates the client through `factory`:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, PresenceProvider } from "@anchor-presence/react";

function App() {
  return (
    <PresenceProvider
      factory={() => {
        const transport = createWebSocketTransport({ port: 8788, path: "/?room=main" });
        return createPresenceClient({ transport });
      }}
    >
      <Dashboard />
      <CursorLayer />
    </PresenceProvider>
  );
}
```

## Props

The provider takes `factory`, `client`, `binding`, `bindingOptions`, `clientKey`, `bindingKey`, and `children`. For the type of each prop, see [Components API](/docs/react/api/components#presenceprovider).

Pass `factory` or `client`. The types forbid passing both. In JavaScript, `client` wins. For the difference between the two, read [Create the client](/docs/react/client-creation). The provider disposes a client that `factory` created. It never disposes a `client` that you pass.

To render without a client, for example on the server, pass `client={null}`. See [SSR and Strict Mode](/docs/react/ssr-and-strict-mode).

## The binding

If you omit `binding`, the provider creates one with `createDomBinding(client, bindingOptions)`. It disposes that binding when the client changes, when `bindingKey` changes, or when the provider unmounts.

If you pass `binding`, the provider creates no binding and never disposes yours. Use this to share one binding across two providers. The provider then ignores `bindingOptions`.

The provider reads `bindingOptions` only when it creates the binding. A later change to the `bindingOptions` object has no effect until `bindingKey` or the client changes.

## Rebuild the binding

To apply a new `bindingOptions` value, change `bindingKey`. The provider disposes the binding and creates a new one with the current `bindingOptions`. The client stays connected, so each peer keeps your cursor.

This example switches the interpolator:

```tsx
import { createPresenceClient, linearInterpolator, noneInterpolator } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, PresenceProvider } from "@anchor-presence/react";

function Workspace({ smooth }: { smooth: boolean }) {
  return (
    <PresenceProvider
      factory={() =>
        createPresenceClient({ transport: createWebSocketTransport({ port: 8788, path: "/?room=main" }) })
      }
      bindingKey={smooth}
      bindingOptions={{
        resolution: { interpolatorFactory: smooth ? linearInterpolator : noneInterpolator },
      }}
    >
      <Dashboard />
      <CursorLayer />
    </PresenceProvider>
  );
}
```

## Switch rooms

To replace the client that `factory` made, change `clientKey`. The provider disposes the old client and runs the current `factory` again. The tree below the provider does not remount.

This example joins the room that the `room` prop names:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, PresenceProvider } from "@anchor-presence/react";

function Room({ room }: { room: string }) {
  return (
    <PresenceProvider
      clientKey={room}
      factory={() => {
        const transport = createWebSocketTransport({
          port: 8788,
          path: `/?room=${encodeURIComponent(room)}`,
        });
        return createPresenceClient({ transport });
      }}
    >
      <Dashboard />
      <CursorLayer />
    </PresenceProvider>
  );
}
```

<Callout type="warn">
  If you pass `client`, the provider ignores `clientKey`. To switch the room of a client that you own, dispose
  it and pass a new client.
</Callout>

The provider ignores a new `factory` function until `clientKey` changes. An inline `factory` is safe for this reason.

## Development warnings

In development mode, the provider writes one console warning in each of these cases:

- It gets neither `client` nor `factory`. It then renders without presence.
- It gets both `client` and `factory`. It then ignores `factory`.
- It gets both `binding` and `bindingOptions`. It then ignores `bindingOptions`.

## A factory that is not a function

If `factory` is set and is not a function, and you pass no `client`, the provider throws a `TypeError` in every build mode. It throws on mount in the browser, never on the server.
