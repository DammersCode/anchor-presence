You want a relay built on a small, framework-shaped router instead of raw `Bun.serve`. This example uses [Hono](https://hono.dev)'s `hono/bun` adapter, which wires `upgradeWebSocket` and a `websocket` handler straight into `Bun.serve`.

This example picks `hono/bun` over `@hono/node-ws` because this relay runs on Bun already. `@hono/node-ws` gives the same helper on plain Node, for a Hono app that does not run on Bun.

## Install

```sh
bun add @anchor-presence/core @anchor-presence/dom hono
```

## Client

The client needs no custom transport. It connects with the native `createWebSocketTransport`:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";

const transport = createWebSocketTransport({ port: 8790, path: "/?room=main" });
const client = createPresenceClient({ transport });
transport.connect();
```

## Run it

```sh
cd examples/hono
bun run dev:relay
```

The relay listens on `http://localhost:8790`.

## Production notes

- **Room name validation.** `sanitizeRoomName` caps room names at 256 characters and restricts them to `[A-Za-z0-9_-]`. An invalid or missing name falls back to `"main"`.
- **Max payload size.** `MAX_MESSAGE_BYTES` (default 32 KiB) drops an oversized message instead of closing the connection.
- **Per-connection rate limit.** A token bucket limits inbound messages per socket (`RATE_CAPACITY`, `RATE_REFILL_PER_SECOND`).
- **Origin allowlist.** `RELAY_ALLOWED_ORIGINS` is a comma-separated list of allowed origins. Leave it empty for local development. Every origin is accepted then.
- **Auth hook placeholder.** Pass an `authCheck` function, or set `RELAY_AUTH_TOKEN` for a plain shared-token check.
- **Room cleanup.** The relay drops a room's entry once its last socket closes.
- **Per-room connection cap.** `RELAY_MAX_ROOM_SOCKETS` limits one room. There is no process-wide cap in this example.
- **Backpressure on slow consumers.** `WSContext.raw` exposes the underlying Bun socket's `getBufferedAmount()`. The relay skips sends above a soft watermark and closes above a hard one.

<Callout type="warn">
  Every Hono WebSocket event (`onOpen`, `onMessage`, `onClose`) gets a new `WSContext` wrapper around the same
  Bun socket. Key room state on `ws.raw`, not on the `WSContext` object, or membership checks will never match
  across events.
</Callout>

Set `RELAY_ALLOWED_ORIGINS` and `RELAY_AUTH_TOKEN` before you expose this relay past local development. Put a TLS-terminating proxy in front of it.
