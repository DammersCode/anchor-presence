`@anchor-presence/dom` is the only package that calls browser APIs. It turns a `PresenceClient` from `@anchor-presence/core` into a list of resolved cursors: the position of each remote cursor in the pixels of your viewport. It renders nothing. `@anchor-presence/react` uses it for you. Use it directly to draw cursors without React, or to build an adapter for another UI framework.

This sample connects a client and logs each visible cursor:

```ts
import { createPresenceClient } from "@anchor-presence/core";
import { createDomBinding } from "@anchor-presence/dom";

const client = createPresenceClient({ transport: myTransport });
const binding = createDomBinding(client);

binding.subscribe(() => {
  for (const cursor of binding.getSnapshot()) {
    if (cursor.visible) renderCursor(cursor.clientId, cursor.x, cursor.y);
  }
});
```

## What the binding does

`createDomBinding` does four jobs:

<Mermaid
  chart={`flowchart LR
  page["page: data-anchor elements"] --> registry["anchor registry"]
  pointer["local pointer events"] --> client["PresenceClient"]
  registry --> pointer
  client --> resolver["resolver, once per frame"]
  registry --> resolver
  resolver --> snapshot["ResolvedCursor[] snapshot"]`}
/>

- It watches the page for elements with an anchor attribute and registers them.
- It listens for pointer events and reports the local cursor position relative to the nearest anchors.
- It reads the remote presence from the client and resolves each cursor against the layout of this page.
- It schedules layout reads on the frame clock, so a resolve pass runs at most once per frame.

See [How it works](/docs/get-started/concepts/how-it-works) for the full picture.
