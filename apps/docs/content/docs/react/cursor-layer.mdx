---
title: CursorLayer
description: Render every visible remote cursor with labels, colors, and filtering.
---

`CursorLayer` renders one fixed-position root per visible remote cursor. No cursor component is required. If you need a different rendering model, build your own with [useRemoteCursors](/docs/react/remote-cursors) instead.

## Basic use

This app renders the remote cursors with the defaults:

```tsx
import { CursorLayer, LiveCursorProvider } from "@anchor-presence/react";

function App() {
  return (
    <LiveCursorProvider client={client}>
      <Dashboard />
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

With no props, `CursorLayer` renders `DefaultCursor` for each visible cursor. If `user.name` is a string that is not empty, it is the label of the cursor. Each client gets one color from a palette of 8 colors, picked from its `clientId`, so one client keeps its color on every screen. See [Custom cursors](/docs/react/custom-cursors) to replace the cursor content or its default styling.

## Label and color

`getLabel` and `getColor` run once per visible cursor. They replace the default label and the default color:

```tsx
type MyUser = { name: string; color?: string };

<CursorLayer<unknown, MyUser>
  getLabel={(cursor) => cursor.user?.name ?? "Guest"}
  getColor={(cursor) => cursor.user?.color ?? "#6b7280"}
/>;
```

<Callout type="warn">
  If you render remote `user` data, treat it as text, never as HTML. Another client sends this data, and it
  can hold any value. See [Security](/docs/get-started/guides/security).
</Callout>

## Filter cursors

`filterCursor` hides a cursor when it returns `false`. It runs after the visibility check, so a hidden cursor never reaches `getLabel` or `getColor`:

```tsx
<CursorLayer filterCursor={(cursor) => cursor.tier !== "viewport"} />
```

## Extra props on the root

`getCursorProps` adds classes, non-geometry styles, and attributes to each cursor's root element:

```tsx
<CursorLayer
  getCursorProps={() => ({
    className: "my-cursor",
    "data-testid": "remote-cursor",
  })}
/>
```

`CursorLayer` sets `position`, `left`, `top`, `transform`, `pointerEvents`, and `opacity` after your style, so your value never replaces them. The `zIndex` prop replaces the default of `9999`, which keeps cursors above most app UI.

## Dialogs and the top layer

<Callout type="warn">
  If a dialog opens with `<dialog>.showModal()`, or an element uses `popover`, it covers the cursors. The
  browser renders these elements in the top layer, above every `z-index`. Render a second `CursorLayer` inside
  the dialog or the popover.
</Callout>

<Callout type="warn">
  If an ancestor of `CursorLayer` has a `transform`, `filter`, or `contain` style, the cursors move to wrong
  positions. These styles change the box that `position: fixed` refers to. Render `CursorLayer` at the root of
  the app.
</Callout>

## Accessibility

- Each cursor root has `aria-hidden="true"` and `pointerEvents: "none"`, so a screen reader and pointer input both skip it.
- The opacity transition on a cursor's root follows the OS reduced-motion setting: `CursorLayer` skips it when the operating system prefers reduced motion.
- `DefaultCursor` sets `forced-color-adjust: none`, so its arrow and label keep their own colors under Windows forced-colors mode.
- Label text contrast is your app's palette choice: `getLabel`, `getColor`, and `renderCursor` control the content and colors that `CursorLayer` renders.

See [Custom cursors](/docs/react/custom-cursors) to change what a cursor renders, and [Motion](/docs/dom/motion) for the interpolator and reduced-motion behavior underneath it.
