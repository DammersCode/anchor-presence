Pointer capture is the part of the binding that turns local pointer events into the local cursor. The binding listens on the document and calls `client.setLocalCursor` on each relevant event. It is on by default. Set `capturePointer: false` for a client that only shows remote cursors.

This binding also sends a cursor for keyboard focus:

```ts
const binding = createDomBinding(client, { captureFocus: true });
```

## What the binding sends

On `pointermove`, `pointerdown`, and `pointerover`, the binding reads the event target, walks its anchor ancestors, and builds a `CursorPosition`. It ignores a touch or pen event whose `isPrimary` is `false`, for example a second finger on a touch screen. The `CursorPosition` has these fields:

- `anchors`: the fallback chain, most specific first, up to `maxSentAnchors` entries. Each entry carries the anchor ID and the `u`/`v` position inside the rectangle of that anchor. The binding skips an anchor with a zero width or height.
- `viewport`: the `u`/`v` position across the full window, when the window has a non-zero size.

The binding rounds each `u` and `v` value to 4 decimal places. It reads each rectangle from the cache of the current frame when one exists, and calls `getBoundingClientRect()` otherwise. The cache is at most one frame old.

If an element has pointer capture, the event target stays the element where the drag started. In this case, the binding uses the element under the pointer instead, through `document.elementFromPoint`.

The binding also sends the pointer type, `mouse`, `pen`, or `touch`, from the `pointerType` of the event.

<Callout type="warn">
  If the browser reports another pointer type, the binding sends the cursor with no pointer type.
</Callout>

## When the cursor clears

The binding sends a `null` cursor position, which hides the local cursor on every receiver, in these cases:

- `pointerleave` on the document, when the pointer leaves the browser window.
- `blur` on the window, when the tab or window loses focus.
- `pointerup` or `pointercancel` of the primary touch pointer. As a result, a touch cursor does not stay after the finger leaves the screen.
- `binding.dispose()`, unless you pass `keepLocalCursor: true`. See [Dispose](/docs/dom/binding#dispose).

A switch to another tab blurs the window, so two tabs in one window never show each other a cursor. To test on one computer, open the page in two windows side by side.

On `pagehide`, the binding calls `client.leave()` instead. Each peer then removes the whole client at once, not only its cursor. See [Page hide](/docs/dom/binding#page-hide).

## Keyboard focus

By default, the binding ignores keyboard focus. With `captureFocus: true`, the binding sends a cursor for keyboard users:

- On `focusin`, it sends a cursor at the center of the focused element.
- On `focusout`, it clears the cursor when focus leaves the document.
- If the focused element has a zero-size rectangle, it sends no cursor.

<Callout type="warn">A focus cursor clears the pointer type, so peers show it with no type.</Callout>

## Event listeners

The binding adds its listeners to the document and the window, not to each anchor. `pointerover` and `pointermove` bubble, so one listener on the document covers every element.

## Skip part of the page

Add `data-anchor-private` to an element to keep the pointer over it private. Over that element and everything inside it, the binding sends no cursor. Peers see your cursor disappear, not move to a parent anchor.

```html
<input type="password" data-anchor-private />
```

The rule also holds for an element inside a shadow root. With `captureFocus`, focus that moves into the element clears the cursor in the same way. The cursor comes back when the pointer or the focus moves to an element outside it.

To use another attribute name, set `privateAttribute`. The name follows the same rules as `anchorAttribute`:

```ts
const binding = createDomBinding(client, { privateAttribute: "data-no-cursor" });
```

Over an element with no anchor and no private mark, the binding sends the nearest anchored parent. Set `capturePointer: false` to stop sending for the whole page.

## Touch behavior

A touch pointer fires the same `pointermove`, `pointerdown`, and `pointerover` events as a mouse. The binding does not separate a touch scroll from a touch drag, and it has no option to ignore touch pointers.

With the default `touch-action`, a second finger starts a pinch. The browser then sends `pointercancel` for both pointers, and the cursor clears. When the first finger lifts, the remaining finger does not take over the cursor, because its `isPrimary` is `false`. To keep one cursor on a canvas or a drawing surface, set `touch-action: none` on that element.
