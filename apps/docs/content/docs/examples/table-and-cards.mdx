A list can show as a table on a wide screen and as a stack of cards on a narrow screen. The fields of one record move to different places. In this demo, the wide pane shows invoices as table rows. The narrow pane shows each invoice as a card. A cursor on the status cell of a row lands on the status pill of the same card.

The `field` helper builds every anchor ID from the invoice ID and the field name. As a result, the table and the cards cannot use different IDs for the same field.

## Behavior notes

Try it: Move your pointer down the amount column in the wide pane.

- Each field has the same anchor ID in the table and in the card, for example `invoices.row:INV-2043.status`.
- Each row and each card has the anchor `invoices.row:<id>`. A cursor between two fields resolves to the record.
- The action buttons have their own anchors. A cursor on "Remind" in the table lands on "Remind" in the card.
- In the narrow pane, the cursor moves to the second line of each card.
- The fields move and change size when the pane shrinks. The demo shows this worst case on purpose. For the layout rule, see [Keep item sizes and shapes alike](/docs/get-started/guides/layout-design#keep-item-sizes-and-shapes-alike).
