## Try it with no backend

`createInMemoryPair` gives you two connected transports in one process. Use it to see the library work before you wire up a relay:

```tsx
import { createInMemoryPair, createPresenceClient } from "@anchor-presence/core";
import { LiveCursorProvider, CursorLayer } from "@anchor-presence/react";

const { a: transport } = createInMemoryPair();
const client = createPresenceClient({ transport, user: { name: "Alice" } });

function DashboardButton() {
  return <button data-anchor="nav.dashboard">Dashboard</button>;
}

function App() {
  return (
    <LiveCursorProvider client={client}>
      <DashboardButton />
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

This client only talks to itself: `transport.a`'s messages go to `transport.b`'s listeners, and nothing else holds `transport.b`. It is enough to render the tree and check that anchors, the provider, and `CursorLayer` compile and mount. It is also how the docs site tests every sample on this page.

## Connect two real clients

Real live cursors need two clients, one per browser tab, talking over a shared transport. Create the client inside `usePresenceClient`, so React Strict Mode's double-invoke in development does not create two clients or connect the transport twice:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, LiveCursorProvider, usePresenceClient } from "@anchor-presence/react";

function App() {
  const client = usePresenceClient({
    factory: () =>
      createPresenceClient({
        transport: createWebSocketTransport({ path: "/?room=main" }),
        user: { name: "Alice" },
      }),
  });

  return (
    <LiveCursorProvider client={client}>
      <button data-anchor="nav.dashboard">Dashboard</button>
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

`usePresenceClient` runs the factory once, in a mount effect, and returns `null` until it has run. `LiveCursorProvider` accepts `client={null}` and renders normally, so the first render before the effect (and every server render) is safe. See [SSR and Strict Mode](/docs/guides/ssr-and-strict-mode) for the full rule.

`apps/server` in the repository is a matching Bun WebSocket relay. Run it locally:

```sh
cd apps/server && bun run dev
```

`room` is a relay-side grouping key, not part of the protocol. Any bidirectional byte channel that implements the transport interface works in place of `createWebSocketTransport`. See [Transports](/docs/guides/transports).
