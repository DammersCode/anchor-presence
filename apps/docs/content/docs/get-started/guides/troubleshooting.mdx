Most cursor problems have one of three causes: a missing anchor, a connection that is not open, or a layout change that the binding cannot see. Find your symptom below. Read the [development warnings](#development-warnings) in the browser console first, because they name most causes.

## No cursor at all

If no remote cursor ever appears, do these checks in order:

<Steps>
<Step>

Open the browser console, and read the warnings with the prefix `[anchor-presence]`.

</Step>
<Step>

Show the value of `usePresenceStatus()`. If it is not `"connected"`, the transport has no open connection.

</Step>
<Step>

Log the close `code` and `reason` with `client.subscribeClose(listener)`. Find the code in the [close code table](/docs/examples/backends/relay-contract#close-codes).

</Step>
<Step>

For a WebSocket transport, open the network panel of the browser developer tools, and read the frames of the connection. If no frames arrive, the relay does not forward the messages of the other client.

</Step>
<Step>

Make sure that both clients use the same room and the same codec.

</Step>
</Steps>

## Cursor not visible

Four causes give the same symptom.

**The sender is not active.** When its window loses focus or the pointer leaves the page, the sender clears its cursor. Two tabs in one window never show each other a cursor. To test on one computer, open two windows side by side. See [When the cursor clears](/docs/dom/pointer-capture#when-the-cursor-clears).

**The anchor is not registered.** The sender can point at an element that has no matching anchor ID on the receiver. If the fallback chain and the viewport position both miss, the tier is `hidden`. Make sure that both clients render the same anchor ID for the same element.

**A visibility policy hides it.** A custom policy can return `"hide"` for a cursor that the default policy shows. The default policy hides only the `hidden` tier. Check the policy in `resolution.visibilityPolicy` of the binding options. See [UI context](/docs/get-started/concepts/ui-context).

**The peer is idle or stale.** A peer is **idle** after `idleAfterMs` (default 15 000 ms) with no change. `CursorLayer` dims an idle cursor. A heartbeat that changes nothing does not end the idle state. A peer is **stale** after `staleTimeoutMs` (default 70 000 ms) with no message, and the store then removes it. A background tab still sends a heartbeat every `heartbeatIntervalMs` (default 10 000 ms). A browser can slow the timers of a hidden tab to one run per minute, so a long background period can still remove the peer.

## Cursor is outside the window

The resolver also resolves anchors that are scrolled out of view. `ResolvedCursor.x` and `ResolvedCursor.y` are pixels in the viewport. To find a cursor outside the window, compare them with the window size:

```ts
const offscreen = x < 0 || y < 0 || x > window.innerWidth || y > window.innerHeight;
```

[Off-screen hints](/docs/get-started/guides/offscreen-hints) shows an arrow at the window edge for each such cursor.

## Cursor floats over empty space

An inner scroll container can clip an anchor that is still measurable. The resolver then sets `pointVisible` to `false`, but the default policy still shows the cursor. [Occlusion and scroll](/docs/dom/occlusion-and-scroll) shows a policy that hides these cursors, and the limits of the check.

## Cursor drifts

A cursor can slowly move away from its element when a container moves without a signal that the scheduler watches. One example is a rule that you add with `CSSStyleSheet.insertRule()`: it changes layout and writes no attribute. After such a change, call `invalidate()` on the binding:

```ts
binding.invalidate("custom-layout-change");
```

See [Invalidation signals](/docs/get-started/guides/performance#invalidation-signals) for the signals that the scheduler watches.

## Cursor jumps between two elements

If the pointer crosses a gap with no anchored parent, the cursor falls back to the viewport position. On a receiver with another layout, that position is at another place, so the cursor jumps. Give the parent container its own anchor, for example `data-anchor="nav"` on a sidebar.

Two neighbors can also be far apart in the other layout. [Layout design for presence](/docs/get-started/guides/layout-design) gives the rules for both cases, and a skill that measures them.

## Two tabs share one clientId

A `clientId` identifies one client instance, not one user. If two tabs use one `clientId`, each tab ignores the messages of the other, because a client ignores its own `clientId`. A third tab sees one peer whose cursor jumps between the two tabs.

Use the default `clientId`, which is random for each client. Put the identity of the user in the `user` field.

## Plain HTTP

The client works on plain HTTP. The default `idFactory` builds each ID from 72 random bits of `crypto.getRandomValues()`. If `crypto` is missing, it uses `Date.now()` and `Math.random()`. For your own ID format, pass `idFactory` or `clientId` to `createPresenceClient`.

## Tests in jsdom

jsdom has no layout. `getBoundingClientRect()` returns zeros unless a test mocks it, and `ResizeObserver` can be missing. A jsdom test can check your own logic with mocked rectangles. For wrapping, sidebar states, and element sizes, use a real browser, for example Playwright on Chromium, Firefox, and WebKit. If a behavior is correct in jsdom but wrong in a browser, suspect a jsdom gap first.

## Development warnings

Outside production builds, the library writes warnings to the console with the prefix `[anchor-presence]`. Production builds write none. `isDevMode()` decides which build is a production build. [Development mode](/docs/core/presence-client#development-mode) lists the warnings of the client in `@anchor-presence/core`. This table lists the warnings of the other packages:

| Package | Warning                                                             | Cause and fix                                                                                                                                                                       | How often             |
| ------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| react   | A hook or `CursorLayer` runs outside the provider                   | No `PresenceProvider` is above it, so it returns empty data. Wrap the tree in the provider.                                                                                         | One time              |
| react   | The provider got neither `client` nor `factory`                     | The provider renders without presence. Pass one of the two props.                                                                                                                   | One time              |
| react   | The provider got both `client` and `factory`                        | The provider uses `client` and ignores `factory`. Pass one of the two props.                                                                                                        | One time              |
| react   | The provider got both `binding` and `bindingOptions`                | The provider uses `binding` and ignores `bindingOptions`. Pass one of the two props.                                                                                                | One time              |
| dom     | Duplicate anchor ID                                                 | Two elements use one anchor ID. The newest element wins. See [Duplicate IDs](/docs/dom/anchor-registration#duplicate-ids).                                                          | One time for each ID  |
| dom     | Empty anchor attribute value                                        | An element has `data-anchor=""`. The binding ignores it.                                                                                                                            | One time per element  |
| dom     | The relay closed the connection with code N                         | The relay closed the WebSocket with a code of `4000` or more. See the [close codes](/docs/examples/backends/relay-contract#close-codes).                                            | On each close         |
| dom     | The connection closed with code N and the client does not reconnect | The default reconnect rule stopped after a close code below `4000`, which is `1008` today. A custom `shouldReconnect` never warns. Read the reason, and fix the cause on the relay. | One time for each URL |
| dom     | The connection to URL failed 4 times in a row                       | No socket to the URL opened in 4 attempts in a row. Make sure that a relay runs at the URL, and that `port` and `path` are correct.                                                 | One time for each URL |
| dom     | `createWebSocketTransport` ignores host, port and path              | You passed `url` and also `host`, `port`, or `path`. The transport uses `url` only. Remove the other options.                                                                       | One time              |
| dom     | `connect()` after `disconnect()` is a no-op                         | After `disconnect()`, a WebSocket transport cannot connect again. Create a new transport.                                                                                           | On each call          |
| dom     | `createWebSocketTransport` found no global `WebSocket`              | The runtime has no global `WebSocket`, for example an older Node.js, so the status becomes `disconnected`. Pass `WebSocketCtor`, or connect in the browser.                         | One time              |
| dom     | A BroadcastChannel transport dropped a message                      | The client sent while the transport was not connected. Call `connect()` first, or keep the default `autoConnect`.                                                                   | One time              |
| dom     | Cursor resolution threw (console error)                             | A visibility policy or an interpolator threw. The binding keeps the last snapshot and tries again on the next change.                                                               | On each throw         |
