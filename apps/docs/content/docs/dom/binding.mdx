`createDomBinding(client, options?)` creates the DOM side of one presence client. It returns a `DomBinding`: an object with a snapshot of resolved cursors, a `subscribe` method, and a `dispose` method. A resolved cursor is the position of one remote cursor in the pixels of your viewport. Create one binding for each client. `@anchor-presence/react` creates it for you.

## Create a binding

Call `createDomBinding` with a `PresenceClient`:

```ts
import { createPresenceClient } from "@anchor-presence/core";
import { createDomBinding } from "@anchor-presence/dom";

const client = createPresenceClient({ transport: myTransport });
const binding = createDomBinding(client);

binding.subscribe(() => {
  for (const cursor of binding.getSnapshot()) {
    if (cursor.visible) renderCursor(cursor.clientId, cursor.x, cursor.y);
  }
});
```

The binding runs its geometry scheduler only while two conditions are true:

- The client is live: its status is `connecting` or `connected`.
- At least one peer has a cursor.

In all other cases the scheduler stops, so an empty room costs no frame work.

## Options

| Option            | Default       | Effect                                                                                                                                                                             |
| ----------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `anchorAttribute` | `data-anchor` | The attribute that marks an anchor element. See [Anchor registration](/docs/dom/anchor-registration).                                                                              |
| `maxAnchors`      | `4`           | The length of the fallback chain that the binding sends. The binding clamps an integer outside `1` to `8` into this range.                                                         |
| `capturePointer`  | `true`        | Sends the local pointer as a cursor. With `false`, the client shows remote cursors and sends no cursor. `context` and `user` still go to peers.                                    |
| `captureFocus`    | `false`       | Sends a cursor at the center of the focused element, for keyboard users. Ignored when `capturePointer` is `false`. See [Keyboard focus](/docs/dom/pointer-capture#keyboard-focus). |
| `resolution`      | see below     | How remote cursors turn into screen positions. See [Resolution](/docs/dom/resolution) and [Motion](/docs/dom/motion).                                                              |
| `environment`     | the browser   | The DOM and timing hosts: `root`, `window`, `raf`, `caf`, `ResizeObserverCtor`, `MutationObserverCtor`.                                                                            |

Each `environment` field defaults to the matching browser global. A test can replace one host with a fake and keep the others. See [Binding API](/docs/dom/api/binding) for the full types.

For a same-origin iframe, `root` can be its `contentDocument`, with its `contentWindow` as `window`. The binding identifies an element by its `nodeType`, so the elements of the iframe pass that check. The tests cover only a root in the same document as the binding code, so an iframe root is not tested.

`createDomBinding` throws a `TypeError` in these cases:

- `anchorAttribute` is not letters and digits in groups split by single hyphens, with a letter first. For example, `data-anchor` and `anchor` pass, and `data_anchor` and `1-anchor` fail.
- `maxAnchors` is not an integer, for example `2.5` or `NaN`.

## Draw cursors without React

Subscribe to the binding and update one element for each cursor. Set `CURSOR_MARKER_ATTRIBUTE` on the root element of each cursor. The binding then ignores the DOM changes inside your cursors and does not measure the layout again for them.

This function draws each visible cursor as a `div` inside `layer`, and returns the unsubscribe function:

```ts
import { CURSOR_MARKER_ATTRIBUTE, type DomBinding } from "@anchor-presence/dom";

function drawCursors(binding: DomBinding, layer: HTMLElement): () => void {
  const elements = new Map<string, HTMLElement>();
  return binding.subscribe(() => {
    const shown = new Set<string>();
    for (const cursor of binding.getSnapshot()) {
      if (!cursor.visible) continue;
      shown.add(cursor.clientId);
      let element = elements.get(cursor.clientId);
      if (element === undefined) {
        element = document.createElement("div");
        element.setAttribute(CURSOR_MARKER_ATTRIBUTE, "");
        element.setAttribute("aria-hidden", "true");
        element.className = "remote-cursor";
        layer.append(element);
        elements.set(cursor.clientId, element);
      }
      element.style.transform = `translate(${cursor.x}px, ${cursor.y}px)`;
    }
    for (const [clientId, element] of elements) {
      if (shown.has(clientId)) continue;
      element.remove();
      elements.delete(clientId);
    }
  });
}
```

`x` and `y` are viewport pixels. Give `.remote-cursor` the CSS `position: fixed`, `left: 0`, `top: 0`, and `pointer-events: none`. `aria-hidden="true"` keeps the cursor away from screen readers. `@anchor-presence/react` uses the same styles and attribute on each cursor root. The final empty snapshot of `dispose` removes every element.

## invalidate

`binding.invalidate(reason?)` marks the layout dirty. On the next frame, the binding measures every active anchor again and resolves the cursors again. An active anchor is an anchor that a remote cursor uses.

While the scheduler runs, the binding reacts to these layout signals:

- A window resize, or a scroll of the document or of any element.
- A size change of an active anchor or of the document element.
- A DOM change anywhere in the document body, outside the cursor elements.
- A CSS transition or animation on an element outside the cursor layer that can change geometry.

Call `invalidate` after a layout change that none of these signals can see. One example is a web font that loads after the first paint and moves an anchor without a change to its size:

```ts
document.fonts.ready.then(() => {
  binding.invalidate("fonts-loaded");
});
```

The binding does not read `reason`. It is for your own code.

If state that your `visibilityPolicy` reads changes, also call `invalidate`. See [Run the policy again after a state change](/docs/dom/visibility-policy#run-the-policy-again-after-a-state-change).

## Connection status

While the client status is `reconnecting` or `disconnected`, the binding hides every remote cursor, and the snapshot is empty. The remote presences stay in the client store. When the status returns to `connected`, the binding resolves the cursors again and shows them. The `connecting` status does not hide cursors.

## Page hide

On the `pagehide` event of the window, the binding calls `client.leave()`. Peers then remove this client at once, so a closed tab does not leave a cursor behind. If the page stays open, for example after a return from the back-forward cache, the next publish or heartbeat announces the client again.

## Errors in a policy or interpolator

If a `visibilityPolicy` or an interpolator throws, the binding keeps the last snapshot and does not stop. In development mode, it logs the error with `console.error`. The binding tries again on the next remote, anchor, or layout change.

If a `binding.subscribe` listener throws, the binding reports the error through the development warning. It still calls the other listeners.

## Dispose

`binding.dispose()` stops the binding. When the surface that owns the binding unmounts, call it one time. `client.dispose()` also calls it. `dispose` does these steps in order:

1. It clears the local cursor on the client, unless you pass `keepLocalCursor: true`. As a result, a client that stays connected leaves no cursor on its peers.
2. It stops the scheduler and removes every listener.
3. It sends one final empty snapshot, so subscribers can remove every cursor.
4. It clears the subscriber list.

If you replace the binding and keep the client, pass `keepLocalCursor: true`. Peers then keep the local cursor while the new binding starts:

```ts
binding.dispose({ keepLocalCursor: true });
const nextBinding = createDomBinding(client, { resolution: { hitTest: true } });
```
