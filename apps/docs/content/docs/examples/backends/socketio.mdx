Your app already uses Socket.IO for other real-time features, and you want presence on the same connection. `examples/socketio` has a Socket.IO relay and a client transport for it. A peer is another client in the same room. The relay forwards each presence message to the peers of the sender. Every `@anchor-presence/react` hook works the same way as on a WebSocket relay.

Use it like any other transport:

```ts
import { createPresenceClient } from "@anchor-presence/core";
import { io } from "socket.io-client";
import { createSocketIoTransport } from "./transport";

const socket = io("https://your-server.example", { query: { room: "main" } });
const client = createPresenceClient({ transport: createSocketIoTransport(socket) });
```

## Close reasons

Socket.IO has no close codes. For this reason, the relay sends a `refused` event with a code and a reason before it disconnects a socket. The transport reports that code through `subscribeClose`:

| Code   | Meaning                             | How the relay sends it             |
| ------ | ----------------------------------- | ---------------------------------- |
| `4001` | The room is full.                   | `refused` event, then a disconnect |
| `4002` | The server is full.                 | `refused` event, then a disconnect |
| `4006` | The room token is missing or wrong. | `connect_error` with `data.code`   |
| `4007` | The room name is not valid.         | `refused` event, then a disconnect |

A disconnect from the server stops the Socket.IO client from retrying, so `willReconnect` is `false` for these codes. An origin outside the allowlist fails the handshake with no code. To show the reason to the user, subscribe to the close:

```ts
client.subscribeClose((close) => {
  if (!close.willReconnect && close.code === 4001) console.warn("The room is full.");
});
```

## Behavior notes

- `subscribeStatus` replays the current status to every new subscriber. As a result, a component that mounts after the socket connects still learns that it can send.
- The relay never parses `"presence"` payloads. The validation in the receiving client is the only check between the wire and the store. See [Security](/docs/get-started/guides/security).
- A token bucket (a counter that refills at a fixed rate) limits the inbound `"presence"` messages of each socket (`RATE_CAPACITY`, default 80, and `RATE_REFILL_PER_SECOND`, default 40). The relay drops a message above the limit and keeps the socket open.
- The relay limits one room with `RELAY_MAX_ROOM_SOCKETS` (default 64) and the process with `RELAY_MAX_TOTAL_SOCKETS` (default 10,000).
- Socket.IO closes dead connections with its own heartbeat. The `pingInterval` and `pingTimeout` server options control it.
- If `authCheck` returns `{ clientId, user }`, the relay binds that identity to every JSON frame of the socket. See [Identity binding](/docs/examples/backends#identity-binding).
- `examples/socketio/socketio.test.ts` starts a real Socket.IO server on a free port and connects two clients. It checks that a cursor update from one client reaches the other through `getRemoteSnapshot()`. It also checks the rate limit.
