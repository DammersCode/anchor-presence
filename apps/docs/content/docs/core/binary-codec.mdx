`binaryCodec` is a compact binary codec with a fixed layout. `@anchor-presence/core` ships it. It sends smaller messages than `jsonCodec`.

Pass `binaryCodec` as the `codec` option:

```ts
import { binaryCodec, createPresenceClient } from "@anchor-presence/core";

const client = createPresenceClient({ transport: myTransport, codec: binaryCodec });
```

## Wire layout

The layout is little-endian. The fields come in this order:

1. Header: magic `0x41`, format `2`, protocol version `1`.
2. `clientId`: a `u16` byte length, then the UTF-8 bytes.
3. `session`: a `u16` byte length, then the UTF-8 bytes.
4. `sequence`: a `u32`.
5. Cursor tag: `0` for a `null` cursor, `1` for a cursor, `2` for a leave message, `3` for an event.
6. For tag `3` only: a `u16` byte length of the event type, then the UTF-8 event type.
7. For tag `1` only: a `u8` anchor count. Then each anchor: a `u16` id length, the UTF-8 id, an `f32` `u`, and an `f32` `v`.
8. For tag `1` only: a viewport tag, `0` absent or `1` present. A present viewport adds an `f32` `u` and an `f32` `v`.
9. Pointer tag: `0` absent, `1` present without a type, `2` `mouse`, `3` `pen`, `4` `touch`.
10. `context` tag: `0` absent, `1` explicit `null`, or `2` JSON. Tag `2` adds a `u32` byte length and the UTF-8 JSON.
11. `user` tag: the same encoding as `context`.

An event frame writes the pointer tag and the `context` tag as `0`. It writes the event `data` in the `user` slot.

The `context` and `user` values stay JSON inside the binary frame. The cursor fields use the fixed layout. As a result, `binaryCodec` is smaller than `jsonCodec` for a typical message with many anchors.

## Coordinate precision

`binaryCodec` stores the anchor and viewport `u` and `v` values as 32-bit floats. A decoded coordinate keeps about 7 significant digits, so it can differ from the sent value. For a coordinate from `0` to `1`, the difference is less than `1e-7`. This difference is much less than one pixel.

## Encode limits

`binaryCodec.encode` throws an `Error` when a message breaks a frame limit:

- `version` is not `1`.
- `clientId`, `session`, or an anchor `id` is longer than 65535 UTF-8 bytes.
- The event `type` is longer than 255 UTF-8 bytes.
- `cursor.anchors` is not an array.
- The cursor has more than 255 anchors.
- `sequence` is not a safe integer from 0 to `DEFAULT_MAX_SEQUENCE`.
- An anchor or viewport coordinate is not a finite number.
- `pointer.type` is not `mouse`, `pen`, or `touch`.
- `JSON.stringify` cannot serialize `context` or `user`.

The protocol limits on the [Security](/docs/get-started/guides/security) page are tighter than these frame limits. For example, the protocol allows 8 anchors and the frame allows 255. A message inside the protocol limits never reaches a frame limit.

`binaryCodec.decode` never throws. It returns `null` for malformed, truncated, or non-binary input.
