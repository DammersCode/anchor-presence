---
title: SSR and Strict Mode
description: How to create a client safely under server rendering and React Strict Mode.
---

Create the client inside the provider `factory`, or in an effect. Never create it at module scope in code that also runs on the server. This rule keeps a client safe under server rendering and React Strict Mode. No package accesses the DOM at module load time.

## Use the provider factory

`LiveCursorProvider` runs its `factory` once per mount, in a mount effect:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, LiveCursorProvider } from "@anchor-presence/react";

function App() {
  return (
    <LiveCursorProvider
      factory={() => {
        const transport = createWebSocketTransport({ path: "/?room=main" });
        return createPresenceClient({ transport });
      }}
    >
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

Until the factory has run, the provider renders its children with a `null` client, and every hook returns its server-safe value. Server renders never run the factory. Create the transport inside the factory, because `client.dispose()` calls `transport.disconnect()`.

## Why Strict Mode matters here

React Strict Mode, in development, mounts every component twice to surface effects that are not idempotent. If a `createPresenceClient` call sits at module scope, or directly inside a component body, it runs twice. Two clients then exist, or one transport's socket connects twice.

The provider creates the client in an effect with a cleanup. The first mount creates the client, and Strict Mode's cleanup disposes it. The second mount's effect creates a new client, so the page always holds one live client.

## Two supported SSR patterns

- Create the client only in browser-only code, for example inside the provider `factory` or a plain `useEffect`. Pass `client={null}` until it exists.
- Pass `client={null}` for the duration of server rendering, and swap in a real client after hydration.

Every hook has a server-safe snapshot: `useRemoteCursors` and `useCursorPresence` return `[]`, `useCursorStatus` returns `"disconnected"`, `useCursorClient` returns `null`, and `useCursorContext` returns `[undefined, setContext]`. `renderToString` works for a tree using every hook with `client={null}`:

```tsx
<LiveCursorProvider client={null}>
  <Dashboard />
</LiveCursorProvider>
```
