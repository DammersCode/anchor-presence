An `Interpolator` eases a remote cursor's position toward its latest target, instead of snapping on every message. `@anchor-presence/dom` creates one interpolator per remote client through an `InterpolatorFactory`.

## The Interpolator interface

```ts
interface Interpolator {
  target(x: number, y: number, timestampMs: number): void;
  shift(dx: number, dy: number): void;
  sample(timestampMs: number): { x: number; y: number; settled: boolean };
  reset?(): void;
}

type InterpolatorFactory = () => Interpolator;
```

`target` sets a new position to ease toward, starting from the current eased position. `shift` moves the current position and the target by a delta, without restarting the ease. A scroll or layout shift uses `shift` so an in-flight ease continues from the new place. `sample` returns the eased position at a timestamp, with `settled: true` once the position reaches its target. `reset` clears the ease state, so the next `target` call snaps instead of easing from a stale position.

## linearInterpolator

```ts
import { linearInterpolator } from "@anchor-presence/core";

const interpolator = linearInterpolator(80);
```

`linearInterpolator(durationMs?)` eases linearly over a fixed duration, `80` milliseconds by default. The first `target` call ever received snaps, since there is no previous position to ease from. Pass a factory that calls `linearInterpolator` with your chosen duration where an `InterpolatorFactory` is expected:

```ts
const factory = () => linearInterpolator(120);
```

## noneInterpolator

```ts
import { noneInterpolator } from "@anchor-presence/core";
```

`noneInterpolator` applies no easing. `sample` always returns the latest target, always `settled: true`. Use it when you render remote cursors at a high message rate and do not need smoothing between updates.
