title: Custom transport
description: Write a transport for BroadcastChannel or a managed real-time service.

Write your own transport when your app already has a byte channel, such as `BroadcastChannel`, or when you use a managed real-time service. A transport only moves bytes. It never validates or interprets them.

Already on Socket.IO or SignalR? Use the shipped [Socket.IO](/docs/examples/backends/socketio) or [SignalR](/docs/examples/backends/signalr) example instead of writing a transport.

## BroadcastChannel sketch

`BroadcastChannel` sends messages between browsing contexts (tabs, iframes, workers) on the same origin. It never crosses a network, so it fits demos and same-origin multi-tab apps, not real presence over the internet.

```ts
import type { ConnectionStatus, LiveCursorTransport } from "@anchor-presence/core";

function createBroadcastChannelTransport(channelName: string): LiveCursorTransport {
  const channel = new BroadcastChannel(channelName);
  const statusListeners = new Set<(status: ConnectionStatus) => void>();

  channel.onmessage = null; // set per subscriber below

  return {
    connect() {
      // BroadcastChannel has no handshake; it is open as soon as it is constructed
      for (const listener of statusListeners) listener("connected");
    },
    disconnect() {
      channel.close();
    },
    send(data) {
      channel.postMessage(data);
    },
    subscribe(listener) {
      const onMessage = (event: MessageEvent<Uint8Array>) => listener(event.data);
      channel.addEventListener("message", onMessage);
      return () => channel.removeEventListener("message", onMessage);
    },
    subscribeStatus(listener) {
      listener("connected");
      statusListeners.add(listener);
      return () => statusListeners.delete(listener);
    },
    getStatus() {
      return "connected";
    },
  };
}
```

`BroadcastChannel` delivers structured-cloned values, so it can carry a `Uint8Array` directly, with no base64 step.

## Managed real-time services

A managed service, such as a hosted pub/sub or a serverless WebSocket gateway, usually exposes its own SDK with a `send` method and a message event. Wrap that SDK the same way. Forward `send` calls to the SDK. Forward the SDK's message event to `subscribe` listeners. Map the SDK's own connection events to `ConnectionStatus`.

<Callout type="warn">
  If the SDK delivers text or JSON instead of bytes, encode and decode at the transport boundary so the codec
  still receives a `Uint8Array` from `send` and gives one to the SDK.
</Callout>

## Close reasons

A transport can report why a connection closed through the optional `subscribeClose` method. Keep a set of listeners, and call each one from the close handler of your socket:

```ts
import type { TransportClose } from "@anchor-presence/core";

const closeListeners = new Set<(close: TransportClose) => void>();

function subscribeClose(listener: (close: TransportClose) => void) {
  closeListeners.add(listener);
  return () => {
    closeListeners.delete(listener);
  };
}

function onSocketClose(event: CloseEvent, willReconnect: boolean) {
  const close: TransportClose = { code: event.code, reason: event.reason, willReconnect };
  for (const listener of closeListeners) listener(close);
}
```

Return `subscribeClose` on the transport object. Set `willReconnect` to `true` only when the transport schedules another attempt. `client.subscribeClose` then receives each close. See [Close reasons](/docs/core/transports#close-reasons).

## Testing a custom transport

Run your transport through the same message shapes `createInMemoryPair` produces: a connect, a send while connected, a send while disconnected, and a status change with no active subscriber. See [In-memory transport](/docs/core/in-memory-transport) for a transport that already satisfies the full contract, as a reference implementation.
