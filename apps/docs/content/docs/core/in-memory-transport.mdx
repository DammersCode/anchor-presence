`createInMemoryPair` returns two transports that are wired directly to each other in one process. Use it in unit tests, in server-rendered samples, and to try the provider and the hooks before a relay exists.

## Usage

Give one side of the pair to each client:

```ts
import { createInMemoryPair, createPresenceClient } from "@anchor-presence/core";

const { a, b } = createInMemoryPair();
const clientA = createPresenceClient({ transport: a, user: { name: "Alice" } });
const clientB = createPresenceClient({ transport: b, user: { name: "Bob" } });
```

A send from `a` reaches only the listeners of `b`. A send from `b` reaches only the listeners of `a`. Call `dispose()` on the pair to stop delivery and clear both sides.

## Delivery

By default, a send reaches the other side at once, inside the `send` call. To deliver in a microtask, pass `{ async: true }`:

```ts
const { a, b } = createInMemoryPair({ async: true });
```

## Test with more than two peers

Use `createInMemoryRoom` when a test needs three or more clients. Call `join()` once per client:

```ts
import { createInMemoryRoom, createPresenceClient } from "@anchor-presence/core";

const room = createInMemoryRoom();
const alice = createPresenceClient({ transport: room.join(), user: { name: "Alice" } });
const bob = createPresenceClient({ transport: room.join(), user: { name: "Bob" } });
const carol = createPresenceClient({ transport: room.join(), user: { name: "Carol" } });
```

A send reaches every other joined transport and never the sender. `join()` returns a connected transport. Call `disconnect()` on a transport to leave the room. A disconnected transport receives nothing, and its sends are dropped. Call `connect()` to join again. The room takes the same `{ async: true }` option as the pair.

## Limits

- Both sides must run in the same JavaScript realm, that is, one global environment such as one page or one worker. The pair cannot cross a process, tab, or iframe boundary.
- Each side starts `disconnected`. `connect()` sets it to `connected`, and `disconnect()` sets it to `disconnected`.
- A send reaches the other side also while the sending side is `disconnected`. The browser transports drop such a send. A test of offline behavior can pass with this pair and fail in the browser.
- The pair has no `subscribeClose` and no `bufferedBytes`.
