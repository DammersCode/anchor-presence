`@anchor-presence/core` exports every name below. These types describe the wire protocol that the client checks, stores, and sends.

## CursorPresence

`CursorPresence` is the wire format of one presence message.

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="CursorPresence" />

### Leave and event messages

A message with `leave: true` tells receivers that the client left. A message with an `event` field carries one [event](/docs/core/presence-client#events). Both messages have a `null` cursor. An event message carries no `context`, `user`, or `pointer`.

Both codecs carry the two fields:

- `jsonCodec` writes `leave` and `event` as JSON fields.
- `binaryCodec` writes a leave message with cursor tag `2`. It writes an event message with cursor tag `3`, followed by the event `type`. The event `data` uses the slot of `user`.

<Callout type="warn">
  If a relay checks messages, it must pass `leave` and `event` through. If a relay drops these fields, a
  client that left stays until the stale timeout. Each event then arrives as a message that clears the cursor
  of the sender.
</Callout>

## PresenceEvent

A `PresenceEvent` is a one-shot event that `client.sendEvent` sends.

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="PresenceEvent" />

`RemoteEvent` is a `PresenceEvent` with the `clientId` of the sender added. `client.subscribeEvents` gives a `RemoteEvent` to its listener.

## PeerChange

A `PeerChange` reports a peer (another client in the same room) that joined, left, or changed its `user` or `context`. `client.subscribePeers` gives a `PeerChange` to its listener. See [Peer changes](/docs/core/remote-presence#peer-changes).

## CursorPosition

A `CursorPosition` is the cursor position inside one presence message. It holds a fallback chain of anchors and an optional viewport fallback.

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="CursorPosition" />

## RemotePresence

A `RemotePresence` is a presence message that has no `sequence` field and has an `idle` field. `client.getRemotePresence()` returns an array of this type. `idle` is `true` when the presence did not change for `idleAfterMs`, even while heartbeats arrive. See [How it works](/docs/get-started/concepts/how-it-works) for how this differs from the raw snapshot.

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="RemotePresence" />

## PointerInfo and PointerType

`PointerInfo` holds optional pointer info that a presence message carries.

<AutoTypeTable path="../../packages/core/src/protocol.ts" name="PointerInfo" />

`PointerType` is `"mouse" | "pen" | "touch"`.

## ConnectionStatus

Import `ConnectionStatus` from `@anchor-presence/core`:

```ts
import type { ConnectionStatus } from "@anchor-presence/core";
```

`ConnectionStatus` is `"connecting" | "connected" | "reconnecting" | "disconnected"`. See [Transports](/docs/core/transports) for how a transport reports it.

## Protocol constants

Import the protocol constants from `@anchor-presence/core`:

```ts
import {
  DEFAULT_MAX_CLIENT_ID_LENGTH,
  DEFAULT_MAX_SESSION_LENGTH,
  DEFAULT_MAX_SEQUENCE,
  DEFAULT_MAX_ANCHORS,
  DEFAULT_MAX_ANCHOR_ID_LENGTH,
  DEFAULT_MAX_FIELD_BYTES,
  DEFAULT_MAX_FIELD_DEPTH,
  DEFAULT_MAX_MESSAGE_BYTES,
  MAX_EVENT_TYPE_LENGTH,
} from "@anchor-presence/core";
```

The `DEFAULT_` constants are the defaults of `ValidationLimits`. See [ValidationLimits](/docs/core/validation#validationlimits) for the field, the value, and the result of each limit.

`MAX_EVENT_TYPE_LENGTH` is `64`, the maximum length of an event `type`. `ValidationLimits` cannot change it.
