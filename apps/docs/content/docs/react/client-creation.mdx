title: Creating the client
description: Create a presence client with the provider factory, the client prop, or createPresenceClient.
---

Three paths create the client for a React app. Pick one path and use it everywhere.

## The provider factory (standard)

Pass `LiveCursorProvider` a `factory`. The provider runs it once per mount, in an effect, and disposes the client it created on unmount. It also runs the factory again each time `clientKey` changes. It runs the factory only in the browser, so server renders and React Strict Mode's double-invoke never create two clients.

This app creates the client in the factory:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, LiveCursorProvider } from "@anchor-presence/react";

function App() {
  return (
    <LiveCursorProvider
      factory={() => {
        const transport = createWebSocketTransport({ path: "/?room=main" });
        return createPresenceClient({ transport });
      }}
    >
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

The factory owns the transport: create it, then create the client. The client connects the transport by default.

<Callout type="warn">
  If you create the transport at module scope, it connects once for the whole page. Create the transport
  inside the factory function.
</Callout>

To connect to another room, change `clientKey`. The provider disposes the old client and creates a new one. See [Switch rooms](/docs/react/live-cursor-provider#switch-rooms).

## Bring your own client

Pass the `client` prop. The provider never disposes a client you pass. You own its lifecycle. This path fits an app that creates the client in its own setup code and shares it through props or a context.

This app passes a client that it created:

```tsx
const client = createPresenceClient({ transport: myTransport });

<LiveCursorProvider client={client}>
  <Dashboard />
</LiveCursorProvider>;
```

If you set both `factory` and `client`, `client` wins, the factory never runs, and `clientKey` has no effect. Pass `client={null}` to provide no client, for example during server rendering.

## Manual control

Create the client anywhere with `createPresenceClient` from `@anchor-presence/core`. The client connects the transport by default. To connect the transport yourself, pass `autoConnect: false` and call `transport.connect()`. To stop the client, call `client.dispose()`. `dispose` is final: create a fresh client instead of reusing a disposed one.
