title: Overview
description: What @anchor-presence/core does, and why it has no DOM and no framework.
---

`@anchor-presence/core` is the protocol layer. It checks and stores the presence of peers, publishes the local presence, and defines the interfaces that every transport and codec implements. A peer is another client in the same room.

`@anchor-presence/core` has zero runtime dependencies and needs no DOM. It runs in Node.js, Bun, workers, and browsers. Its only browser access is one read of `document`, with a check that it exists. The client uses it to send a pending publish when the page becomes visible again. See [How it works](/docs/get-started/concepts/how-it-works) for how it fits under `@anchor-presence/dom` and `@anchor-presence/react`.

## Framework- and DOM-free

`@anchor-presence/core` never imports a DOM library, React, or any transport or codec library. This split has two effects:

- A test or a server process can create a `PresenceClient` and exercise the protocol with no browser and no framework.
- A framework adapter, such as `@anchor-presence/react`, holds no protocol state of its own. It only subscribes to the client that `@anchor-presence/core` runs.

## What core owns

- The wire protocol types (`CursorPresence`, `AnchorPoint`, `RemotePresence`, and related types).
- `validatePresence`, which turns an untrusted decoded value into a `CursorPresence` or `null`.
- `RemotePresenceStore`, which holds the presence of each peer and removes stale peers.
- `createPresenceClient`, which runs publishing and heartbeats over a transport and a codec.
- The `LiveCursorTransport` and `CursorCodec` interfaces, plus `createInMemoryPair`, `jsonCodec`, and `binaryCodec`.
- The `Interpolator` interface, plus `linearInterpolator` and `noneInterpolator`.
