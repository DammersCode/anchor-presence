If your app already has a byte channel, write your own transport. Do the same for a managed real-time service. A transport only moves bytes. It never checks or reads them.

If your app uses Socket.IO or SignalR, use the [Socket.IO](/docs/examples/backends/socketio) or [SignalR](/docs/examples/backends/signalr) example. You do not need to write a transport.

## BroadcastChannel sketch

`BroadcastChannel` sends messages between browsing contexts (tabs, iframes, workers) on the same origin. It never crosses a network. As a result, it fits demos and multi-tab apps on one origin, not presence over the internet.

`@anchor-presence/dom` ships `createBroadcastChannelTransport` for this channel. This sketch shows the parts of a transport on a smaller version of it:

```ts
import type { ConnectionStatus, LiveCursorTransport } from "@anchor-presence/core";

function createBroadcastChannelTransport(channelName: string): LiveCursorTransport {
  const channel = new BroadcastChannel(channelName);
  const statusListeners = new Set<(status: ConnectionStatus) => void>();

  return {
    connect() {
      // a BroadcastChannel has no handshake and is open from construction
      for (const listener of statusListeners) listener("connected");
    },
    disconnect() {
      channel.close();
    },
    send(data) {
      channel.postMessage(data);
    },
    subscribe(listener) {
      const onMessage = (event: MessageEvent<Uint8Array>) => listener(event.data);
      channel.addEventListener("message", onMessage);
      return () => channel.removeEventListener("message", onMessage);
    },
    subscribeStatus(listener) {
      listener("connected");
      statusListeners.add(listener);
      return () => statusListeners.delete(listener);
    },
    getStatus() {
      return "connected";
    },
  };
}
```

`BroadcastChannel` delivers structured-cloned values. As a result, it can carry a `Uint8Array` directly, with no base64 step.

## Managed real-time services

A managed service is a hosted pub/sub or a serverless WebSocket gateway. Its SDK has a `send` method and a message event. Wrap that SDK in the same way:

- Forward `send` calls to the SDK.
- Forward the message event of the SDK to the `subscribe` listeners.
- Map the connection events of the SDK to `ConnectionStatus`.

<Callout type="warn">
  If the SDK delivers text or JSON instead of bytes, convert at the transport boundary. Each `subscribe`
  listener must receive a `Uint8Array`. Otherwise the codec cannot decode the messages.
</Callout>

## Close reasons

A transport can report why a connection closed through the optional `subscribeClose` method. Keep a set of listeners, and call each one from the close handler of your socket:

```ts
import type { TransportClose } from "@anchor-presence/core";

const closeListeners = new Set<(close: TransportClose) => void>();

function subscribeClose(listener: (close: TransportClose) => void) {
  closeListeners.add(listener);
  return () => {
    closeListeners.delete(listener);
  };
}

function onSocketClose(event: CloseEvent, willReconnect: boolean) {
  const close: TransportClose = { code: event.code, reason: event.reason, willReconnect };
  for (const listener of closeListeners) listener(close);
}
```

Return `subscribeClose` on the transport object. When the transport schedules another attempt, set `willReconnect` to `true`. Otherwise, set it to `false`. `client.subscribeClose` then receives each close. See [Close reasons](/docs/core/transports#close-reasons).

## Test a custom transport

Do a test of your transport with these cases:

- A connect.
- A send while the transport is connected.
- A send while the transport is disconnected.
- A status change with no active subscriber.

`createInMemoryPair` implements the required methods of the contract. It has no `subscribeClose` and no `bufferedBytes`. It also delivers a send while its side is disconnected. See [In-memory transport](/docs/core/in-memory-transport).
