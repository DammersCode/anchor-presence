An event is a one-shot message to every peer, for example a reaction or a ping. It has a `type` and an optional `data` value. `useRemoteEvents` calls a listener for each event that a peer sends. Use events for things that happen one time. For state that a late peer must also see, use the [local user or context](/docs/react/local-context).

## Usage

This component sends a reaction with `client.sendEvent` and shows the last reaction from a peer. It needs the `PresenceProvider` from `@anchor-presence/react`:

```tsx
import { useState } from "react";
import { usePresenceClient, useRemoteEvents } from "@anchor-presence/react";

function Reactions() {
  const client = usePresenceClient();
  const [lastReaction, setLastReaction] = useState<string | null>(null);

  useRemoteEvents((event) => {
    if (event.type === "reaction" && typeof event.data === "string") {
      setLastReaction(`${event.clientId}: ${event.data}`);
    }
  });

  return (
    <div>
      <button type="button" onClick={() => client?.sendEvent("reaction", "wave")}>
        Wave
      </button>
      {lastReaction !== null && <p role="status">{lastReaction}</p>}
    </div>
  );
}
```

## Check the data

`event.data` has the type `unknown`, because a peer can send any value. Check its type before you use it. To check every event in one place, pass `parseEvent` to `createPresenceClient`. If `parseEvent` returns `undefined` or throws, the client drops the event. See [Events](/docs/core/events).

## Send typed events

The `useSendEvent` that you import from `@anchor-presence/react` sends any event `type`, with `data` of the type `unknown`. For a function that sends only the events of one event map, call `createPresenceHooks` with the event map as its third type argument and export `useSendEvent` from the result. See [Typed hooks](/docs/react/typed-hooks). A misspelled `type` or a `data` value of the wrong type then does not compile. Without a client, the function sends nothing and returns `false`.

This button sends a typed reaction. The `PresenceProvider` above it must come from `./presence`, the module of [Typed hooks](/docs/react/typed-hooks#usage):

```tsx
import { useSendEvent } from "./presence";

function WaveButton() {
  const sendEvent = useSendEvent();
  return (
    <button type="button" onClick={() => sendEvent("reaction", { emoji: "wave" })}>
      Wave
    </button>
  );
}
```

The typed `useRemoteEvents` of the same result types the events that you receive. See [typed events](/docs/react/typed-hooks#typed-events).

## Behavior

- The client never stores an event and never sends it again. A peer that is not connected at that time never receives it.
- A client never receives its own events.
- The listener receives a `RemoteEvent`: the `type`, the `data`, and the `clientId` of the sender.
- `client.sendEvent(type, data?)` returns `false` when it sends nothing, for example while the client is not connected. See [Events](/docs/core/events) for every case.
- The receiver limits the events of each sender and of all senders together. It drops the events above a limit. See [Event rate limit](/docs/core/events#event-rate-limit).
- The hook subscribes one time per client. An inline listener does not subscribe again on each render, and the hook always calls the listener of the last render. The hook returns nothing, so it adds no rerender of its own.
