Your app runs on ASP.NET Core, and you want presence without a second WebSocket server. `examples/signalr` relays presence through a SignalR hub. The hub forwards each message to the peers of the sender and never parses the payload. The tests of this example use `@microsoft/signalr` 10.0.11 and .NET 10 (`net10.0`).

## Install

Install the packages. `@anchor-presence/react` and `@dammers/use-signalr-react` are needed only for the shared connection below:

<InstallCommand packages="@anchor-presence/core @anchor-presence/react @dammers/use-signalr-react @microsoft/signalr" />

## Run it

Start the hub from the server folder:

```sh
cd examples/signalr/server
dotnet run
```

The hub listens on `http://localhost:5000`. To use a different URL, set `ASPNETCORE_URLS`.

## Share a use-signalr connection

If your app uses [`use-signalr`](https://www.npmjs.com/package/@dammers/use-signalr-react) for its other hubs, add the presence hub to its contract. Then presence shares the connection, the authentication and the reconnect policy of the app. This sample adds the presence hub to the contract:

```ts
// signalr.ts
import { createSignalRClient, event, method } from "@dammers/use-signalr-react";

export const { SignalRProvider, useSignalR } = createSignalRClient({
  hubs: {
    "/hubs/presence": {
      events: { PresenceReceived: event<[payload: string]>() },
      methods: { OnPresence: method<[payload: string]>() },
    },
    // your app's other hubs
  },
});
```

`useSignalR` gives access to the raw `HubConnection` through `getConnection`. This component creates the presence client on that connection, in the `factory` of a `PresenceProvider`:

```tsx
import type { ReactNode } from "react";
import { createPresenceClient } from "@anchor-presence/core";
import { PresenceProvider } from "@anchor-presence/react";
import { createSignalRTransport } from "./transport";
import { useSignalR } from "./signalr";

function AppPresenceProvider({ children }: { children: ReactNode }) {
  const { getConnection } = useSignalR();
  const connection = getConnection("/hubs/presence");
  if (connection === null) return children;
  return (
    <PresenceProvider
      clientKey={connection}
      factory={() => {
        // use-signalr owns the connection, so disposing the client must not stop it
        const transport = createSignalRTransport(connection, { stopConnection: false });
        return createPresenceClient({ transport });
      }}
    >
      {children}
    </PresenceProvider>
  );
}
```

`getConnection` returns `null` until `use-signalr` opens the hub. Until then, the component shows its children without presence. When the hub opens, the children mount again inside the provider, so their local state resets one time.

The provider runs `factory` once per mount and once more for each new connection. It disposes the client on unmount. The option `stopConnection: false` keeps the shared connection open after the dispose. The transport still removes its `Refused` and `PresenceReceived` handlers. After `disconnect()`, a transport stays `disconnected` when the shared connection reconnects.

If the shared connection is `Connecting` or `Disconnecting`, `connect()` waits and reports `connecting`. It polls every 50 ms for 10 seconds, then every second with no time limit, until the state is final. `disconnect()` cancels the wait. A `connect()` right after `disconnect()` waits for the stop to finish, then starts the hub. See [Create the client](/docs/react/client-creation) for the rules of `factory`.

<Callout type="warn">
  If the provider remounts on a shared connection, the `onclose`, `onreconnecting`, and `onreconnected`
  callbacks of the old transport stay on that connection, because SignalR has no API to remove them.
</Callout>

## Close reasons

The hub refuses a connection with an invalid room name. It first sends a `Refused` message with the code `4007` and the reason `invalid room`. Then it aborts the connection. The transport reports the code through `subscribeClose`:

```ts
client.subscribeClose((close) => {
  if (close.code === 4007) console.warn("The room name is not valid.");
});
```

The hub sends no other close code. An origin outside the allowlist gets HTTP `403` before the hub starts, so the transport reports no code for it. `willReconnect` is `true` while `withAutomaticReconnect` retries, and `false` after the connection closes.

## Behavior notes

The hub reads `RELAY_ALLOWED_ORIGINS` and `ASPNETCORE_URLS` from the environment. Every other limit is in `Program.cs`.

### What the relay does

| Topic            | Behavior                                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Room             | Reads `room` from the query of the hub URL. A missing value is `main`. An invalid name gets `Refused` with code `4007`. |
| Upgrade path     | The hub route, `/hubs/presence`.                                                                                        |
| Fan-out          | `Clients.OthersInGroup(room)` sends to every other connection in the SignalR group of the room.                         |
| Payload          | Forwards each payload unchanged. The hub never parses it.                                                               |
| Dead connections | The SignalR keep-alive closes them, with the ASP.NET Core defaults.                                                     |
| Room cleanup     | SignalR removes a connection from its groups when it disconnects.                                                       |

`connection.send` and `connection.on` call a hub method by its name and do not wait for an answer. The hub sends no acknowledgment, and the `send` contract of the transport interface needs none.

### Limits

| Limit               | Setting (default)                    | Above the limit                   |
| ------------------- | ------------------------------------ | --------------------------------- |
| Message size        | `MaximumReceiveMessageSize` (32 KiB) | SignalR closes the connection.    |
| Hard frame size     | The same setting                     | SignalR closes the connection.    |
| Message rate        | None                                 | The hub forwards every message.   |
| Sockets in one room | None                                 | The hub accepts every connection. |
| Sockets in total    | None                                 | The hub accepts every connection. |
| Slow receiver       | None in the hub                      | SignalR buffers the messages.     |

The size cap applies to the base64 text of a message, so the real payload cap is about 24 KiB.

### Auth

| Check            | Setting                                                                            | On refusal                                               |
| ---------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Origin           | `RELAY_ALLOWED_ORIGINS`, comma-separated. Default `http://localhost:5173`.         | HTTP `403`. A request without an `Origin` header passes. |
| Room token       | None. The hub reads no [room token](/docs/dom/websocket-transport#room-token).     | Not applicable.                                          |
| Auth hook        | None. Use ASP.NET Core authentication, for example `[Authorize]` on `PresenceHub`. | Your authentication refuses the request.                 |
| Identity binding | None. A client can claim any `clientId`.                                           | Not applicable.                                          |
| Check order      | Origin, then your authentication, then room name.                                  | The hub never starts for a refused origin.               |

See [Security](/docs/get-started/guides/security) for the risks of a relay without identity binding.

### Tests

`examples/signalr/signalr-hub.test.ts` starts the real ASP.NET Core hub and runs two clients through it. It checks the relay in one room, the isolation between rooms, the origin check, and the `4007` refusal. If `dotnet` is not on `PATH`, the test skips. `examples/signalr/signalr.test.ts` covers the transport states with a fake hub connection: disconnect, reconnect, and the wait for a connection that is still starting.

<Callout type="warn">
  If you expose the hub publicly, add a rate limit, for example [ASP.NET Core rate
  limiting](https://learn.microsoft.com/aspnet/core/performance/rate-limit). The hub has no rate limit and no
  connection caps, so one client can flood a room.
</Callout>
