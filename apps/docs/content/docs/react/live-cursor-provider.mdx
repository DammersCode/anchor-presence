---
title: LiveCursorProvider
description: Share a presence client and its DOM binding with the tree below.
---

`LiveCursorProvider` shares a `PresenceClient` and a `DomBinding` with every hook and component below it, through React context. Every app that uses `@anchor-presence/react` wraps its cursor-aware tree in one provider.

## Props

The samples on this page use these imports:

```tsx
import { createPresenceClient, linearInterpolator, noneInterpolator } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, LiveCursorProvider } from "@anchor-presence/react";
import type { LiveCursorProviderProps } from "@anchor-presence/react";
```

The provider takes these props:

| Prop             | Type                                      | Default                    |
| ---------------- | ----------------------------------------- | -------------------------- |
| `factory`        | `() => PresenceClient<TContext, TUser>`   | none                       |
| `client`         | `PresenceClient<TContext, TUser> \| null` | none (wins over `factory`) |
| `binding`        | `DomBinding`                              | the provider creates one   |
| `bindingOptions` | `DomBindingOptions`                       | none                       |
| `clientKey`      | `unknown`                                 | none                       |
| `bindingKey`     | `unknown`                                 | none                       |
| `children`       | `ReactNode`                               | none                       |

Create the client through `factory`, or pass a client you own:

```tsx
<LiveCursorProvider
  factory={() => {
    const transport = createWebSocketTransport({ path: "/?room=main" });
    return createPresenceClient({ transport });
  }}
>
  <Dashboard />
</LiveCursorProvider>
```

## Client ownership

The provider disposes a client that `factory` created. It never disposes a `client` that you pass. For when the factory runs and which prop wins, read [Creating the client](/docs/react/client-creation).

## The binding the provider creates

When you omit `binding`, the provider creates a `DomBinding` for the client with `createDomBinding(client, bindingOptions)`. It disposes that binding when the client changes, when `bindingKey` changes, or when the provider unmounts. If you created a binding yourself, for example to share one binding across two providers, pass it as `binding`. The provider then creates no binding and never disposes yours.

`bindingOptions` configures the binding the provider creates. The provider reads `bindingOptions` only when it creates the binding. A later change to the `bindingOptions` object does not recreate the binding.

## Rebuild the binding

To apply a new `bindingOptions` value, change `bindingKey`. The provider then disposes the binding and creates a new one with the current `bindingOptions`. The client stays connected. A peer is another client in the same room. Peers keep the local cursor. This example switches the interpolator:

```tsx
function Workspace({ smooth }: { smooth: boolean }) {
  return (
    <LiveCursorProvider
      factory={() => createPresenceClient({ transport: createWebSocketTransport({ path: "/?room=main" }) })}
      bindingKey={smooth}
      bindingOptions={{
        resolution: { interpolatorFactory: smooth ? linearInterpolator : noneInterpolator },
      }}
    >
      <Dashboard />
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

## Switch rooms

To replace the client that `factory` made, change `clientKey`. The provider then disposes the old client and runs the current `factory` again. The tree below the provider does not remount. This example joins the room that the `room` prop names:

```tsx
function Room({ room }: { room: string }) {
  return (
    <LiveCursorProvider
      clientKey={room}
      factory={() => {
        const transport = createWebSocketTransport({ path: `/?room=${encodeURIComponent(room)}` });
        return createPresenceClient({ transport });
      }}
    >
      <Dashboard />
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

<Callout type="warn">
  If you pass `client`, the provider ignores `clientKey`. To switch the room of a client you own, dispose it
  and pass a new client.
</Callout>

## client={null}

Pass `client={null}` for server rendering or the gap before hydration. The provider renders its children normally and the factory does not run. Every hook returns its server-safe value: see [SSR and Strict Mode](/docs/react/ssr-and-strict-mode).
