`createWebSocketTransport` builds a `LiveCursorTransport` over the native browser `WebSocket`. It works with any relay that follows the [relay contract](/docs/examples/backends/relay-contract). Use it to connect clients on different machines. For tabs of one origin with no server, use the [BroadcastChannel transport](/docs/dom/broadcast-channel-transport).

## Basic use

This sample connects a client to one room of a relay:

```ts
import { createWebSocketTransport } from "@anchor-presence/dom";
import { createPresenceClient } from "@anchor-presence/core";

const transport = createWebSocketTransport({ url: "wss://relay.example.com/?room=room-42" });
const client = createPresenceClient({ transport });
```

The returned transport always has `connect()`, `disconnect()`, `subscribeStatus`, `getStatus`, `subscribeClose`, and `bufferedBytes`. See [Transports](/docs/core/transports) for the contract.

The transport uses `globalThis.WebSocket` by default. If there is no global `WebSocket`, for example on an older Node.js, pass `WebSocketCtor`.

<Callout type="warn">
  If there is no global `WebSocket` and no `WebSocketCtor`, the transport never opens a socket. Its status
  changes to `disconnected`, and it reports no close. In development mode, it warns one time.
</Callout>

## Connection status

The transport moves through these statuses:

  chart={`stateDiagram-v2

  connecting --> reconnecting: close, retry allowed

  reconnecting --> disconnected: close, no retry
  connecting --> disconnected: close, no retry`}

A `disconnect()` call changes any status to `disconnected`. With no `WebSocket`, the status changes from `connecting` to `disconnected`, as the warning above describes.

## The default URL

When you omit `url`, the transport builds the URL from these options:

| Option | Default                    | Rule                                                                                                                  |
| ------ | -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `url`  | none                       | The full URL. If you pass `url`, the transport ignores `host`, `port`, and `path`, and warns in development mode.     |
| `host` | `window.location.hostname` | The host of the default URL.                                                                                          |
| `port` | `8787`                     | The port of the default URL. The transport adds the port to the URL on `https:` pages too.                            |
| `path` | `/`                        | The path and the query, for example `/?room=main`. It must start with `/` or `?`. Another value throws a `TypeError`. |

The protocol is `wss:` when the page loads over `https:`, and `ws:` otherwise. Behind a proxy on port 443, pass `port: 443`, or pass `url`.

The default URL needs `window`. If you omit `url` and `window` does not exist, for example on a server, `createWebSocketTransport` throws a `TypeError`. Outside the browser, pass `url`.

## Room token

A room token is a secret that the relay checks before it accepts a connection. On the reference relay, one room token opens every room. The transport sends it as the `token` query parameter. See [Security](/docs/get-started/guides/security#room-token) for the relay side.

Set the `token` option to send a room token. The transport URL-encodes the value and adds `token=<value>` to the URL. If the URL already has a query string, the transport joins the parameter with `&`.

If the room token expires, pass a function. The transport calls it before every connection attempt, including each reconnect. The function can be async. The transport waits for a returned promise:

```ts
const transport = createWebSocketTransport({
  url: "wss://relay.example.com/?room=main",
  token: async () => (await fetch("/api/room-token")).text(),
});
```

If the function throws or rejects, the transport reports a close with no code and the reason `connection attempt failed`. Then, if `reconnect` is on, it schedules the next attempt.

## Reconnect and backoff

`reconnect` defaults to `true`. When a connection drops and your own `disconnect()` call did not cause it, the transport schedules a reconnect with exponential backoff:

- The first delay is `baseBackoffMs` (default `500`). The delay doubles on each attempt, up to `maxBackoffMs` (default `8000`).
- The transport waits a random time between 50% and 100% of that delay. This is the random wait. As a result, many clients that lose the connection at the same time do not all retry at the same moment.
- The backoff resets only after a connection stays open for `stableAfterMs` (default `5000`). A relay that accepts a connection and then closes it therefore sees growing delays, not a retry loop.
- A close with code `1008` (policy), `4004` (origin), `4006` (room token), or `4007` (room name) stops the reconnect, and the status becomes `disconnected`.
- `random` replaces the source of the random wait. It defaults to `Math.random`. A test can pass a fixed function to get a fixed delay.

While a connection is connecting or open, a second `connect()` call has no effect. It does not open a second socket.

<Callout type="warn">
  If you call `connect()` after `disconnect()`, the transport logs a development-mode warning and does
  nothing. To reconnect, for example with a new room token, create a new transport and a new client.
</Callout>

## Stop reconnecting

`shouldReconnect` decides after each close whether the transport tries again. It receives the close `code` and `reason`, and returns `false` to stop. This rule also stops on `4001`, the code that the reference relay and the example relays send for a full room:

```ts
const NO_RETRY_CODES = [1008, 4001, 4004, 4006, 4007];

const transport = createWebSocketTransport({
  url: "wss://relay.example.com/?room=main",
  shouldReconnect: (close) => close.code === undefined || !NO_RETRY_CODES.includes(close.code),
});
```

<Callout type="warn">
  If you pass `shouldReconnect`, it replaces the default rule. Include `1008`, `4004`, `4006`, and `4007` in
  your rule, or the transport retries a connection that the relay rejects.
</Callout>

When `reconnect` is `false`, the transport never calls `shouldReconnect`.

## Close reasons

`transport.subscribeClose(listener)` runs the listener each time a connection closes. The listener receives a `TransportClose` object with the close `code`, the `reason`, and `willReconnect`. This listener shows the close when the transport stops:

```ts
transport.subscribeClose?.((close) => {
  if (!close.willReconnect) {
    console.warn(`Relay closed the connection: ${close.code ?? "no code"} ${close.reason ?? ""}`);
  }
});
```

The `?.` is necessary because the `WebSocketTransport` type marks `subscribeClose` as optional, although the transport always has it.

The transport does not replay a past close to a new listener. A close after your own `disconnect()` call does not run the listener. In development mode, the transport also logs each close with a code of `4000` or higher. `client.subscribeClose` receives the same closes.

## Send and receive

`send()` drops the message without a warning when the socket is not open. It does not queue it, because presence is lossy by design. The transport delivers only binary frames to its listeners. It drops a text frame.

`transport.bufferedBytes()` returns the `bufferedAmount` of the socket, or `0` when no socket is open.
