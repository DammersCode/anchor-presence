Server rendering (SSR) and React Strict Mode both break a client that you create in the wrong place. If your app renders on the server, or runs in development with `<StrictMode>`, read this page. The rule is short: create the client in the provider `factory` or in an effect. Never create it at module scope or in a component body.

## Usage

This tree renders on the server with `client={null}`. Every hook in it returns its server-safe value:

```tsx
<LiveCursorProvider client={null}>
  <Dashboard />
</LiveCursorProvider>
```

In the browser, use one of the two paths from [Create the client](/docs/react/client-creation). Both are safe on the server and under Strict Mode.

## Where to create the client

| Place                    | On the server                          | Under Strict Mode                         |
| ------------------------ | -------------------------------------- | ----------------------------------------- |
| Provider `factory`       | does not run                           | one live client                           |
| `useEffect` with cleanup | does not run                           | one live client                           |
| Component body           | runs on each render                    | a new client on each render, none stopped |
| Module scope             | runs one time, every request shares it | one client for the whole page             |

No package touches the DOM when its module loads, so an import alone is safe on the server.

## Strict Mode

In development, Strict Mode renders each component two times. It also mounts, unmounts, and mounts each component again. This finds effects that break when they run two times.

The provider creates the client in an effect with a cleanup. The first mount creates a client, and the Strict Mode cleanup disposes it. The second mount creates a new client. As a result, the page holds one live client.

## Server-safe values

On the server, and before the provider has a client, each hook returns a fixed value:

| Hook                       | Value                                                  |
| -------------------------- | ------------------------------------------------------ |
| `useRemoteCursors`         | `[]`                                                   |
| `useRemoteCursorsSelector` | the result of `select([])`                             |
| `useRemoteUsers`           | `[]`                                                   |
| `useRemotePresence`        | `[]`                                                   |
| `useCursorStatus`          | `"disconnected"`                                       |
| `useLocalContext`          | `[undefined, setContext]`, and the setter does nothing |
| `useLocalUser`             | `[undefined, setUser]`, and the setter does nothing    |
| `useCursorClient`          | the `client` prop, or `null` without it                |
| `useCursorBinding`         | the `binding` prop, or `null` without it               |
| `usePeerChanges`           | calls nothing                                          |
| `useCursorEvents`          | calls nothing                                          |

`CursorLayer` renders nothing on the server. A test renders a tree that uses every hook with `renderToString` and `client={null}`.

## React Server Components

The package entry starts with `"use client"`, so its exports are Client Components. A Server Component cannot pass a function, such as `factory`, to a Client Component. For this reason, put the provider in a module that starts with `"use client"`. See [Frameworks](/docs/get-started/frameworks) for the Next.js App Router and other frameworks.
