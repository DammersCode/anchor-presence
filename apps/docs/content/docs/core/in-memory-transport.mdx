---
title: In-memory transport
description: createInMemoryPair, two transports wired to each other for tests and prototypes.
---

`createInMemoryPair` returns two transports wired directly to each other in one process. Use it for tests and for a quick local check, before a relay exists.

## Usage

Give one side of the pair to each client:

```ts
import { createInMemoryPair, createPresenceClient } from "@anchor-presence/core";

const { a, b } = createInMemoryPair();
const clientA = createPresenceClient({ transport: a, user: { name: "Alice" } });
const clientB = createPresenceClient({ transport: b, user: { name: "Bob" } });
```

A send from `a` reaches only the listeners of `b`. A send from `b` reaches only the listeners of `a`. Call `dispose()` on the pair to stop delivery and clear both sides.

## When to use it

Use `createInMemoryPair` in unit tests and in server-rendered samples. It also lets you check the provider and the hooks before a relay exists. It cannot cross a process, tab, or iframe boundary. Both sides must run in the same JavaScript realm.

To deliver messages in a microtask instead of at once, pass `{ async: true }`:

```ts
const { a, b } = createInMemoryPair({ async: true });
```

See [Backends](/docs/examples/backends) for transports that do cross a process boundary.
