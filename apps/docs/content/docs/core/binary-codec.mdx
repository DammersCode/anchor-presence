title: Binary codec
description: The binaryCodec wire layout, coordinate precision, and encode limits.
---

`binaryCodec` is a compact fixed-layout binary codec shipped by `@anchor-presence/core`. Pass it as the `codec` option to send smaller messages than `jsonCodec`.

```ts
import { binaryCodec } from "@anchor-presence/core";

const client = createPresenceClient({ transport: myTransport, codec: binaryCodec });
```

## Wire layout

The layout is little-endian:

- header: magic `0x41`, format `2`, protocol version `1`
- `clientId`: `u16` byte length, then UTF-8 bytes
- `session`: `u16` byte length, then UTF-8 bytes
- `sequence`: `u32`
- cursor tag: `0` for `null`, `1` for a cursor
- anchor count: `u8`
- each anchor: `u16` id length, then UTF-8 id, `f32` `u`, `f32` `v`
- viewport tag: `0` absent, `1` present, then `f32` `u`, `f32` `v`
- pointer tag: absent, present without type, `mouse`, `pen`, or `touch`
- `context` and `user`: tag `0` absent, `1` explicit `null`, or `2` a JSON payload with a `u32` byte length

Opaque `context` and `user` values stay JSON payloads inside the binary frame. The hot cursor fields use the compact fixed layout, which is why `binaryCodec` is smaller than `jsonCodec` for a typical multi-anchor message.

## Coordinate precision

`binaryCodec` stores the anchor and viewport `u` and `v` values as 32-bit floats. A decoded coordinate keeps about 7 significant digits, so it can differ slightly from the sent value. For a coordinate from `0` to `1`, the difference is less than `1e-7`, far below one pixel.

## Encode limits

`binaryCodec.encode` throws an `Error` when a message breaks a frame limit:

- `version` is not `1`.
- `clientId`, `session`, or an anchor `id` is longer than 65535 UTF-8 bytes.
- The cursor has more than 255 anchors.
- `sequence` is not a safe integer from 0 to `DEFAULT_MAX_SEQUENCE`.
- An anchor or viewport coordinate is not a finite number.
- `pointer.type` is not `mouse`, `pen`, or `touch`.
- `JSON.stringify` cannot serialize `context` or `user`.

The protocol limits on the [Security](/docs/get-started/guides/security) page are tighter than these frame limits: the anchor count limit alone keeps every real message far below the 255-anchor frame limit. A message inside the protocol limits never reaches a frame limit.

`binaryCodec.decode` never throws. It returns `null` for malformed, truncated, or non-binary input.
