---
title: usePresenceClient
description: Create a presence client once and reuse it across renders and Strict Mode remounts.
---

`usePresenceClient` creates a `PresenceClient` and keeps the same instance across renders, remounts, and React Strict Mode's double-invoke. Use it instead of creating a client directly in a component body or at module scope.

## Basic use

Pass a `factory` that builds the transport, connects it, then builds the client:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { usePresenceClient } from "@anchor-presence/react";

function App() {
  const client = usePresenceClient({
    factory: () => {
      const transport = createWebSocketTransport({ path: "/?room=main" });
      transport.connect();
      return createPresenceClient({ transport });
    },
  });
  // client is null until the mount effect runs
}
```

The factory owns the transport. Create the transport, call `transport.connect()`, then create the client with `createPresenceClient({ transport })`. No part of the library connects a transport for you.

## Behavior

The hook runs `factory` once per `key`, inside a mount effect, and stores the result in a module-level registry keyed by `key`. The hook returns:

- `null`, on the first render and during server rendering, because the factory has not run yet.
- The same client instance on every later render, for the same `key`.

A `key` option identifies a client for multi-client setups, such as a second presence room. Two calls with the same `key` resolve to the same client. The hook uses a default key when you omit `key`.

The hook never calls `transport.connect()` itself and never disposes the client on unmount. A client survives route changes and component remounts until you call `client.dispose()`, which also calls `transport.disconnect()` and removes the `key` entry. The next render after `dispose()` creates a new client.

<Callout type="warn">
  If a factory creates a transport at module scope instead of inside the factory function, the transport
  connects once for the whole page. A second `usePresenceClient` call with the same `key` then creates no
  second connection.
</Callout>
