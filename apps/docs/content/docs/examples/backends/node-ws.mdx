You want a relay that runs on plain Node, not Bun, with a well-known WebSocket library. This example uses [`ws`](https://github.com/websockets/ws) over `node:http`, with each room kept as a plain `Set<WebSocket>`.

## Install

```sh
bun add @anchor-presence/core @anchor-presence/dom ws
bun add -D @types/ws
```

## Client

The client needs no custom transport. It connects with the native `createWebSocketTransport`:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";

const transport = createWebSocketTransport({ port: 8789, path: "/?room=main" });
const client = createPresenceClient({ transport });
transport.connect();
```

## Run it

The entry file calls the factory once and logs the URL:

<CodeFromSource repo="examples/node-ws/relay.ts" lang="ts" />

Start the entry file with Bun, or with a TypeScript runner on Node:

```sh
bun relay.ts
# On Node:
npx tsx relay.ts
```

The relay listens on `http://localhost:8789`. To use a different port, give the port as the first argument.

## Production notes

- **Room name validation.** `parseRoom` caps room names at 256 characters and restricts them to `[A-Za-z0-9_-]`. A missing name is `main`. An invalid name closes the socket with code `4007`.
- **Max payload size.** `ws`'s own `maxPayload` is set well above the app limit, as a hard backstop. The real check that drops an oversized message instead of crashing runs in the message handler against `MAX_MESSAGE_BYTES` (default 32 KiB).
- **Per-connection rate limit.** A token bucket limits inbound messages per socket (`RATE_CAPACITY`, `RATE_REFILL_PER_SECOND`).
- **Origin allowlist.** `RELAY_ALLOWED_ORIGINS` is a comma-separated list of allowed origins. A rejected upgrade gets its raw socket destroyed before the WebSocket handshake completes.
- **Auth hook placeholder.** Pass an `authCheck` function, or set `RELAY_AUTH_TOKEN` for a plain shared-token check.
- **Room cleanup.** The relay drops a room's entry once its last socket closes.
- **Connection caps.** `RELAY_MAX_ROOM_SOCKETS` (default 128) limits one room. `RELAY_MAX_TOTAL_SOCKETS` (default 10,000) limits the process. Above either cap, the relay destroys the upgrade request before the WebSocket handshake completes.
- **Dead connections.** The relay sends a ping to each socket at an interval of half `RELAY_IDLE_TIMEOUT_SECONDS` (default 60, so every 30 seconds). It terminates a socket that did not answer the previous ping.
- **Backpressure on slow consumers.** `ws` exposes `bufferedAmount` per socket. The relay skips sends above a soft watermark and closes the connection above a hard one.

Set `RELAY_ALLOWED_ORIGINS` and `RELAY_AUTH_TOKEN` before you expose this relay past local development. Put a TLS-terminating proxy in front of it.
