An agent skill is a folder of instructions, `SKILL.md` plus reference files, that a coding agent reads before it does a task. It gives the agent the steps, the rules, and the vocabulary for the task. Without a skill, a human maintainer must explain these by hand. Anchor Presence ships two.

## The two skills

<Cards>
  <Card icon={<Plug />} title="Integration" href="/docs/skills/integration">
    Use this when you add cursors to an app, or fix a broken integration. It sets up the transport, the
    client, and the anchors. On request, it also adds a presence list.
  </Card>
  <Card icon={<ScanSearch />} title="Layout audit" href="/docs/skills/layout-audit">
    Use this when you ship a responsive or collapsible layout. It scores a running app for cursor-jump risk
    and proposes fixes.
  </Card>
</Cards>

## Install

Install both skills:

```sh
npx skills add DammersCode/anchor-presence
```

Install only the layout audit skill:

```sh
npx skills add DammersCode/anchor-presence --skill anchor-presence-audit
```

`skills add` accepts any GitHub repository. `--skill <name>` limits the install to one skill in that repository. Without `--skill`, the command installs every skill that the repository ships.

## How the docs serve agents

Every page on this site is also plain Markdown, for an agent that reads URLs directly instead of using a skill:

- [`/llms.txt`](/llms.txt): an index of every doc page, with a link to its Markdown version.
- [`/llms-full.txt`](/llms-full.txt): every page concatenated into one document, for an agent with a large context window and no crawler.
- `/docs/<page>.md`: any single page's Markdown, for example [`/docs/get-started/quick-start.md`](/docs/get-started/quick-start.md).

Every doc page also has a **Copy Markdown** button at the top, plus **Open in ChatGPT** and **Open in Claude** actions. With these actions, a person who reads a page in a browser can give it to a chat model in one click.

If the agent runs inside this repository, or in a project that depends on it, use a skill. A skill is denser than the docs. It includes steps that the reference docs spread across several pages. If the agent works from a URL without repository access, use `llms.txt`. If the agent needs the full API reference next to the integration steps, also use `llms.txt`.
