An anchor inside a scrollable panel can have a real size and position while the panel clips the resolved point out of view. The resolver detects this case and reports it in `pointVisible`. `pointVisible` is separate from the `show`/`hide` decision of the visibility policy. Read it in a policy to hide a cursor that the user cannot see.

## Use pointVisible

`pointVisible` is a field of the resolution that a `VisibilityPolicy` receives, and of every `ResolvedCursor`. The default visibility policy ignores it. This policy hides a clipped cursor:

```ts
import type { VisibilityPolicy } from "@anchor-presence/dom";

const clippedPointPolicy: VisibilityPolicy = ({ resolution }) =>
  !resolution.pointVisible || resolution.tier === "hidden" ? "hide" : "show";
```

To skip the clip check for one anchor, for example a portal overlay, write a policy that skips the `pointVisible` test for the ID of that anchor.

## How the check works

For an `anchor` tier resolution, the resolver walks the DOM ancestors of the winning anchor, up to the document element. It looks for an ancestor whose computed `overflow`, `overflow-x`, or `overflow-y` is not `visible`. Each such ancestor clips the visible rectangle of the anchor to its own client area, without borders and scrollbars. The clip is the intersection of the two rectangles.

The resolver sets `pointVisible` to `false` when the resolved `x`/`y` position falls outside the clipped rectangle. `pointVisible` is always `true` for the `viewport` tier, and always `false` for the `hidden` tier.

## Limits of the check

The check is a simple ancestor walk. It has these limits:

- It does not compute CSS containing blocks. An anchor with `position: absolute` or `position: fixed` can visually escape a clipping ancestor. The walk does not read `position`, so it still treats that anchor as clipped.
- It stops below the document element. A point that the window scroll moves out of view keeps `pointVisible: true`.
- It does not detect an overlay that covers the point. A cursor can report `pointVisible: true` while a modal or a dropdown covers that pixel.

## Hit test for overlays

If an overlay can cover the resolved point, pass `resolution: { hitTest: true }`. The resolver then checks the point with `document.elementFromPoint`, and it also looks into open shadow roots. The point is visible when the element at the point is the anchor or is inside it.

The hit test has these rules:

- It runs only when the ancestor walk reports a visible point. It can hide a covered cursor, but it cannot show an anchor that the walk treats as clipped.
- It treats a point outside the window as visible.
- It adds at least one `elementFromPoint` call on each frame for each `anchor` tier cursor that passes the walk. Each open shadow root at the point adds one more call.

## Browser coverage

The browser tests of the clip check run in Chromium only, in CI and locally. Unit tests in jsdom cover the hit test, and no browser test covers it.
