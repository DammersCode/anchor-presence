`createWebSocketTransport` builds a `LiveCursorTransport` over the native browser `WebSocket`. It is the one transport `@anchor-presence/dom` ships, built for the bundled relay or a compatible one.

## Basic use

```ts
import { createWebSocketTransport } from "@anchor-presence/dom";
import { createPresenceClient } from "@anchor-presence/core";

const transport = createWebSocketTransport({ url: "wss://relay.example.com/?room=room-42" });
const client = createPresenceClient({ transport });
```

`connect()` and `disconnect()` are always present on the returned transport, unlike the optional methods on the base `LiveCursorTransport` contract. See [Transports](/docs/core/transports) for that contract.

## Building the default URL

When you omit `url`, the transport builds one from `host` (default `window.location.hostname`), `port` (default `8787`), and `path` (default `/`). The protocol is `wss:` when the page loads over `https:`, and `ws:` otherwise.

The default URL needs `window`. If you omit `url` and `window` does not exist, for example on a server, `createWebSocketTransport` throws a `TypeError`. Outside the browser, pass `url`.

## Room token

Set `token` to add a room token to the connection URL. The transport URL-encodes it and appends `token=<value>`, joined with `&` when the URL already has a query string. The relay reads this token to authorize the connection to a room. See [Security](/docs/get-started/guides/security).

If the token expires, pass a function. The transport calls it before every connection attempt, including each reconnect. The function can be async. The transport waits for a returned promise:

```ts
const transport = createWebSocketTransport({
  url: "wss://relay.example.com/?room=main",
  token: async () => (await fetch("/api/room-token")).text(),
});
```

If the function throws or rejects, the transport reports a close with no code and the reason `connection attempt failed`. Then, if `reconnect` is on, it schedules the next attempt.

## Reconnect and backoff

`reconnect` defaults to `true`. After a connection drop that was not caused by your own `disconnect()` call, the transport schedules a reconnect with exponential backoff:

- The delay doubles on each attempt, starting from `baseBackoffMs` (default `500`), and caps at `maxBackoffMs` (default `8000`).
- The transport applies full jitter on top of the capped delay, so many clients reconnecting at once do not retry in lockstep.
- The backoff resets only after a connection stays open for `stableAfterMs` (default `5000`). A relay that accepts a connection and then closes it therefore sees growing delays, not a retry loop.
- A close with code `1008` (policy), `4004` (origin) or `4006` (auth) stops the reconnect, and the status becomes `disconnected`.
- `random` overrides the jitter source. It defaults to `Math.random`. A test can pass a fixed function to get a fixed delay.

## Stop reconnecting

`shouldReconnect` decides after each close whether the transport tries again. It receives the close `code` and `reason`, and returns `false` to stop. This rule also stops on `4007`, the code that the example relays send for a room name that is not valid:

```ts
const NO_RETRY_CODES = [1008, 4004, 4006, 4007];

const transport = createWebSocketTransport({
  url: "wss://relay.example.com/?room=main",
  shouldReconnect: (close) => close.code === undefined || !NO_RETRY_CODES.includes(close.code),
});
```

<Callout type="warn">
  If you pass `shouldReconnect`, it replaces the default rule. Include `1008`, `4004` and `4006` in your rule,
  or the transport retries a connection that the relay rejects.
</Callout>

When `reconnect` is `false`, the transport never calls `shouldReconnect`.

`connect()` is idempotent while a connection is already connecting or open: a second call does not open a second socket.

<Callout type="warn">
  If you call `connect()` after `disconnect()`, the transport logs a development-mode warning and does
  nothing. To reconnect, for example with a new auth token, create a new transport and a new client.
</Callout>

## Close reasons

`transport.subscribeClose(listener)` runs the listener each time a connection closes. The listener receives a `TransportClose` object with the close `code`, the `reason`, and `willReconnect`. This listener shows the close when the transport stops:

```ts
transport.subscribeClose?.((close) => {
  if (!close.willReconnect) {
    console.warn(`Relay closed the connection: ${close.code ?? "no code"} ${close.reason ?? ""}`);
  }
});
```

The transport does not replay a past close to a new listener. A close after your own `disconnect()` call does not run the listener. The client has the same method: `client.subscribeClose`.

## Buffered bytes

`transport.bufferedBytes()` returns the underlying socket's `bufferedAmount`, or `0` when no socket is open. Presence is lossy by design: `send()` drops a message silently when the socket is not open, rather than queueing it.
