A remote cursor arrives as a series of discrete positions. An interpolator decides how the cursor moves between them: snap instantly, ease at a fixed rate, or something richer, like a spring. The library ships the first two. A spring is application code, built against the public `Interpolator` interface.

## Behavior notes

- `target` sets a new destination without resetting velocity, so a spring keeps its momentum across consecutive updates instead of restarting from rest each time.
- `shift` moves the current position and the target by the same delta, with no easing. The resolver calls it for a local-only change, such as scroll, where the anchor moved but no new network packet arrived.
- `sample` must eventually report `settled: true`, or the scheduler's animation-frame loop never stops for that cursor.
- The provider reads `bindingOptions` once, at binding creation. Give the provider a `key` that changes with the selected style, so a style switch remounts the binding with the new factory. Remote cursor state lives on the server, not in the binding, so the remount does not reset any position.
