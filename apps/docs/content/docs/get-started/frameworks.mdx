`@anchor-presence/react` is built for any React framework. This page shows where to put the provider in each framework. The provider and `CursorLayer` run only in the browser. On the server, the provider renders its children with a `null` client and creates no client.

## Create a provider module

Every framework below uses this provider module. It creates the client in the `factory` of the provider, never at module scope:

```tsx
// presence-provider.tsx
"use client";

import type { ReactNode } from "react";
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, PresenceProvider } from "@anchor-presence/react";

function createClient() {
  const transport = createWebSocketTransport({ port: 8788, path: "/?room=main" });
  return createPresenceClient({ transport, user: { name: `Guest ${Math.floor(Math.random() * 100)}` } });
}

export function AppPresenceProvider({ children }: { children: ReactNode }) {
  return (
    <PresenceProvider factory={createClient}>
      {children}
      <CursorLayer />
    </PresenceProvider>
  );
}
```

The `"use client"` line has an effect only in a framework with React Server Components, such as the Next.js App Router. Other frameworks ignore it.

## Mount the provider

Render the provider in a component that stays mounted across navigation. Then the page keeps one client and one connection. Pick your framework:

<Tabs items={["Vite", "Next", "TanStack", "React Router", "Astro"]}>
<Tab value="Vite">

Render `AppPresenceProvider` around your app in the entry file. A single-page app renders nothing on the server, so it needs no other step.

</Tab>
<Tab value="Next">

Keep `"use client"` at the top of the provider module. A Server Component cannot pass a function, such as `factory`, to a Client Component, so `factory` must live in a Client Component. Render the provider in the root layout:

```tsx
// app/layout.tsx
import type { ReactNode } from "react";
import { AppPresenceProvider } from "./presence-provider";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <AppPresenceProvider>{children}</AppPresenceProvider>
      </body>
    </html>
  );
}
```

</Tab>
<Tab value="TanStack">

Render the provider in the component of the root route, around `<Outlet />`. This works for TanStack Router and TanStack Start:

```tsx
// src/routes/__root.tsx
import { createRootRoute, Outlet } from "@tanstack/react-router";
import { AppPresenceProvider } from "../presence-provider";

export const Route = createRootRoute({
  component: () => (
    <AppPresenceProvider>
      <Outlet />
    </AppPresenceProvider>
  ),
});
```

TanStack Start also renders the root route on the server. There, the root route needs a `shellComponent` that renders the document. Keep the provider in `component`, not in the shell:

```tsx
// src/routes/__root.tsx
import type { ReactNode } from "react";
import { createRootRoute, HeadContent, Outlet, Scripts } from "@tanstack/react-router";
import { AppPresenceProvider } from "../presence-provider";

export const Route = createRootRoute({
  shellComponent: ({ children }: { children: ReactNode }) => (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        {children}
        <Scripts />
      </body>
    </html>
  ),
  component: () => (
    <AppPresenceProvider>
      <Outlet />
    </AppPresenceProvider>
  ),
});
```

</Tab>
<Tab value="React Router">

Render the provider in the root route module, around `<Outlet />`:

```tsx
// app/root.tsx
import { Outlet } from "react-router";
import { AppPresenceProvider } from "./presence-provider";

export default function App() {
  return (
    <AppPresenceProvider>
      <Outlet />
    </AppPresenceProvider>
  );
}
```

For Remix, import `Outlet` from `@remix-run/react`.

</Tab>
<Tab value="Astro">

Render the provider as a React island. Use `client:only="react"` to skip the server render, or `client:load` to render on the server and hydrate:

```astro
---
// src/pages/index.astro
import { AppPresenceProvider } from "../components/presence-provider";
---

<AppPresenceProvider client:only="react">
  <button data-anchor="nav.dashboard">Dashboard</button>
</AppPresenceProvider>
```

The binding registers every `data-anchor` element in the document, so elements outside the island are anchors too. Each island has its own React tree. A hook or a `CursorLayer` in another island has no provider and returns empty data.

</Tab>
</Tabs>

## Test coverage

The test suite covers two routers directly, with React 19. The others use a tested router, or are not tested:

| Framework          | Status                                                                                                               |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| TanStack Router    | Tested with `@tanstack/react-router` 1: server render, hydration with no mismatch, and one client across navigation. |
| TanStack Start     | Built and run in a sample app, not in the test suite. It uses TanStack Router, which is tested.                      |
| React Router       | Tested with `react-router` 8, which needs React 19: server render inside a router, and one client across navigation. |
| Remix              | Not tested. Remix v2 uses React Router 6, which the tests do not cover.                                              |
| Next.js App Router | Not tested. The built packages import in plain Node, and the React entry starts with `"use client"`.                 |
| Vite and React SPA | Not tested. The package tests mount the provider with `createRoot`, as a single-page app does.                       |
| Astro              | Built and run in a sample app, not in the test suite.                                                                |

The tests do not cover React 18 with a router.
