A framework adapter connects the DOM binding to the reactivity of one UI framework. `@anchor-presence/react` is the adapter for React. Read this page to write an adapter for Solid, Vue, or another framework. The adapter copies the shape of the React adapter.

## The bridge

The core of every adapter is a bridge from `subscribe` and `getSnapshot` to a reactive value. This function writes each new snapshot of a binding into a callback, and returns the unsubscribe function:

```ts
import type { DomBinding, ResolvedCursor } from "@anchor-presence/dom";

function observeCursors(binding: DomBinding, write: (cursors: ResolvedCursor[]) => void): () => void {
  write(binding.getSnapshot());
  return binding.subscribe(() => write(binding.getSnapshot()));
}
```

In Solid, `write` is the setter of a `createSignal`. In Vue, `write` assigns to a `shallowRef`. Neither framework has `useSyncExternalStore`. This bridge does the same job.

## The three layers

Each layer depends only on the layers below it:

<Mermaid
  chart={`flowchart TD
  adapter["adapter: provider, hooks, SSR guard"] --> dom["@anchor-presence/dom: anchor registry, pointer capture, scheduler, resolver"]
  dom --> core["@anchor-presence/core: protocol types, validation, store, client"]
  adapter --> core`}
/>

An adapter holds no protocol state of its own ([invariant 5](/docs/get-started/concepts/how-it-works#the-10-invariants)). Every value that it exposes comes from a `PresenceClient` or a `DomBinding`.

## Write the adapter

<Steps>
  <Step>
    **Give the binding an owner.** A Solid `createRoot` scope or the `setup()` of a Vue component owns the
    `DomBinding`. When a `client` is available, it calls `createDomBinding(client, options)`.
  </Step>
  <Step>**Add an SSR guard.** If `window` or `document` does not exist, do not create the binding.</Step>
  <Step>
    **Expose the client and the binding.** Expose them as a Solid signal pair or a Vue `ref`. The adapter
    makes their state observable. It does not copy that state.
  </Step>
  <Step>
    **Bridge the snapshots.** Use the bridge above for the cursors. Use `client.subscribeStatus`,
    `client.subscribeRemote`, and `client.subscribeContext` the same way for status, presence, and local
    context.
  </Step>
  <Step>
    **Dispose on cleanup.** Solid `onCleanup` or Vue `onUnmounted` unsubscribes and calls `binding.dispose()`.
    A binding that outlives its scope leaks the pointer listener and the observers of the scheduler.
  </Step>
</Steps>

<Callout type="warn">
  If the adapter keeps cursors, status, or presence in a framework store, the copy can drift from the client.
  Read the client and the binding on every reactive update.
</Callout>

## What the React adapter does

`LiveCursorProvider` is the one stateful part of `@anchor-presence/react`:

- It creates the client from a `factory` prop in a mount effect, and disposes it on unmount. The factory runs again each time the `clientKey` prop changes. A client from the `client` prop belongs to the app, and the provider never disposes it.
- If you pass no `binding` prop, it creates one `DomBinding` with `createDomBinding(client, bindingOptions)` in an effect. The cleanup of that effect calls `binding.dispose()`.
- It creates a new binding when the `client` or the `bindingKey` prop changes. A `bindingOptions` change alone creates no new binding.
- Outside the browser, it creates no client from `factory` and no binding.
- It exposes `{ client, binding }` through `LiveCursorContext`.

The hooks read that context. `useRemoteCursors` subscribes to `binding.subscribe` through `useSyncExternalStore` and returns an empty array without a binding. No hook stores cursor data in React state. See the [React overview](/docs/react).

## Public APIs an adapter uses

An adapter calls only the public exports of `@anchor-presence/core` and `@anchor-presence/dom`:

| Package                 | Exports                                                                                                                                               |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@anchor-presence/core` | `createPresenceClient`, the methods of [`PresenceClient`](/docs/core/api/client#presenceclient), and the protocol types such as `RemotePresence`.     |
| `@anchor-presence/dom`  | `createDomBinding`, the `DomBinding` methods, `DomBindingOptions`, `ResolvedCursor`, `ResolutionTier`, `VisibilityPolicy`, `CURSOR_MARKER_ATTRIBUTE`. |

Set `CURSOR_MARKER_ATTRIBUTE` on the root element of each cursor that the adapter draws. See [Draw cursors without React](/docs/dom/binding#draw-cursors-without-react).

An adapter package exports again the types of the lower packages that its own public signatures use. For example, `@anchor-presence/react` exports `AnchorPoint`, `ConnectionStatus`, `PresenceClient`, and `DomBinding`. A user of the adapter then needs no direct dependency on the lower packages for types.

## Package boundaries

No third-party framework code lives inside `@anchor-presence/core` or `@anchor-presence/dom`. A `@anchor-presence/solid` or `@anchor-presence/vue` package depends on these two packages only. It has its own test that pins its exports, and it never imports the internals of another adapter. The [package table](/docs/get-started/introduction#packages) shows the dependencies of each package.
