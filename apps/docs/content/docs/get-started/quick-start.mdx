Run live cursors in two steps. First, mount the library with no backend, on an in-process transport. Then connect two browser tabs through a real relay.

## Try it with no backend

`createInMemoryPair` gives you two connected transports in one process. Use it to see the library work before you connect a relay:

```tsx
import { createInMemoryPair, createPresenceClient } from "@anchor-presence/core";
import { LiveCursorProvider, CursorLayer } from "@anchor-presence/react";

const { a: transport } = createInMemoryPair();
const client = createPresenceClient({ transport, user: { name: "Alice" } });

function DashboardButton() {
  return <button data-anchor="nav.dashboard">Dashboard</button>;
}

function App() {
  return (
    <LiveCursorProvider client={client}>
      <DashboardButton />
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

`createInMemoryPair` returns two transports, `a` and `b`. The client sends on `a`, and its messages go to the listeners of `b`. Nothing listens on `b`, so no remote cursor appears. The sample only shows that the anchors, the provider, and `CursorLayer` compile and mount.

## Connect two real clients

Real live cursors need two clients, one per browser tab, on a shared transport. Pass the provider a `factory`. The provider runs the factory once per mount, in a mount effect. In development, React Strict Mode runs each effect twice. The provider disposes the first client before it creates the second, so only one client stays connected:

```tsx
import { createPresenceClient } from "@anchor-presence/core";
import { createWebSocketTransport } from "@anchor-presence/dom";
import { CursorLayer, LiveCursorProvider } from "@anchor-presence/react";

function App() {
  return (
    <LiveCursorProvider
      factory={() => {
        const transport = createWebSocketTransport({ path: "/?room=main" });
        return createPresenceClient({ transport, user: { name: "Alice" } });
      }}
    >
      <button data-anchor="nav.dashboard">Dashboard</button>
      <CursorLayer />
    </LiveCursorProvider>
  );
}
```

The client connects the transport by default. Before the mount effect runs, the provider renders its children with a `null` client, and every hook returns its server-safe value. See [SSR and Strict Mode](/docs/react/ssr-and-strict-mode) for the full rule.

Copy a relay from [Backends](/docs/examples/backends) to pair with it. [Bun](/docs/examples/backends/bun-native) is the smallest runnable relay.

`room` is a relay-side grouping key, not part of the protocol. Any bidirectional byte channel that implements the transport interface works in place of `createWebSocketTransport`. See [Transports](/docs/core/transports).

## Without React

`@anchor-presence/core` and `@anchor-presence/dom` work with no React in the tree. Subscribe to the resolved cursors of the binding, and render them yourself with plain DOM updates or another framework. See [Binding](/docs/dom/binding) for the subscribe method. To connect the binding to the reactivity of a framework, see [Build a framework adapter](/docs/core/build-a-framework-adapter).
