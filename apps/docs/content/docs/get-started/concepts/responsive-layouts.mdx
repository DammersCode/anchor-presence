Two clients rarely show the same layout at the same time. This page shows how the anchor and its `u`/`v` position keep a cursor on the same element when the layouts differ. You need no code for this. You only keep the anchor IDs the same in every layout.

## Worked example

On the sender, the button `orders.row:17.actions` is 160 pixels wide. The pointer is at `u = 0.75`, so 75% across the button.

On the receiver, the layout is narrower. The same button is 96 pixels wide. The receiver computes:

```text
x = rect.left + rect.width * u
  = rect.left + 96 * 0.75
  = rect.left + 72
```

The cursor lands 72 pixels from the left edge of the button. That is also 75% across the button. The cursor keeps the same spot on the button, not the same pixel offset. The same math applies to `v` and the height of the button.

## How wrapping and breakpoints resolve

A layout can wrap or reflow at a breakpoint. If the element keeps its anchor ID, the cursor follows it:

- The element moves to another pixel position. The receiver measures it again on the next frame.
- The element changes size. The `u`/`v` fraction still applies.
- The element moves from a one-column to a three-column layout. The anchor ID stays the same, so the fallback chain still finds it.

## How sidebar state resolves

A collapsed sidebar and an open sidebar are two layouts of one page. Give each item the same anchor ID in both states, for example `nav.dashboard`. Then a cursor over that item lands on it in either state.

A collapsed sidebar can remove an item from the DOM. The fallback chain then moves to the next anchor, for example the sidebar container.

## How element-size differences resolve

Font settings, zoom, container queries, and the window size can give one anchor a different size on each client. The `u`/`v` position is a fraction of the size of the anchor, so the cursor does not drift.

## When no anchor matches

If no anchor of the chain exists on the receiver, the cursor uses the viewport position. One example is a receiver on another page. If the viewport position is also missing, the cursor is hidden. See [Fallback chain](/docs/get-started/concepts/fallback-chain).
