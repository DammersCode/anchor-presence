title: Overview
description: What @anchor-presence/core does, and why it has no DOM and no framework.
---

`@anchor-presence/core` is the protocol layer. It validates and stores remote presence, orchestrates outbound publishing, and defines the interfaces every transport and codec implements.

`@anchor-presence/core` has zero runtime dependencies and no DOM globals. It runs in Node.js, Bun, workers, and browsers. See [How it works](/docs/get-started/concepts/how-it-works) for how it fits under `@anchor-presence/dom` and `@anchor-presence/react`.

## Framework- and DOM-free

`@anchor-presence/core` never imports `document`, `window`, React, or any transport or codec library. This split has two effects:

- A test or a server process can create a `PresenceClient` and exercise the protocol with no browser and no framework.
- A framework adapter, such as `@anchor-presence/react`, holds no protocol state of its own. It only subscribes to the client `@anchor-presence/core` already runs.

## What core owns

- The wire protocol types (`CursorPresence`, `AnchorPoint`, `RemotePresence`, and related types).
- `validatePresence`, the boundary that turns an untrusted decoded value into a `CursorPresence` or `null`.
- `RemotePresenceStore`, which holds every accepted remote presence with stale-entry expiry.
- `createPresenceClient`, which orchestrates publishing, heartbeats, and the transport and codec interfaces.
- The `LiveCursorTransport` and `CursorCodec` interfaces, plus `createInMemoryPair`, `jsonCodec`, and `binaryCodec`.
- The `Interpolator` interface, plus `linearInterpolator` and `noneInterpolator`.
