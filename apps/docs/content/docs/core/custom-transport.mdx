A custom transport connects the client to a byte channel that the packages do not ship, for example the SDK of a managed real-time service. A transport only moves bytes. It never checks or reads them.

If your app uses Socket.IO or SignalR, use the [Socket.IO](/docs/examples/backends/socketio) or [SignalR](/docs/examples/backends/signalr) example. You do not need to write a transport.

## BroadcastChannel sketch

`BroadcastChannel` sends messages between browsing contexts (tabs, iframes, workers) on the same origin. It never crosses a network. This sketch shows the parts of a transport on a small version of [`createBroadcastChannelTransport`](/docs/dom/broadcast-channel-transport), which `@anchor-presence/dom` ships:

```ts
import type { ConnectionStatus, LiveCursorTransport } from "@anchor-presence/core";

function createBroadcastChannelTransport(channelName: string): LiveCursorTransport {
  const channel = new BroadcastChannel(channelName);
  const statusListeners = new Set<(status: ConnectionStatus) => void>();

  return {
    connect() {
      // a BroadcastChannel has no handshake and is open from construction
      for (const listener of statusListeners) listener("connected");
    },
    disconnect() {
      channel.close();
    },
    send(data) {
      channel.postMessage(data);
    },
    subscribe(listener) {
      const onMessage = (event: MessageEvent<Uint8Array>) => listener(event.data);
      channel.addEventListener("message", onMessage);
      return () => channel.removeEventListener("message", onMessage);
    },
    subscribeStatus(listener) {
      listener("connected");
      statusListeners.add(listener);
      return () => statusListeners.delete(listener);
    },
    getStatus() {
      return "connected";
    },
  };
}
```

`BroadcastChannel` delivers structured-cloned values. As a result, it carries a `Uint8Array` with no base64 step.

## Wrap a managed service

A managed service is a hosted pub/sub or a serverless WebSocket gateway. Its SDK has a `send` method and a message event. Wrap the SDK in a transport object:

<Steps>
  <Step>Forward each `send` call to the SDK.</Step>
  <Step>Forward each message event of the SDK to the `subscribe` listeners.</Step>
  <Step>
    Map the connection events of the SDK to `ConnectionStatus`, and replay the current status to each new
    `subscribeStatus` listener.
  </Step>
  <Step>
    If the SDK reports close codes, implement `subscribeClose`. See [Close reasons](#close-reasons).
  </Step>
</Steps>

<Callout type="warn">
  If the SDK delivers text or JSON instead of bytes, convert at the transport boundary. Each `subscribe`
  listener must receive a `Uint8Array`. Otherwise the codec cannot decode the messages.
</Callout>

## Close reasons

A transport reports why a connection closed through the optional `subscribeClose` method. Keep a set of listeners, and call each one from the close handler of your socket:

```ts
import type { TransportClose } from "@anchor-presence/core";

const closeListeners = new Set<(close: TransportClose) => void>();

function subscribeClose(listener: (close: TransportClose) => void) {
  closeListeners.add(listener);
  return () => {
    closeListeners.delete(listener);
  };
}

function onSocketClose(event: CloseEvent, willReconnect: boolean) {
  const close: TransportClose = { code: event.code, reason: event.reason, willReconnect };
  for (const listener of closeListeners) listener(close);
}
```

Return `subscribeClose` on the transport object. Set `willReconnect` to `true` when the transport schedules another attempt, and to `false` otherwise. `client.subscribeClose` then receives each close. See [Close reasons](/docs/core/transports#close-reasons).

## Test a custom transport

Do a test of your transport with these cases:

- A connect.
- A send while the transport is connected.
- A send while the transport is disconnected. The browser transports drop this send.
- A status change with no active subscriber.
- A `subscribeStatus` call after the connection opened. The listener must receive `connected` at once.

`createInMemoryPair` is not a reference for the disconnected case: it delivers a send while its side is disconnected. See [In-memory transport](/docs/core/in-memory-transport#limits).
