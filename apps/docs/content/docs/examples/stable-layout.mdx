A layout can change with the viewport and still keep cursors calm. In this demo, a release checklist keeps one card width and three tiles per line in both panes. The wide pane adds a side panel beside the card. The narrow pane leaves it out. A cursor that moves from one tile to the next never crosses a long distance.

## Behavior notes

Try it: Move your pointer along the tiles in the wide pane.

- The cursor of Mira walks along the tiles. Each step has the same length in both panes.
- A point on a tile lands on the same tile at the same offset in both panes.
- The card has one width and the tiles have one size. The column count fits the narrowest pane, so the tiles never reflow.
- Extra room holds extra content beside the card. The wide pane adds the side panel and moves nothing else.
- Each group has an anchor: `release.steps`, `release.actions`, and `release`. A point in a gap resolves to its group.
- A page anchor, `release.page`, covers the whole pane. The side panel exists only in the wide pane. In the narrow pane, a cursor on the panel falls back to the page.
- The [layout design guide](/docs/get-started/guides/layout-design) explains each rule. The [audit skill](/docs/skills/layout-audit) scores this pair low.
