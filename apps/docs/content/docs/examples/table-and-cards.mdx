A list often shows as a table on a wide screen and as a stack of cards on a narrow screen. The fields of one record move to different places. In this demo, the wide pane shows invoices as table rows. The narrow pane shows each invoice as a card. A cursor on the status cell of a row lands on the status pill of the same card.

<Callout type="warn">
  As the pane shrinks, the elements in this layout move or change size. That is on purpose in this example. It
  shows the worst case, so the cursor movement is easy to see. In an app, a short pointer move on one screen
  becomes a long jump on the other. Keep element sizes fixed and let the page scroll. See the [Kanban
  example](/docs/examples/kanban).
</Callout>

## What's in the demo

- Each field has the same anchor ID in the table and in the card, for example `invoices.row:INV-2043.status`.
- Each row and each card has the anchor `invoices.row:<id>`. A cursor between two fields resolves to the record.
- The action buttons have their own anchors. A cursor on "Remind" in the table lands on "Remind" in the card.
- Move your pointer down the amount column in the wide pane. In the narrow pane, the cursor moves to the second line of each card.
