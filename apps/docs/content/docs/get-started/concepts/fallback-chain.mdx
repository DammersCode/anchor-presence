The fallback chain lets a receiver place a cursor when the exact element is missing on its screen. One example is a table row that exists on the sender but not in a shorter table on the receiver. The cursor then moves to the nearest parent anchor that the receiver has, and not to a random place.

## Example

Anchor each level of a table: the button, its row, and the table:

```tsx
<table data-anchor="orders">
  <tbody>
    <tr data-anchor="orders.row:17">
      <td>
        <button data-anchor="orders.row:17.actions">Edit</button>
      </td>
    </tr>
  </tbody>
</table>
```

A pointer on the button sends the chain `orders.row:17.actions`, `orders.row:17`, `orders`. If the receiver shows no row 17, its cursor lands on `orders`.

## How the chain works

The fallback chain is the anchor, then its parent anchors, then the viewport position when the message carries one. A cursor position stores the anchors in an ordered list, the most specific first.

1. The sender starts at the element under the pointer.
2. It adds each registered anchor between that element and the document root, the nearest anchor first.
3. It stops at `maxAnchors` entries. The default is 4, and the protocol allows at most 8. See [Binding](/docs/dom/binding).

The receiver walks the chain in order. It uses the first anchor that is connected to its DOM and has a size larger than zero.

## Viewport fallback

A cursor position can also carry a `viewport` field. It is a `u`/`v` position across the full viewport: `pointerX / innerWidth` and `pointerY / innerHeight`. If no anchor in the chain resolves, the receiver uses this position. The cursor then stays visible, but it can land on another element.

## Resolution tiers

A **tier** names the fallback step that placed the cursor. Each resolved cursor carries one:

| Tier       | Meaning                                        |
| ---------- | ---------------------------------------------- |
| `anchor`   | An anchor in the chain resolved.               |
| `viewport` | No anchor resolved. The viewport position won. |
| `hidden`   | The cursor has no position to show.            |

After this step, a **visibility policy** decides whether the cursor shows. The default policy hides only the `hidden` tier. A custom policy can hide other cursors for app reasons. See [UI context](/docs/get-started/concepts/ui-context). [Resolution](/docs/dom/resolution) gives the pixel formula of each tier.
